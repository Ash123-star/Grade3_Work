# Flutter 前端精致化开发阶段规划

## 1. 文档目的

2026-10-13 进展：以原阶段 3 文档和八屏设计板完成本地主要布局重建；分析、67 项 Flutter 测试、三种尺寸/字号与实际八屏截图对照已通过。辅助八屏已取得 Flutter 截图，原第6节验收成果/变更旧值/版本文档/个人时间线及恢复路径已补齐；真实接口/设备验收仍待完成。本次不执行 APK 构建，远程 Issue/提交/PR 因混合工作区和 gh 缺失未执行。详见 mobile/docs/stage-3-verification.md 与 OpenSpec flutter-stage3-layout-rebuild，不将主题迁移或 Mock 当作产品完成。

本规划用于指导 `mobile/` Flutter 前端的后续开发。目标是先完成清晰、统一、可演示的前端产品，再等待后端接口接入，不因后端尚未稳定而反复修改页面结构。

本规划遵循：

```text
产品需求确认 → 路由与流程 → UI 视觉规范 → 页面布局 → 交互状态 → Mock 演示 → 统一验收 → 后端接入
```

每个阶段集中完成一个主题。阶段未达到完成条件前，不提前进入下一阶段，也不在实现过程中反复运行完整编译和测试。

## 2. 当前边界

### 本阶段负责

- Flutter 页面路由、页面布局和交互体验；
- Material 3 主题、颜色、字号、间距、卡片和按钮规范；
- Mock 数据驱动的 loading、empty、error、forbidden、saving、success、conflict 状态；
- 五个主导航入口及页面间跳转；
- 小屏、大屏和字体放大后的布局适配；
- 页面截图和手工验收记录。

### 当前不负责

- 修改 Spring Boot 后端接口、数据库和权限规则；
- 猜测或新增未确认的后端接口；
- 在 Flutter 客户端保存 AI 密钥；
- 把 Mock 成功当作真实业务完成；
- 为了视觉效果引入新的 UI 框架或复杂动画库。

## 4. 阶段 0：需求与范围收口

### 目标

把产品方案转成 Flutter 可以直接执行的页面边界，避免模型自行增加功能或把规划当成完成。

### 必须确认

- 导航顺序固定为：导图、视图、日志、AI 地图、我的；
- 默认进入导图；
- 公司内容、个人内容、任务、日志、审批和 AI 建议的权限边界；
- 员工、团队长、部门老总、创始人、管理员的可见范围；
- 派发页不显示“完成情况”字段；
- 下属日志固定从日志页进入；
- AI 输出只能是带来源的建议草稿；
- 后端接口未覆盖的页面只做 Mock 演示，不伪造真实接入。

### 产物

- 页面清单；
- 角色 × 页面权限矩阵；
- 明确非目标；
- 需求假设和待后端确认项。

### 完成条件

任何页面都能回答“谁使用、解决什么问题、允许什么操作、失败时怎么办”。

## 5. 阶段 1：路由与用户流程

### 一级路由

```text
/auth/login
/auth/register
/auth/pending

/dashboard                 导图首页
/view                      日/周/月视图
/logs                      我的日志
/logs/subordinates         下属日志
/ai                        AI 地图
/me                        我的
```

### 二级路由

```text
/dashboard/company
/dashboard/personal
/tasks/create
/tasks/:id
/tasks/:id/feedback
/tasks/:id/accept

/view/day
/view/week
/view/month

/logs/:id
/logs/:id/edit
/logs/:id/history
/logs/:id/revise

/ai/analysis
/ai/risk
/ai/actions
/ai/:id

/me/profile
/me/notifications
/me/statistics
/me/settings
/me/help
```

### 核心流程

```text
登录 → 导图
导图 → 公司重点/任务详情/个人重点/日志编辑
视图 → 日、周、月 → 点击任务或日志 → 详情
日志 → 编辑草稿 → 提交 → 查看历史或修订
管理者 → 日志 → 下属日志 → 选择成员和日期 → 查看与评语
AI 地图 → 分析 → 来源详情 → 编辑建议 → 人工确认 → 创建任务
我的 → 消息/统计/设置/帮助
```

### 路由规则

- 登录失效统一进入 `/auth/login`；
- 待确认员工进入 `/auth/pending`，不得看到公司业务数据；
- 返回操作保留上一级筛选条件和滚动位置；
- 创建、编辑、详情使用独立路由，不用弹窗承载完整业务页面；
- 删除、撤回、驳回等危险操作必须二次确认；
- 任何页面都必须有明确的返回路径。

### 阶段验收

- 五个底部导航入口可以互相切换；
- 默认打开导图；
- 登录、待确认、失效和无权限路径可演示；
- 从列表进入详情、从详情返回列表的状态保持正确。

## 6. 阶段 2：UI 主题与视觉规范

2026-10-12 用户已确定 **阳光纸张 + 动漫橙 + Q 版人物 + 圆润温和组件**。旧蓝绿、薄荷绿主主题与小圆角方案退出实施基线。

当前视觉基线见 [团团记账气质 UI 设计基线](../mobile/docs/tuantuan-ui-design-system.md)；阶段2阳光纸张/动漫橙方案已退出并清理，不再作为实现依据。

### 当前主题基线

- 主色 `#FF8A24`，主按钮前景 `#44210D`，纸张底 `#FFF8EE`，暖白卡 `#FFFDF8`；
- 薄荷、天空蓝、淡紫、蜂蜜黄按分区和状态使用；
- 普通卡片 20dp、人物卡 24dp、按钮 18dp、字段 16dp、选项胶囊；
- 原创约 2.5 头身工作伙伴用于欢迎、书写、AI 来源解释和真实操作反馈；
- 以 Material 3、ThemeExtension 和公共组件集中定义，不增加 UI 框架；
- 保留四象限、五栏与权限规则，人物和圆角不能遮挡实际工作；
- 48dp 触控、字体放大、TalkBack、减少动态效果和错误恢复纳入验收。

### 阶段状态和下一批

新规范和参考研究已写入；HTML 原型、Flutter 主题、组件、最终人物素材及运行验收未完成。下一批先做令牌、组件状态展示和新版原型，再迁移导图/日志代表页。主色方向不再作为待选择任务。

## 7. 阶段 3：页面布局设计

2026-10-12 详细设计已写入 [页面布局与交互设计](../mobile/docs/stage-3-page-layout-and-interaction-design.md)，包含需求矩阵、参考证据范围、各页面首屏/操作/异常契约。已提供 [五主页设计板](../mobile/docs/stage-3-main-pages.png)、[业务详情设计板](../mobile/docs/stage-3-detail-pages.png) 和 [离线交互原型](../mobile/prototypes/stage-3-pages/index.html)。用户已授权按设计实施 Flutter；当前代码和验收状态见 [验证记录](../mobile/docs/stage-3-verification.md)，不以画稿当作实际运行结果。

### 导图首页

首屏采用两行两列四象限：

1. 公司重要展示项：只读，可进入完整列表；
2. 公司派发任务：展示待处理任务，不显示完成情况字段；
3. 个人重要展示项：新增、编辑、排序、归档；
4. 个人日志：显示最近记录和写日志入口。

小屏每块只显示 2～3 条，使用“查看全部”进入列表。拥有派发权限时显示右下角圆形新增任务按钮，不遮挡底部导航。

### 视图页

- 顶部：日期切换和日/周/月分段控制；
- 中部：任务和日志时间线；
- 日视图：24 小时纵向时间轴；
- 周视图：七日横向时间轴，支持滚动；
- 月视图：七列日期格，事件以紧凑标签显示；
- 点击事件进入任务或日志详情。

### 日志页

- 顶部：我的日志；管理者显示下属日志入口；
- 中部：按业务日期的日志列表；
- 底部：写日志按钮；
- 编辑页：今日工作、关联任务、阻碍、明日计划、工时；
- 已提交日志显示版本、修订和评语入口。

### AI 地图页

- 顶部：个人发展/公司走向切换；
- 第一屏：优先三件事与关系图入口在阶段 3 比较后确定；
- 中部：发展分析、堵点风险、行动规划三个分区；
- 详情页：建议内容、来源、生成时间、编辑按钮；
- 底部：加入行动清单或人工确认创建任务。

### 我的页面

- 个人头像、姓名、部门和介绍；
- 工作统计、消息中心、设置和帮助；
- 管理员额外显示组织管理和审计入口；
- 查看他人面板时显式显示“正在查看某某”，并提供返回本人面板按钮。

### 通用详情页和表单

- 详情页按“摘要 → 关键信息 → 时间线 → 可执行操作”排列；
- 表单按“必填基础信息 → 业务内容 → 附件/补充 → 提交”排列；
- 任何长表单使用单列布局，避免移动端横向表格；
- 危险操作放在页面底部并使用警示色。

## 8. 阶段 4：交互状态与公共组件

### 页面状态

```text
initial / loading / success / empty / error / forbidden
unauthorized / saving / saved / conflict / offline
```

### 公共组件

- `AppScaffold`：统一导航和页面背景；
- `PageHeader`：标题、返回和辅助操作；
- `SectionHeader`：区块标题和查看全部；
- `RecordCard`：任务、日志、重点内容卡片；
- `StatusBadge`：待处理、已提交、已归档等状态；
- `LoadingSkeleton`：列表和详情骨架屏；
- `EmptyState`：无数据和下一步操作；
- `ErrorPanel`：错误信息和重试；
- `PermissionState`：无权限和联系管理员；
- `AppFormField`：统一字段、校验和错误提示；
- `Timeline`：任务和审核事件；
- `PersonPicker`：按权限范围选择人员。

### 阶段验收

每个核心页面至少演示：正常、加载、空数据、网络失败、无权限和提交中状态；核心表单至少包含必填校验、无效输入、重复提交和版本冲突提示。

## 9. 阶段 5：Mock 业务演示

Mock 仅负责演示页面和交互，不伪造后端已完成：

- 导图四象限数据；
- 日/周/月任务和日志数据；
- 日志草稿自动保存；
- 任务接收、反馈和验收状态变化；
- 审核申请、通过和驳回；
- AI 建议、来源和行动清单；
- 通知未读和已读；
- 五种角色的权限表现。

每条 Mock 操作都要对应一个明确状态转换，并可通过 Repository 替换为后端数据源。

## 10. 阶段 6：精修与可用性

### 精修顺序

1. 先修布局溢出、返回路径和主要操作；
2. 再修字号、间距、颜色和卡片层级；
3. 再补充加载、空状态和错误状态的视觉一致性；
4. 最后增加必要的微动效，例如页面切换、提交反馈和列表展开。

### 不引入的效果

- 不使用持续闪烁、自动播放和大面积粒子动画；
- 不使用会影响阅读的复杂背景；
- 不用动效掩盖加载慢或流程不清晰；
- 不在尚未完成的功能上设计“假完成”动画。

## 12. 给模型的页面开发提示模板

后续开发某一页面时，使用以下模板，不需要使用复杂的前端术语：

```text

用户角色：[员工/团队长/部门老总/管理员]
页面目标：[用户在页面上完成什么任务]
进入方式：[从哪个页面或按钮进入]
主要内容：[按优先级列出信息]
主要操作：[最多列出 1 个主操作和 2～3 个次操作]
返回行为：[返回后保留什么状态]
视觉风格：阳光纸张，动漫橙主色、深可可文字、20～24dp 卡片、18dp 按钮、彩色分区和原创 Q 版伙伴；以阶段 2 新规范为准。
必须包含状态：loading、empty、error、forbidden、saving、success、conflict。
必须遵守：不新增后端接口，不使用真实 API Key，不出现完成情况字段，不改变导航顺序。
验收条件：[列出可操作的正向和异常流程]

先阅读相关现有组件和路由，先给出页面设计和文件计划，确认后再写代码。
```

## 13. 执行规则

- 一次只实现一个阶段，阶段内可以批量处理互相依赖的小任务；
- 每阶段开始前先说明目标、允许修改文件、排除范围和验收条件；
- 设计阶段不提前修改业务代码；
- 后端未提供接口时保留 Mock 和明确占位状态；
- 统一验收前不反复运行完整分析、测试和构建；
- 最终报告必须区分已实现、已验证、未验证、未实现、假设和风险。
