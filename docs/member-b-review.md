# 成员 B 第三批：审核规则与协作边界

Issue #5；OpenSpec member-b-backend-readiness 4.1–4.6。MVP 分工优先，保留主规格分层复核与版本冲突行为。

## 本批 B 可独立实施部分

ReviewController 从应用服务文件分离，Controller 不执行 SQL；分页查询调用 ReviewRepository，输入/self-review/终态/驳回原因规则由 ReviewPolicy 验证。审核应用仍持有事务：锁定申请行，校验当前步骤和当前职责，处理一步，最后一步才应用业务候选；生效、审计和 outbox 同事务。
reason 类型现明确要求文本，布尔 approve 必填，非法/未知字段拒绝；自审403、空白驳回400、无资格403、终态/目标版本变化409。失败后不写本次步骤、业务、审计或事件。
审核列表仅本人申请或分配给本人，详情只对本公司申请人/分配审核人开放。重新路由仅申请人在没有已处理步骤时执行。
现有 route 保持团队→部门→公司，公司独立人缺失时保持待审而不跳过最终层级；任务策略本身独立审核后才变化。组织最终应用再次校验当前公司关系、有效账号和最后管理员。

## 尚未完成的分层与跨模块替换

ReviewApplicationService 仍有历史 SQL 和对任务/日志/仪表盘的直接应用代码；因此 4.1 的完整分层、4.5 的跨模块替换不能宣称完成。
仓库 TaskApi/LogApi 没有审核最终应用方法。B 已提供 ReviewedRevisionApplication 作为待协作边界：模块声明 kind，并在调用方事务内按申请人/审核人身份、目标、expectedVersion 和候选应用一次。该接口尚未接入，不是已实现功能。
需要 C 为 TASK/LOG 提供事务应用实现，与 E 确认 ActorContext/统一错误和接口注册；仪表盘由 E 提供应用边界；D/E 核对 outbox 一次投递和重试。B 不复制、接管或弱化这些业务规则。接口实施完成后再移除审核模块中的相关历史直接 SQL。

## 验证与限制

ReviewPolicyTest：自审、终态、布尔决定、原因类型/空白及未知字段。
ReviewIntegrationTest：权限/列表范围、逐级旧值保持、缺失独立人和重新路由、版本冲突回滚、重复并发决定一次写入、审核期间组织关系变化再次验证。使用独立真实公司数据，HTTP 与数据库都检查。
新增测试不改 E 的 BackendIntegrationTest。全套任务转交失败仍交 E；接口与客户端核对、跨模块新应用实现、规定规模性能及最终联调未完成，不报告三批已全部交付。
