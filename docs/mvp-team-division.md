# 一周 MVP 分工清单

## 统一协作规则

- A 只负责 Flutter 架构、页面和本地展示状态，不编写接口调用、DTO 映射或后端联调代码。
- B、C、D 只负责 Spring Boot 后端业务实现、数据库访问和后端测试，不修改 Flutter 页面。
- E 负责公共接口契约、Flutter 与后端的接口接入、联调、回归测试和发布检查，不代替 B/C/D 实现业务规则。
- 接口以 `server` 运行时 SpringDoc、`docs/openapi.json` 和 `docs/backend-interface.md` 为统一规定；接口变更必须三处同步。
- 每个人在自己的分支开发，提交必须关联 Issue；跨边界需求先在 Issue 中确认，不直接改他人负责目录。

## A：Flutter 架构与页面

**负责目录**：`mobile/`

**工作清单**：

- 建立 Flutter 分层：`core`、`routing`、`theme`、`features`、通用组件和页面状态模型。
- 完成导航顺序：导图、视图、日志、AI 地图、我的；默认进入导图。
- 完成登录、导图/视图、日志、AI 地图、我的页面的 MVP 静态布局和交互状态。
- 实现 loading、空状态、错误状态、表单校验和权限不可用状态的页面表现。
- 使用本地假数据或固定状态模型验证页面，不接入真实 HTTP 接口。
- 提供页面路由表、组件使用说明和截图验收记录。

**明确不负责**：Dio/API Client、OpenAPI 生成代码、认证 token、接口重试、后端字段适配、接口联调。

**交付验收**：`flutter analyze`、`flutter test`（适用测试）通过；五个导航入口可运行，主要页面无溢出和阻塞交互。

## B：认证、组织与审核后端

**负责模块**：`server/src/main/java/cn/workpanel/module/auth`、`organization`、`review`，以及对应 Flyway/单元和集成测试。

**工作清单**：

- 注册、登录、改密、登出、会话失效和待确认账号限制。
- 公司、部门、团队、人员、汇报关系和组织数据范围。
- 分层审核、版本校验、禁止申请人自审、驳回原因校验。
- 角色权限：管理员、创始人、部门负责人、团队长、员工。
- 维护认证、组织和审核接口的 JavaDoc、OpenAPI schema 和错误码。

**明确不负责**：任务流转、日报业务、AI 调用、Flutter 页面和最终接口接入。

**交付验收**：覆盖登录/注册、待确认越权、审核通过/驳回、自审拒绝、版本冲突和组织范围隔离。

## C：任务与日报后端

**负责模块**：`server/src/main/java/cn/workpanel/module/task`、`log`，以及对应 Flyway/单元和集成测试。

**工作清单**：

- 任务派发、幂等键、负责人和协作人、附件引用、事件时间线。
- 任务接收、反馈、验收、转派、改期、撤回、归档和版本并发控制。
- 任务列表不得返回完成情况或替代状态字段。
- 日报草稿、提交、每日唯一主日报、历史版本、修订、已读和评语。
- 下属日志入口、草稿不可见、组织范围过滤和日志任务关联。

**明确不负责**：组织审核链实现、通知投递、AI provider、Flutter 接口调用。

**交付验收**：覆盖任务正常生命周期、幂等重放、转派/改期、非法状态、越权读取、日报草稿隐私和版本冲突。

## D：仪表盘、通知、分析、附件与 AI 后端

**负责模块**：`server/src/main/java/cn/workpanel/module/dashboard`、`message`、`analytics`、`attachment`、`ai`。

**工作清单**：

- 公司重点、个人重点、个人资料和私人备注。
- 通知未读数、全部已读、类型筛选、事务 outbox、提醒和 SSE。
- 统计、时间线和 CSV 导出，确保与详情使用相同数据范围。
- 附件上传、授权下载、大小限制和每次下载重新鉴权。
- 服务端 DeepSeek 调用、AI Job、来源校验、流式输出、重试、取消、预算和 AI 地图。
- AI 失败不得影响普通任务和日报链路。

**明确不负责**：Flutter 页面、认证/组织核心规则、任务和日报状态机、最终前后端接入。

**交付验收**：覆盖私人数据隔离、通知 outbox/SSE、导出范围、附件越权、AI 来源过滤、失败降级和 API Key 不出客户端。

## E：接口契约、接入与集成测试

**负责目录/文件**：`docs/openapi.json`、`docs/backend-interface.md`、Flutter API client 层（由 A 交付页面后的独立接入目录）、集成测试与验证记录。

**工作清单**：

- 依据 B/C/D 的实现维护统一 OpenAPI、请求/响应 DTO、错误模型、分页、版本和幂等规则。
- 将接口接入 Flutter；负责 token、请求头、序列化、错误提示、超时、重试和 SSE 客户端。
- 不修改 A 的页面结构；通过页面公开的状态接口注入真实数据。
- 编写跨模块联调场景：登录 → 组织范围 → 任务/日报 → 通知/统计 → AI 草稿确认。
- 执行后端集成测试、Flutter 联调测试、OpenSpec 校验和最终回归。
- 发现接口不一致时创建 Issue，协调对应后端负责人修复；不得在客户端静默兼容错误字段。

**明确不负责**：业务规则、数据库表设计、Controller 核心逻辑、Flutter 页面视觉和布局。

**交付验收**：接口文档与运行时 OpenAPI 一致；核心链路可从 Flutter 调用后端；记录正向、异常、权限和兼容性结果。

## 依赖顺序

1. B/C/D 先完成接口和业务实现，提交请求/响应示例及验证结果。
2. E 根据接口契约接入 Flutter，并反馈字段或权限问题。
3. A 可并行完成页面，页面只依赖本地状态模型；E 在页面稳定后注入真实数据。
4. E 负责最终联调，B/C/D 修复各自模块问题，A 只处理页面和状态展示问题。

## 一周交付门槛

- A：五个导航页面可运行，页面状态完整。
- B/C/D：核心后端链路和异常/权限测试通过。
- E：接口契约、真实接入、跨模块回归和验证记录完成。
- 全组：不得以“页面完成”“接口存在”“编译通过”单独宣称 MVP 完成；必须有可运行链路和验收证据。
