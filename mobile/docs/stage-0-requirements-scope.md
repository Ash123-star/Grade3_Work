## 2. 产品目标

Flutter Android 客户端面向企业内部员工和管理者，核心目标是让用户在一个移动工作台中完成：

1. 快速查看公司重点、个人重点、任务和日志；
2. 在日、周、月视图中定位任务与工作记录；
3. 填写、提交和修订工作日志；
4. 接收、反馈和跟进任务；
5. 通过 AI 地图理解目标、阻碍、来源和下一步行动；
6. 在权限范围内查看组织成员、通知、统计和审核信息。

产品体验的优先级为：

```text
看得懂 → 找得到 → 做得完 → 出错可恢复 → 视觉统一
```

## 4. 用户角色边界

| 角色 | 主要目标 | 允许的前端行为 | 明确限制 |
|---|---|---|---|
| 员工 | 完成自己的任务和日志 | 查看授权内容、接收任务、提交成果、填写日志、查看 AI 建议 | 不能查看无权限成员，不能审核自己 |
| 团队长 | 管理团队工作 | 派发任务、查看团队日志、评语、任务验收、查看团队 AI 分析 | 只能操作服务端授权范围 |
| 部门老总 | 查看部门工作 | 查看下属范围、派发任务、复核、统计分析 | 不能超出部门数据范围 |
| 创始人 | 查看公司整体工作 | 查看公司重点、任务、人员面板和经营分析 | 关键修改仍需审核链 |
| 管理员 | 配置组织和权限 | 管理组织、角色、审核策略、审计和账号 | 关键业务修改不能绕过审核规则 |

前端只负责表达可用状态和提供交互限制；最终权限、数据范围、下载、导出和 AI 检索必须由服务端校验。

## 5. 五个主导航职责

### 导图

用户进入应用后的工作总览。首屏固定展示四个区域：

- 公司重要展示项；
- 公司派发任务；
- 个人重要展示项；
- 个人日志。

导图的任务是“快速判断下一步做什么”，不是承载全部列表和复杂编辑。

### 视图

按日、周、月查看同一时间范围内的任务和日志。视图的任务是“定位时间和安排”，点击事件进入详情，不在时间轴中直接编辑复杂内容。

### 日志

分为我的日志和管理者可见的下属日志。日志的任务是“记录工作、提交结果、查看历史”，日期筛选属于日志业务日期，不与视图日期状态混用。

### AI 地图

展示带来源的工作分析、风险和行动建议。AI 地图的任务是“帮助用户理解方向并确认下一步”，不能直接自动创建正式任务或绕过权限。

### 我的

提供个人主页、消息、统计、设置、帮助和管理员入口。我的页面的任务是“管理个人信息和辅助工作入口”，不承载主业务列表。

## 7. 核心业务流程边界

### 认证流程

```text
登录页
  ├─ 登录成功 → 导图首页
  ├─ 待确认员工 → 待确认页
  ├─ 首次改密 → 修改密码页 → 导图首页
  ├─ 账号停用 → 停用页
  └─ 凭据错误/网络失败 → 当前页错误提示与重试
```

### 任务流程

```text
派发
  → 待接收
  → 负责人接收
  → 提交成果
  → 派发者验收
  → 已验收
  → 归档
```

异常分支包括：无派发权限、负责人无效、版本冲突、重复提交、撤回、退回补充和网络失败。

派发页面不出现“完成情况”字段；任务状态通过详情时间线和允许的操作表达。

### 日志流程

```text
编辑日志 → 本地保存草稿 → 提交 → 上级查看 → 评语
                                      └→ 修订申请 → 审核 → 更新正式版本
```

异常分支包括：必填内容缺失、日期无效、工时超范围、无权查看、版本冲突和提交失败。

### AI 流程

```text
选择分析范围 → 服务端生成建议 → 展示来源 → 用户编辑
                                      ├→ 保存建议
                                      └→ 人工确认后创建任务
```

AI 失败时，任务和日志等基础业务仍可使用；没有来源的内容不能以确定事实展示。

## 8. 页面体验原则

### 信息优先级

每页只设置一个主要任务：

- 导图：知道今天最重要的事；
- 视图：找到某一天的工作安排；
- 日志：完成当天记录并提交；
- AI 地图：理解建议并决定下一步；
- 我的：进入个人和系统辅助功能。

### 操作优先级

- 首屏显示主要 CTA；
- 次要操作放入页面标题操作区或底部操作区；
- 危险操作需要确认；
- 表单提交期间禁用重复提交；
- 成功后给出明确反馈并回到合理上下文；
- 错误消息说明“发生了什么”和“下一步做什么”。

### 视觉边界

阶段 0 只确定方向，不在本阶段定最终色值：

- 整体使用清爽企业工作台风格；
- 颜色服务于信息层级和状态表达；
- 卡片和插画用于辅助理解，不堆叠装饰；
- AI 地图允许有独立识别度，但不能脱离全局主题；
- 不使用大面积渐变、发光球、持续动画或营销型首屏。

## 9. 页面状态边界

所有列表、详情和表单必须支持以下状态模型：

```text
initial      初始
loading      加载中
success      正常内容
empty        无数据
error        请求失败，可重试
forbidden    无权限
unauthorized 登录失效
saving       保存或提交中
saved        保存成功
conflict     版本冲突
offline      暂时离线
```

状态的表现要求：

- loading 使用骨架屏或局部进度，不让页面空白等待；
- empty 给出原因和下一步操作，不制造假数据；
- error 提供重试入口和简短原因；
- forbidden 说明权限边界，不显示误导性的空列表；
- conflict 保留用户输入，并提供重新读取或返回编辑的选择；
- success 使用轻量反馈，不阻塞后续操作。

## 10. 阶段 0 的需求假设

以下假设风险较低，暂按产品方案执行：

| 假设 | 原因 | 若不成立的影响 |
