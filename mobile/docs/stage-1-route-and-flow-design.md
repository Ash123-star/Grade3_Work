# Flutter 阶段 1：路由与用户流程设计

状态：方案已确认，代码已实现；Flutter 工具链验收待补

本文档是阶段 1 的设计方案。它只定义页面路由、导航结构、进入和退出流程、权限跳转和异常路径，不修改 `mobile/lib/routing/` 或页面代码。阶段 1 获得确认后，才进入阶段 2 的 UI 主题和页面设计工作。

## 1. 阶段目标

将阶段 0 已确认的产品边界转换为可实现的路由和流程：

- 五个主导航共用一套底部导航；
- 默认进入导图；
- 员工与管理者使用同一导航框架，管理入口按权限显示；
- 日志、任务、视图和 AI 页面之间有明确的进入和返回关系；
- 登录失效、待确认、无权限、资源不存在和版本冲突都有稳定落点；
- 页面设计阶段可以基于稳定路由制作 Mock 界面，不依赖后端是否完成。

## 2. 路由设计原则

### 2.1 用户可见路由使用业务语义

最终路由应表达页面用途，不让用户可见路径依赖通用资源字符串。现有 `/list/:resource`、`/item/:resource/:id`、`/form/:kind` 可以继续作为内部复用机制，但应逐步由明确的业务路由入口调用。

### 2.2 主导航使用状态保持

五个主导航使用持久化分支：

```text
导图  → /dashboard
视图  → /view
日志  → /logs
AI 地图 → /ai
我的  → /me
```

从一个主导航进入详情页后，返回应回到原导航分支，并保留该分支的日期、筛选和滚动状态。

### 2.3 子页面使用普通栈路由

列表、详情、编辑和确认页面使用栈式进入，返回顺序遵守用户实际浏览路径。危险操作和关键提交不使用不可追踪的多层弹窗代替页面。

## 4. 主导航流程

### 4.1 登录到导图

```text
/auth/login
  ├─ 登录成功且账号可用 → /dashboard
  ├─ 账号待确认 → /auth/pending
  ├─ 必须首次改密 → /auth/password
  ├─ 账号停用 → /auth/disabled
  ├─ 凭据错误 → 保留 /auth/login，显示字段或表单错误
  └─ 网络失败 → 保留 /auth/login，显示重试
```

### 4.2 导图

```text
/dashboard
  ├─ 公司展示项 → /dashboard/company → 展示详情
  ├─ 公司任务 → /dashboard/tasks → /tasks/:id
  ├─ 个人重点 → /dashboard/personal → 新增/编辑/归档
  ├─ 个人日志 → /logs/mine 或 /logs/:id/edit
  └─ 有派发权限 → /tasks/create
```

导图返回时保留四象限滚动位置。新增任务完成或取消后返回导图，不跳到无关页面。

### 4.3 视图

```text
/view
  ├─ 日 → /view/day
  ├─ 周 → /view/week
  ├─ 月 → /view/month
  ├─ 点击任务 → /tasks/:id
  └─ 点击日志 → /logs/:id
```

日、周、月共享当前业务日期，但切换视图不清空用户选择的日期。详情返回后恢复原视图和日期。

### 4.4 日志

```text
/logs/mine
  ├─ 写今天日志 → /logs/:id/edit
  ├─ 打开已提交日志 → /logs/:id
  ├─ 历史修订 → /logs/:id/history
  └─ 提交修订 → /logs/:id/revise

/logs/subordinates
  ├─ 选择成员
  ├─ 选择业务日期
  └─ 打开下属日志 → /logs/:id
```

下属日志入口只出现在管理者的日志页，不放入导图或个人设置作为替代入口。

### 4.5 AI 地图

阶段 1 只固定入口和子页面，不提前决定首页首屏是“今天优先三件事”还是关系图：

```text
/ai
  ├─ /ai/analysis
  ├─ /ai/risk
  ├─ /ai/actions
  ├─ 点击来源 → /tasks/:id 或 /logs/:id
  ├─ 点击建议 → /ai/:id
  └─ 人工确认 → /ai/:id/confirm-task
```

首页具体布局和首屏优先级留到阶段 3 的页面设计方案比较后再确认。

### 4.6 我的

```text
/me
  ├─ 个人主页 → /me/profile
  ├─ 消息 → /me/notifications
  ├─ 统计 → /me/statistics
  ├─ 设置 → /me/settings
  ├─ 帮助 → /me/help
  └─ 管理员 → /me/admin/*
```

管理入口只在具备相应权限时显示；直接访问无权限路由统一进入 `/system/forbidden`，不显示空白页。

### 4.7 统一下属工作台

#### 需求判断

当前实现中的下属查看主要集中在日志页：管理者切换“下属日志”、选择成员和日期，然后查看日志列表；组织成员详情页已经可以展示个人资料、个人重点和已提交日志，但入口和分类还不够统一。

用户提出的“从一个统一入口选择下属，再按分类查看信息、日志、任务等”能够减少管理者在多个页面之间寻找成员，也更适合后续扩展统计和 AI 摘要。因此不把下属查看设计成日志页的附属功能，而是增加一个管理者专用的下属工作台。

#### 方案比较

| 方案 | 结构 | 优点 | 风险 |
|---|---|---|---|
| A：日志专属入口 | 日志 → 下属日志 → 选择成员 | 改动小，符合当前实现 | 只能围绕日志查看，任务、重点和资料入口分散 |
| B：统一下属工作台 | 我的 → 下属工作台 → 选择成员 → 分类查看 | 入口统一，适合持续查看一个成员的整体工作 | 需要明确分类权限和返回状态 |
| C：完全替代日志入口 | 只保留下属工作台，移除日志页入口 | 路由更少 | 违反“下属日志入口固定在日志页”的产品规则 |

#### 推荐方案：B + 日志页快捷入口

采用方案 B，同时保留日志页的固定入口：

```text
我的 → 下属工作台 → 选择成员 → 下属详情工作台 → 分类查看
日志 → 下属日志 → 选择成员和日期 → 直接查看该成员日志
```

两条入口使用同一套成员和权限数据，但用途不同：下属工作台适合查看一个人的整体情况，日志页入口适合快速完成按成员、按日期查看日志。

#### 下属工作台页面结构

1. `/me/team`：管理范围内成员列表，支持姓名或部门搜索、组织分类、成员状态和摘要信息。
2. `/me/team/:memberId`：下属详情工作台，顶部显示头像、姓名、部门、团队、直属关系、“正在查看：某某”、返回列表和返回本人面板。
3. 详情分类固定为：`概览｜资料｜重点｜日志｜任务｜AI 摘要`。

分类内容和边界如下：

| 分类 | 内容 | 默认操作 | 操作边界 |
|---|---|---|---|
| 概览 | 最近活动、待处理任务、最近日志、个人重点摘要 | 打开对应详情 | 只读，不显示私人备注和未提交草稿 |
| 资料 | 头像、姓名、部门、团队、介绍 | 查看公开资料 | 不允许修改组织归属和角色 |
| 重点 | 个人公开重点 | 查看重点详情 | 不允许管理者代替成员编辑 |
| 日志 | 已提交日志、日期筛选、评语 | 查看日志、添加评语 | 不显示未提交草稿；评语权限由服务端决定 |
| 任务 | 授权范围内任务、任务事件和成果 | 查看或进入业务操作 | 不扩大成员任务范围 |
| AI 摘要 | 带来源的工作摘要和风险提示 | 查看来源 | 不能读取私人备注，不能直接替成员创建任务 |

#### 下属详情交互

```text
进入下属列表 → 搜索或按组织分类 → 选择成员 → 进入概览
→ 选择分类 → 查看列表或详情 → 返回时保留成员和当前分类
```

从日志页进入时可以直接打开“日志”分类并携带日期筛选；从任务或导图进入时可以直接打开“任务”分类。返回后回到原来源页面，而不是强制回到下属列表。

#### 权限边界

- 只有管理者或服务端明确授权的角色显示下属工作台；
- 普通员工不显示入口，也不能通过深链访问；
- 管理者只能搜索和查看自己的组织数据范围；
- 下属工作台默认只读，不代替成员提交日志、接受任务或修改个人重点；
- 评语、任务派发、验收等操作仍遵守各自业务权限；
- 私人备注、未提交日志草稿、密码和敏感信息永不显示；
- 无权限或资源消失时进入统一错误状态，不显示空白工作台。

该设计不新增第六个底部导航。下属工作台作为“我的”中的管理入口，“日志 → 下属日志”继续保留，满足日志场景的固定入口要求。

## 5. 跨页面业务流程

### 5.1 任务闭环

```text
/tasks/create
  → /tasks/:id
  → /tasks/:id/feedback
  → /tasks/:id
  → /tasks/:id/accept
  → /tasks/:id
  → 归档后回到来源列表
```

每次提交后回到任务详情并刷新事件时间线。后端拒绝、版本冲突或重复提交时仍停留在当前任务上下文。

### 5.2 日志闭环

```text
/logs/mine
  → /logs/:id/edit
  → 保存草稿
  → 提交
  → /logs/:id
  → /logs/:id/history 或 /logs/:id/revise
```

离开编辑页时保留本地草稿。提交成功后清除对应草稿，提交失败时保留输入内容。

### 5.3 AI 建议闭环

```text
/ai/analysis
  → /ai/:id
  → /ai/:id/edit
  → /ai/:id/confirm-task
  → /tasks/:id
```

AI 生成失败进入当前页面的错误状态，不影响任务和日志页面。没有来源的建议只能作为不确定的提示，不能进入任务确认流程。

## 6. 路由守卫

| 守卫 | 判断 | 目标 |
|---|---|---|
| 未登录 | 没有有效会话 | `/auth/login` |
| 待确认 | 账号状态为待确认 | `/auth/pending` |
| 首次改密 | 服务端要求改密 | `/auth/password` |
| 已停用 | 账号被停用 | `/auth/disabled` |
| 管理权限 | 管理员入口无权限 | `/system/forbidden` |
| 资源权限 | 详情不在授权范围 | `/system/forbidden` 或安全的不存在页 |
| 资源不存在 | 记录已删除或 ID 无效 | `/system/not-found` |
| 离线/服务不可用 | 页面请求无法完成 | 当前页面保留错误和重试 |
| 版本冲突 | 提交版本已过期 | `/system/conflict` 或当前页冲突面板 |

路由守卫只负责用户体验和入口限制，不能替代服务端授权。

## 7. 返回与状态保持规则

- 从详情返回列表时保留列表筛选、日期、分页位置和滚动位置；
- 从表单取消返回来源页面，不创建空记录；
- 表单保存失败不清空字段；
- 表单提交成功回到详情或来源列表，并显示一次性成功反馈；
- 登录失效后跳转登录页，登录成功后尽量返回原目标路由；
- 用户主动退出后清空受保护页面栈，不允许返回看到业务内容；
- 进入他人面板后显示查看对象和返回本人入口；
- 无权限页面不能通过返回按钮循环回到受保护页面。
