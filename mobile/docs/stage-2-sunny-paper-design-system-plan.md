## 1. 目标、范围与验收故事

视觉目标：明亮、亲切、有动漫感的移动协作工作台。奶油纸张提供阅读底色，鲜橙建立品牌和行动焦点，软圆角、彩色图标托盘、Q 版伙伴和轻弹性反馈共同表达卡通风格。

| 用户故事 | 优先级与范围 | 正向验收 | 异常或边界验收 |
|---|---|---|---|
| 作为员工，我希望按钮和导航鲜明、圆润，快速找到工作入口 | P0，五栏、按钮、字段、卡片 | 默认导图；统一动漫橙选中态，文字清晰 | 长标题和 1.5 倍字体不遮挡；禁用与选中可区分 |
| 作为使用者，我希望 Q 版伙伴陪伴记录工作和理解 AI 建议 | P1，欢迎、空状态、反馈、来源提示 | 同一角色的表情与业务状态一致 | 错误、待审、离线不庆祝；隐藏插画仍可理解状态 |
| 作为管理者，我希望温和风格中仍清楚识别权限和审核信息 | P0，日志、任务、审核、成员面板 | 查看对象、来源、版本和主操作可辨认 | 无权限不伪装空数据；驳回理由和冲突输入可保留 |

本批次产物：主题规范、官方参考研究、静态风格示意和 OpenSpec 计划。Flutter 页面、路由、Repository、后端、数据库、原型重绘和生产角色素材属于后续任务；本次不删除仍被引用的资源。

## 2. 官方参考及取舍

详细查阅记录见 [主题研究](stage-2-ui-theme-research.md)。观察结论与本项目的设计数值分开记录。

| 参考 | 采用的模式 | 本项目落点 |
|---|---|---|
| [Duolingo 官方导航重设计](https://blog.duolingo.com/core-tabs-redesign/) | 彩色图标与人物、统一标题、按页面目的分配容器和插画 | 圆润导航、语义托盘、一致组件；不引入员工排名或打卡惩罚 |
| [Finch 官网](https://finchcare.com/) | 圆头角色、明亮柔和色块、温和陪伴语气 | 原创 Q 版人物、状态表情；不引入宠物养成系统 |
| [Headspace 官网](https://www.headspace.com/)及[产品页](https://www.headspace.com/app) | 明亮橙黄、圆形角色、浅底和彩色内容区域、胶囊操作 | 奶油底 + 鲜橙 + 薄荷/蓝/淡紫，保留协作业务的信息结构 |

推荐组合：Duolingo 的组件一致性 + Finch 的角色亲和力 + Headspace 的暖色与彩色内容分区。本项目色值及 Q 版人物为自定义，不是竞品官方数值或可复制素材。

## 3. 视觉组成与密度

- 品牌橙持续出现在主按钮、选中导航、派发加号、局部标题标记和角色服装。
- 奶油背景与暖白表面承载正文；薄荷、天空蓝、淡紫和桃粉作为明确分区色。
- 首页允许一个 72～96dp 高的角色欢迎区域；四象限必须保留，大插画不替代工作内容。
- 人物可跨页面出现于标题旁小半身、空状态、提交反馈和 AI 助手；同屏最多一个主要人物插画，彩色图标托盘不计入人物数量。
- 常规列表保持清楚的任务、时间、人物和来源层级；不在每一行重复大插画。
- 每屏一个主 CTA；次操作通过描边、浅底或文字层级区分。

可见面积建议约 60% 奶油/暖白、20% 浅色分区、15% 鲜橙、5% 人物细节与强调色；这是评审参考，不是逐像素配额。重点卡允许局部橙色渐变，但文字区仍以已验证的纯色承载；正文和长表单不使用纹理或渐变背景。

| 角色 | 前景 | 浅容器 | 用途 |
|---|---|---|---|
| 薄荷/成功 | #246447 | #DEF4E6 | 个人重点、真实保存成功 |
| 天空蓝/信息 | #275E8D | #E2F1FF | 授权任务、来源、说明 |
| 淡紫/AI | #7650B6 | #F1E7FF | 建议、关系节点、助手托盘 |
| 蜂蜜黄/警告 | #795000 | #FFF0BD | 临期、待审、需关注 |
| 桃粉/日志分区 | #3C3028 | #FFE5D2 | 日志编辑提示与欢迎 |
| 珊瑚红/错误 | #B33643 | #FFE3E6 | 字段错误、失败、危险操作 |
| 禁用 | #756456 | #F1E8DC | 禁用按钮；同时去掉深下沿并解释原因 |

颜色必须配文字和图标。品牌橙不代表警告；任务蓝不代表完成状态。派发页不得借色彩徽标增加完成情况或替代状态字段。

### 4.3 Material 3 与文字约束

primary、onPrimary、primaryContainer、onPrimaryContainer、surface、onSurface、onSurfaceVariant、outline、outlineVariant、error 映射 ColorScheme 对应字段；secondary 使用 AI 紫及对应前景/容器，tertiary 使用薄荷。拟议 SunnyPaperTokens ThemeExtension 承载 canvas、按下色、按钮下沿、分区色、形状、动效，实例字段支持 copyWith 和真实 lerp，不继续只使用静态常量。

正文使用 onSurface，橙色小字只用 primaryText。outlineVariant 只表达装饰边界；输入框、勾选框、焦点不可单靠浅边界识别。选中 chip 使用成对定义的深前景和浅容器。

## 5. 圆角、描边、层次和尺寸

| 对象 | 形状/尺寸 | 层次 |
|---|---|---|
| 普通业务卡 | 20dp 圆角；16dp 内边距 | 1dp 暖边界，轻阴影或无阴影 |
| 重点/人物卡 | 24dp 圆角；16～20dp 内边距 | 浅橙/分区浅底，最多 2～4dp 下沿 |
| 主按钮 | 18dp 圆角；最小高 52dp；水平内边距 20dp | 鲜橙、3dp 深橙下沿；按下缩至 1dp |
| 次按钮 | 18dp 圆角；最小高 52dp | 暖白，1.5dp 必要边界 |
| 输入框 | 16dp 圆角；单行最小高 56dp | 默认 1.5dp outline；聚焦 2dp primaryText；错误 2dp error |
| chip/分段选项 | 胶囊；最小交互高 48dp | 浅底深字；选中浅橙 + 勾选 |
| 只读徽标 | 胶囊；视觉高 24～28dp | 可点击时外层触控仍至少 48dp |
| 图标托盘 | 14～16dp 圆角；容器 40dp，图标 24dp | 分区浅底，有轮廓图标 |
| 底栏 | 顶部 24dp 圆角；内容约高 76dp，另加安全区 | 暖白；选中胶囊、橙标记、文字 |
| FAB | 圆形 56dp | 深可可加号；遵守派发资格，避开底栏 |
| 底部弹层 | 顶部 28dp 圆角 | 关闭路径、标题、安全区 |

圆润通过真实圆角、圆帽图标线条和软下沿实现，不把所有控件变成巨大气泡。下沿仅用于主行动；不复制到全部字段和卡片。列表行最小高 64dp，复杂表单保持单列。

卡片阴影候选 offset (0,3)、blur 10、spread 0、#44210D 的 6% 不透明度；导航/弹层 offset (0,4)、blur 18、8%。阴影是装饰，不能替代控件必要边界。

## 6. 字体、间距与响应式

中文使用系统无衬线字体；圆润字重、组件和人物承担卡通感。品牌标题如需圆体，后续确认字体许可，本轮不增加字体依赖。

| 文字角色 | 字号/字重 | 行高 |
|---|---|---|
| 页面标题 | 24sp/700 | 1.25 |
| 欢迎标题 | 20sp/700 | 1.3 |
| 区块标题 | 18sp/600 | 1.35 |
| 卡片标题 | 16sp/600 | 1.4 |
| 正文 | 15～16sp/400 | 1.5 |
| 辅助说明 | 13～14sp/400 | 1.45 |
| 按钮 | 16sp/600 | 1.25 |
| 底栏标签 | 12sp/600 | 1.3 |

间距令牌 4、8、12、16、20、24、32dp；页面左右 16dp、卡片间 12dp、区块间 24dp。高度随内容变化，不截断主操作。

主要检查 360×800、390×844 和字体 1.0/1.3/1.5 倍。四象限保持两行两列并可纵向滚动；字体放大时减少预览条数、允许标题换行和操作折行。角色欢迎横排可退化为小头像 + 文字。底部操作随键盘与 SafeArea 调整，失败和失焦不丢输入。

## 7. Q 版人物体系

### 7.1 推荐造型

原创中性 Q 版工作伙伴，临时代号“橙橙”：约 2.5 头身、圆脸、短四肢、柔和深棕描边；橙色外套/卫衣、奶油内搭、浅蓝小挎包，额前一撮弧形头发；手持笔记本、地图卡或铅笔。

至少准备 welcome、writing、explaining、success、empty、retry 六种姿态。最终肤色、发型和衣服细节通过角色稿评审。角色不根据性别或职级分配高低地位造型，不复制商业动漫角色、Duo 或 Finch 小鸟。

品牌角色与身份头像分开：不能冒充真实员工、当前用户或审核人。

### 7.2 使用规则

| 场景 | 姿态与尺寸 | 必须配合的业务信息 |
|---|---|---|
| 导图欢迎 | 挥手半身 72～96dp | 真实日期/概要，不编造任务 |
| 日志空状态 | 拿铅笔 96～120dp | 写今天的日志入口 |
| 日志编辑 | 书写小头像 40～48dp | 保存状态，不遮挡字段 |
| AI 建议 | 指向来源 64～80dp | 来源、生成时间、不确定提示 |
| 保存/提交成功 | 点头/挥手 48～64dp | 真实成功后才出现 |
| 超时/离线 | 等待/整理笔记 72～96dp | 原因、重试、保留内容 |
| 无权限/驳回 | 中性表情或纯图标 | 权限边界和驳回原因优先 |
| 审批/审计列表 | 不放大人物 | 用彩色托盘延续风格，版本与正文优先 |

同屏一个主要人物；人物可以持续作为跨页面识别元素，不局限于空状态。装饰人物从语义树排除，信息由文本同步表达。减少动态效果时使用静态姿态；没有持续漂浮或眨眼。

### 7.3 资产交付

后续角色优先项目自有矢量稿；外部素材仅从官网/GitHub 选择，核对许可。需要位图或动画时另开资产批次，不自动增加动画运行库。

## 8. 组件状态矩阵

| 拟议组件 | 默认表达 | 状态与边界 |
|---|---|---|
| SunnyPrimaryButton | 鲜橙深字、18dp、下沿 | 按下下移 2dp；加载保留标签/宽度；禁用不可触发；外扩焦点圈 |
| SunnyCard | 暖白/语义浅底、20dp | 长文本增高；非交互卡无点击效果 |
| SunnyTextField | 16dp、常驻标签 | placeholder 不代替标签；字段错误；冲突保留输入 |
| SunnySegmentedControl | 胶囊组、浅橙选中 | 日周月保留日期；selected 语义；48dp 目标 |
| SunnyNavigationBar | 五栏、彩色图标、选中胶囊 | 左到右导图/视图/日志/AI地图/我的，默认导图；未读数可读 |
| SunnyStatusBadge | 深前景/浅容器、文字图标 | 待审与成功不同；派发页不表达完成情况 |
| SunnyCharacterPanel | 人物、标题、短说明、可选 CTA | 隐藏装饰仍可理解；低宽度不挤掉 CTA |
| SunnyStatePanel | 统一加载/空/错误/权限结构 | 每个状态有恢复路径；不填样例掩盖失败 |

| SunnyConfirmSheet | 28dp 顶部圆角、单列 | 内容、版本、权限可读；取消不写业务 |

交互组件覆盖 enabled、pressed、focused、disabled、loading；字段补充 invalid，列表/详情覆盖 loading、empty、error、forbidden、unauthorized、offline，写操作覆盖 saving、saved、conflict。禁用、加载和只读不能仅靠透明度区分。

## 9. 五个主页面应用

| 页面 | 配色与人物 | 必须保留 |
|---|---|---|
| 导图 | 橙橙小欢迎；浅黄/蓝/薄荷/桃粉四象限；橙 FAB | 公司重点/公司任务在上且只读，个人重点/日志在下；2～3 条预览和查看全部 |
| 视图 | 奶油画布、橙日期和分段、蓝任务/桃色日志 | 日周月、实际时间、事件类型；人物用于无记录 |
| 日志 | 暖白正文、桃色日期、橙提交、小书写人物 | 独立业务日期、我的/下属、草稿/修订/评语 |
| AI 地图 | 淡紫节点、蓝来源、橙确认、解释人物 | 发展分析/堵点风险/行动规划；来源和人工确认；首屏两方案留到阶段 3 比较 |
| 我的 | 浅橙身份卡、入口彩色托盘 | 真实身份、消息、统计、下属/管理员入口、返回本人 |

认证页可用大人物，字段错误仍靠近输入和按钮。任务、审核、他人面板沿用组件，不新增完成情况字段，不显示草稿和私人备注，不代替成员提交。

## 10. 动效与文案

| 令牌 | 参数建议 | 用途 |
|---|---|---|
| press | 100ms、easeOut、下移 2dp | 主按钮软下压 |
| selection | 160ms、easeOutCubic | 导航/胶囊 |
| enter | 200ms、easeOutCubic、位移 4dp | 页面内容进入，滚动不重播 |
| sheet | 240ms、easeOutCubic | 底部弹层 |
| characterFeedback | 400～600ms，一次 | 保存后的点头/挥手 |

减少动态效果时即时切换；人物没有持续循环，局部实际加载可以进度指示。AI 需可取消或超时恢复，未接入远程取消时明确演示边界。

文案亲切但准确：“草稿已保存”“网络暂时连不上，内容还在，可以重试”；待审用“修订已提交，等待复核”，不使用“完成啦”。权限错误说明范围，驳回展示实际理由，不让人物责备员工。

## 11. 技术路线与迁移

| 路线 | 兼容性/成本 | 结论 |
|---|---|---|
| cute_ui 仅替换颜色 | 成本低，但静态令牌、旧形状和页内颜色继续耦合 | 不选 |
| App 拥有 Material 3 + SunnyPaperTokens，渐进适配现有组件 | 不加 UI 框架，页面可回滚；需盘点旧引用 | 推荐，theme 管令牌、shared 管组件 |
| 第三方卡通框架/重动画库 | 主题冲突、包体、许可和维护成本增加 | 当前不采用 |

实施顺序：
1. 同步 OpenSpec、关联 Issue，保持范围和验收明确。
2. 落实主题令牌与组件状态页。
3. 更新 HTML：完整四象限、一个可编辑表单、至少一种失败恢复。
4. 迁移导航/公共组件，以导图代表页和日志压力页评审。
5. 制作角色最终稿，再迁移其他主页面、认证和业务详情。
6. 盘点旧颜色/组件/资产，仅在调用方迁移验证后清理。
7. 集中执行分析、测试编译、实际渲染及可执行手工验收，记录未验证和接口缺口。用户已明确禁止本环境APK构建。
