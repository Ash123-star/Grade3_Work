# Flutter 阶段 2：UI 主题与高级感调研

状态：调研完成，等待用户确认；本阶段不修改 Flutter 代码。

本文把“卡通动画、温馨、高级、适合企业工作台”转化为可执行的视觉规则。它不直接决定 AI 地图首页布局，也不替代阶段 3 的页面布局设计。

## 1. 调研目标与边界

### 1.1 目标

- 为五个主导航建立同一套视觉语言，而不是每页单独换颜色；
- 在手机竖屏中保持清楚的任务层级、足够的点击区域和可读对比度；
- 让卡通插画承担情绪和解释作用，同时保持企业工作台的效率感；
- 为导图、视图、日志、AI 地图、我的，以及认证、任务和下属工作台提供可复用的主题角色；
- 给后续 AI coding 提供一份可检查的设计输入，减少“看起来漂亮但无法持续维护”的页面。

### 1.2 不在本阶段决定的内容

- 不实现 `app_theme.dart`、页面布局、动效或图片资源；
- 不确定 AI 地图首页首屏采用优先三件事还是关系图；
- 不新增 Flutter UI 框架或后端接口；
- 不复制具体商业产品的商标、插画或页面源码；
- 不把渐变、阴影或动画数量当成高级感指标。

## 2. 当前代码基线

当前主题入口是 `mobile/lib/theme/app_theme.dart`，实际直接调用 `cute_ui` 的 `cuteTheme()`。`mobile/packages/cute_ui/lib/cute_ui.dart` 已包含：

- Material 3 `ColorScheme.fromSeed`；
- `CuteTokens`：墨色、薄荷绿、珊瑚橙、奶油白、画布色、分隔线、弱文字、蓝色和黄色状态底；
- `CuteCard`、`SectionHeader`、`StatusPill`、`EmptyIllustration`、`ErrorPanel`、`LoadingSkeleton`；
- OpenMoji 本地 SVG：机器人、火箭、笔记、日历、植物、星星；
- 按钮和图标最小尺寸已接近 48dp，卡片圆角为 8dp。

这说明项目已有“温和卡通”的起点，但还缺少颜色角色命名、语义状态色、字体层级、组件变体、插画使用密度、动效时长和无障碍验收。阶段 2 的实现应优先扩展现有 `CuteTokens` 和 Material 3 主题，而不是再引入一套平行颜色系统。

## 3. 可借鉴的公开设计依据

本次参考的是公开设计系统和产品模式，不直接照搬某个商业项目：

| 来源 | 可借鉴内容 | 对本项目的约束 |
|---|---|---|
| [Material Design 3 色彩系统](https://m3.material.io/styles/color/system/overview) | 用 primary、secondary、surface、on-surface、error 等角色表达语义；支持浅色/深色和动态对比 | 颜色按角色命名，组件不直接散落写十六进制颜色 |
| [Material 3 无障碍](https://m3.material.io/foundations/accessible-design/overview) | 文字、图标、控件需要足够对比度和可感知反馈 | 状态不能只靠颜色；同时使用文字、图标或形状 |
| [Flutter Material 3](https://docs.flutter.dev/ui/design/material) | 使用 `ThemeData`、`ColorScheme`、组件主题集中控制视觉 | 页面只使用主题角色和组件，不在业务页创建局部主题 |
| [Apple Human Interface Guidelines](https://developer.apple.com/design/human-interface-guidelines/) | 信息优先级、触控目标、反馈和动效应服务于任务 | 卡通元素不能遮挡主要操作，动效必须可跳过 |
| [Atlassian Design System](https://atlassian.design/) | 企业工具中的状态、密度、反馈和一致组件模式 | 保持工作台效率，不把所有内容做成大插画卡片 |
| [OpenMoji](https://openmoji.org/) / [GitHub](https://github.com/hfg-gmuend/openmoji) | 统一的彩色手绘符号，可用于空状态和轻量引导 | 继续遵守 CC BY-SA 4.0 署名和本地打包规则 |

“高级感”在这些系统中的共同点不是昂贵素材，而是稳定的间距、明确的层级、克制的强调色、可预测的交互和完整的空/错/加载状态。

## 4. 主题方向比较

### 4.1 方向 A：温馨企业工作台（推荐）

奶油白或浅灰画布作为底色，深墨色正文，薄荷绿作为主行动色，珊瑚橙只用于提醒和少量情绪点缀。卡片使用白色和细描边，插画只出现在空状态、首次引导、AI 建议和完成反馈。

优点：和现有 `cute_ui` 最兼容；企业场景可读；长期使用不疲劳；状态颜色容易扩展。风险是需要严格控制橙色和插画密度，否则会显得幼稚。

### 4.2 方向 B：卡通成长工作台

在主色基础上增加蓝、黄、紫等成长标签，使用更多角色插画、徽章和进度反馈。

优点：反馈有情绪，适合新手引导和 AI 建议。风险是容易像学习或游戏产品，降低企业任务的严肃度；统计、审批和日志页面会出现视觉噪声。

### 4.3 方向 C：柔和插画工作台

以低饱和米色、雾蓝和浅绿组成大面积背景，使用较大的场景插画和柔和阴影。

优点：氛围最强，空状态和 AI 地图容易做出记忆点。风险是背景与文字对比变弱，手机小屏的有效信息面积减少，图片资源成本更高。

### 4.4 方向 D：深色 AI 科技主题（不推荐作为全局主题）

深色画布、霓虹蓝紫、发光节点和大量动态关系线。

优点：AI 地图有辨识度。风险是与温馨卡通目标冲突，长时间阅读日志不舒适，普通任务和表单的可读性及无障碍成本更高。若使用，只应作为 AI 地图的局部视觉状态，且仍保留全局文字、按钮和状态规则。

### 4.5 推荐结论

采用 **方向 A 作为全局基线**，吸收方向 C 的少量柔和插画手法，并允许 AI 地图在局部使用更强的节点色。方向 B 只用于成就、完成反馈和新手引导，不用于主业务列表。方向 D 不作为默认主题。

## 5. 推荐色彩系统（候选，不代表已批准实现）

颜色应先定义角色，再定义具体色值。以下色值延续已有 `CuteTokens`，是阶段 2 实现的候选基线：

| 角色 | 候选色值 | 使用位置 | 规则 |
|---|---|---|---|
| `canvas` | `#FAFCFB` | 页面底色 | 保持大面积安静，不放装饰渐变 |
| `surface` | `#FFFFFF` | 卡片、表单、底部导航 | 与画布形成轻微层级，不使用厚重阴影 |
| `surfaceWarm` | `#FFF9F0` | 温馨提示、引导、日志情绪卡 | 不作为所有卡片的默认底色 |
| `primary` | `#257D68` | 主按钮、选中态、关键链接 | 同屏只保留一个主要行动色 |
| `primaryContainer` | `#D8EFE6` | 选中导航、轻量强调背景 | 文字必须使用深色角色 |
| `secondary` | `#FF9D87` | 提醒、AI 建议点缀、完成反馈 | 不用于大段正文和整页背景 |
| `infoContainer` | `#E9F2FC` | 来源、说明、普通信息 | 结合信息图标和文字 |
| `warningContainer` | `#FFF3C9` | 临期、待处理、需要关注 | 同时显示“待处理/临期”等文字 |
| `error` | `#BA1A1A` | 错误、危险操作、失败状态 | 不用珊瑚橙替代错误色 |
| `outline` | `#DCE6E1` | 分隔线、输入框描边 | 只做结构，不抢正文注意力 |
| `onSurface` | `#263238` | 标题、正文、主要图标 | 正文不使用彩色低对比文字 |
| `onSurfaceVariant` | `#5B6D65` | 辅助说明、时间、次要信息 | 重要信息不得只放在此角色 |

实现时应通过 `ColorScheme` 和 `ThemeExtension` 提供这些角色，业务页面不得直接引用 `Colors.orange`、`Colors.grey` 等临时颜色。深色主题、动态颜色和色盲模拟属于后续适配，不应在本阶段偷偷引入第二套未经验证的色板。

## 6. 视觉规范草案

### 6.1 字体和层级

- 优先使用系统中文字体，保证 Android 无需额外下载字体；
- 页面标题 24sp，区块标题 18～20sp，卡片标题 16sp，正文 14～16sp，辅助信息 12～14sp；
- 正文行高约 1.45～1.6，标题字距保持 0；
- 一页只设置一个最高层级标题，卡片内部不使用英雄式大字；
- 字体放大后不能截断主要操作，长标题允许换行。

### 6.2 间距和形状

- 采用 4dp 基线，常用间距为 8、12、16、24、32dp；
- 主卡片圆角候选 12dp，输入框和按钮圆角候选 10～12dp；现有 8dp 可作为密集列表和表格行的下限；
- 触控目标至少 48dp，主要列表行建议 56dp 以上；
- 阴影只用于浮层、底部操作条和需要与背景分离的卡片，普通卡片优先使用描边和留白；
- 禁止在同一个页面混用过多圆角、厚边框和阴影层级。

### 6.3 卡通资产规则

- 插画用于解释状态：空数据、加载完成、错误恢复、AI 建议和首次使用；
- 常规列表、审批、日志正文和统计表保持清爽，不在每行重复放大插画；
- 同一页面最多一个主插画区域，图标和插画保持同一线条/填充风格；
- OpenMoji 继续本地打包，保留 `mobile/packages/cute_ui/ATTRIBUTION.md` 的作者、来源和 CC BY-SA 4.0 说明；
- 不使用外部热链、未授权商业插画或从竞品截图中抠图；
- 新增图片资产需记录来源、许可、版本和用途。

### 6.4 动效规则

- 首选短、可预测的过渡：页面 180～240ms，轻量反馈 120～180ms；
- 只对状态变化、导航层级和操作反馈做动效，避免循环漂浮、自动播放和持续闪烁；
- 加载使用骨架或局部进度，不能依赖动画传达唯一信息；
- 系统开启减少动态效果时，动画应降级为即时切换；
- AI 流式内容即使使用 Mock，也要显示可中断、失败和重试状态，不用无限“思考中”动画。

## 7. 五个主页面的视觉重点

| 页面 | 视觉重点 | 卡通元素边界 | 主要状态 |
|---|---|---|---|
| 导图 | 四象限层级、今天要做什么、个人与公司内容区分 | 只在区块空状态或完成反馈使用 | 正常、空、加载、权限不可用 |
| 视图 | 日期切换、日/周/月模式、时间轴扫描 | 不在每个事件上使用插画 | 无事件、跨日、错误、离线 |
| 日志 | 阅读和编辑舒适、草稿/提交状态清晰 | 空日志可用小插画，正文区域不装饰 | 草稿、保存中、已提交、冲突、无权限 |
| AI 地图 | 来源、风险、建议和人工确认层级 | 允许更鲜明节点色和一处助手插画 | 生成中、可编辑、无来源、失败、已确认 |
| 我的 | 个人身份、通知、统计和管理入口易找 | 头像/空状态可卡通化，设置列表保持简洁 | 未读、权限隐藏、账号停用、离线 |

这张表只规定视觉重点，不预设 AI 地图首页的最终布局。页面阶段仍需为 AI 地图比较“优先三件事”和“关系图入口”的真实信息密度。

## 8. 让 AI coding 生成高质量 UI 的实际方法

网络上看起来精致的 AI coding 项目，通常不是一次生成整页，而是把设计约束拆成可检查的输入，再分批实现：

1. **先给设计上下文**：提供产品目标、目标设备、页面清单、角色、非目标、现有组件和参考系统链接。
2. **先生成设计令牌**：要求模型先输出颜色角色、字号、间距、圆角、阴影、动效和无障碍规则，用户确认后再写代码。
3. **先做一个代表页**：用导图或日志做主题试做，验证卡片、按钮、导航、状态面板和插画密度，再扩展到其他页面。
4. **组件优先**：把 `AppShell`、页面头、卡片、状态容器、列表行、标签、表单字段和底部操作条做成复用组件，页面只编排业务内容。
5. **明确状态矩阵**：每个页面同时要求正常、加载、空、错误、无权限、保存中、冲突和离线状态，避免只生成“成功截图”。
6. **用真实文案和最窄屏幕约束**：中文长标题、无数据、权限提示和错误信息比占位英文更容易暴露布局问题。
7. **视觉评审循环**：实现后只做一轮统一验收，按 360dp/390dp 竖屏、字体放大、键盘弹出、滚动和无障碍语义检查，再集中修复。
8. **限制自由发挥**：明确“禁止大面积渐变、禁止装饰性毛玻璃、禁止无意义动效、禁止新依赖”，让模型围绕系统一致性优化。

可复用的提示词结构是：

```text
你是 Flutter Material 3 产品设计工程师。
目标用户：企业员工和管理者，手机竖屏优先。
视觉方向：温馨卡通，但工作台优先，正文保持高可读性。
必须使用：现有主题令牌、CuteCard、状态模型、OpenMoji 本地资产。
页面任务：<只写一个主要任务>。
必须覆盖：loading / empty / error / forbidden / saving / conflict。
约束：主操作触控区 >= 48dp；中文长文案可换行；不要大面积渐变和持续动画。
先输出：页面层级和组件清单；确认后再写 Dart 代码。
验收：窄屏无溢出，状态可恢复，颜色不作为唯一信息，组件不重复造轮子。
```

这类提示词只能提高输入质量，不能代替人工确认和最终运行验收。高级感最终来自设计令牌和组件复用，而不是模型使用了更多装饰。

## 9. 工具和技能选择

当前可用技能中没有一个专门“自动生成 Flutter 高级 UI”的单一 UI design skill。可组合使用：

| 工具/技能 | 适合用途 | 当前阶段是否使用 |
|---|---|---|
| `project-development-gate` | 需求、设计确认、实现和统一验收门 | 已使用，约束本阶段只做调研 |
| `imagegen` | 生成空状态、引导、AI 助手等位图资产 | 阶段 3 明确资产需求后再用 |
| `visualize:visualize` | 做主题对比、流程图或交互原型 | 需要视觉方案对比时可用 |
| `computer-use` | 浏览器查看公开设计系统、运行中的 App 截图检查 | 调研和最终手工检查可用 |
| Flutter Material 3 / `cute_ui` | 主题实现、组件复用、本地素材 | 阶段 2 实现时使用 |

Figma、Dribbble、Behance、Mobbin 等可以作为灵感来源，但需要把灵感转成自己的令牌和组件规则；不建议把截图直接当实现规格，也不建议引入与现有 Material 3 不兼容的 UI 套件。

## 10. 无障碍和质量门槛

阶段 2 实现后，至少检查：

- 正文、按钮文字、图标和背景有足够对比度；
- 状态同时有颜色、文字或图标；
- 所有主要交互可用 TalkBack 读出用途和当前状态；
- 触控目标不少于 48dp，底部导航和浮动按钮不遮挡内容；
- 系统字体放大后不溢出、不遮挡、不依赖固定高度；
- 空状态和错误状态都能回到有效业务路径；
- 低性能设备中无持续高频动画；
- AI、反馈、附件等 Mock 功能明确标注演示状态，不伪装为后端成功。

阶段 2 不执行完整 Flutter analyze/test；实现批次完成后再按仓库规则统一验收。调研文档只做轻量格式检查。

## 11. 推荐方案与待确认项

### 推荐方案

采用“温馨企业工作台”全局主题：奶油白/浅画布、深墨色正文、薄荷绿主行动、珊瑚橙小范围情绪点缀、白色描边卡片、OpenMoji 空状态插画。以 Material 3 颜色角色承载语义，以 `cute_ui` 作为现有组件基础，先完成一页代表性主题试做，再扩展全页面。

### 实现前需要确认

1. 是否同意方向 A 作为全局视觉基线，并吸收方向 C 的少量柔和插画手法；
2. 是否同意沿用现有薄荷绿/珊瑚橙/奶油白色系，只对颜色角色、对比度和组件状态做系统化调整；
3. 是否同意卡通插画主要用于空状态、引导、AI 建议和完成反馈，不铺满业务列表；
4. 是否同意阶段 3 先用导图或日志做代表页，再根据确认结果扩展五个主页面；
5. 是否同意阶段 2 实现前不确定 AI 地图首页布局，页面阶段再比较两种首屏方案。

用户确认后，下一步才进入主题令牌、组件变体和代表页面的代码设计；确认前不修改 `mobile/lib/theme/` 或 `mobile/packages/cute_ui/`。
