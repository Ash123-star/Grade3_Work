## 3. 员工日常路径与布局原则

早上：导图扫读公司重点和自己下一步 → 视图查看期限 → 打开任务。下午：任务详情提交成果/阻碍。下班：日志进入今天草稿 → 关联任务 → 提交。管理者：日志查看下属已提交内容 → 添加评语；我的进入审批对比变更。避免让每条路径反复进入通用列表或同一种详情卡。

| 页面形态 | 使用对象 | 空间语言 |
|---|---|---|
| 工作总览 | 导图 | 两行两列四象限，短条目，彩色区分语义 |
| 时间安排 | 日/周/月 | 真实网格、时间刻度与议程，无装饰性假日历 |
| 文档 | 日志阅读/编辑、AI 长分析 | 暖白纸张、连续正文和分节留白，减少层层套卡 |
| 工作对象 | 任务详情、成员工作台 | 摘要 + 关键属性 + 时间线/分类；动作基于权限 |
| 收件箱 | 日志历史、通知、审批 | 行式列表、日期/类别分组、清晰未读与筛选 |
| 配置 | 我的、设置、组织管理 | 分组入口、列表与纵向表单；不用十张同权重卡 |

通用尺寸继承阶段 2：左右 16dp，区块间 20～24dp，标题 24～28sp，正文 15～16sp；主页标题左对齐，图标有语义标签。底栏 76dp 加安全区。详情和编辑推入独立页面，隐藏底栏以集中阅读/写作。长页顶部保留标题，底部主操作位于安全区与键盘上方。

人物密度：主页仅导图小欢迎人物、AI 小解释人物；日志列表可以有一张很小的写作提示，文档阅读/审批不放人物。空状态使用原创人物和实际原因；失败不庆祝。人物不当真人头像。

## 4. 需求 → 页面覆盖矩阵

P0 是核心移动工作链，P1 是管理/辅助链，P2 是增强分析；它们是设计/实施顺序，不删除产品需求。所有入口以服务端授权为准。

| 优先级 / 页面 | 展示功能与主操作 | 角色 / 需求依据 | 异常或边界 |
|---|---|---|---|
| P0 登录/注册/首次改密 | 账号密码、注册手机号与部门选择；登录/申请加入/改密 | 所有人；方案 §2 | 注册只能员工；无部门列表显示加载失败，不让文本冒充 ID；不伪造短信验证 |
| P0 待确认/停用/失效 | 申请部门与账号状态、重新登录/退出 | 待确认、停用账号；§2 | 不显示任何业务摘要；失效不丢弃当前账号草稿 |
| P0 导图 | 公司重点/公司任务/个人重点/个人日志，查看全部/写日志 | 全部已授权角色；§4 | 每类最多置顶 10，空项不补齐；公司区域始终只读 |
| P0 公司/个人重点列表详情 | 置顶、正文；本人重点新增/排序/归档；私人备注 | 本人/授权受众；§4 | 置顶满额提示替换；私人备注不出现在他人面板/AI |
| P1 公司发布/修订 | 标题、正文、受众、变更原因，提交候选版本 | 具备发布权限；§3 | 旧有效版继续展示，候选标为待审；不直接“更新成功” |
| P0 视图日/周/月 | 日期定位、任务/日志事件、当天议程，打开详情 | 授权内容；§4 | 周一开始/上海时区；跨月跨年；日志独立日期筛选 |
| P0 我的日志列表 | 全历史，今天草稿，日期筛选、日报/周报/月报，写今天日志 | 本人；§4 | 无筛选默认全部，不默认只查今天；一天一份主日报 |
| P0 日志编辑/阅读 | 工作、关联任务、阻碍、明日计划、可选工时；草稿/提交 | 本人写，上级读正式版；§4 | 空必填/无效工时/重复日报/失败保留内容；不展示他人草稿 |
| P0 日志修订/历史 | 正式版、候选差异、原因、版本序列，申请修订 | 本人申请，独立复核人处理；§3 | 冲突保留输入；审核通过前正式正文不变 |
| P1 下属日志 | 成员/日期组合筛选、已提交记录、已读/评语 | 管理者范围内；§4/6 | 入口固定日志页；无权限与没有日志区别展示 |
| P2 周报/月报 | 聚合区间、源日报清单、带来源 AI 总结、可编辑草稿 | 授权范围；§4/7 | 缺失日期真实提示；无 AI 仍可看聚合，不能自动发布 |
| P0 任务列表/详情 | 标题、分组、期限、负责人/协作人、附件、活动时间线 | 被授权任务；§5 | 派发列表无完成/替代状态筛选；详情显示实际流转事件 |
| P0 派发 | 名称、分组、内容、截止、紧急、进度备注、单负责人、协作人、附件 | 有派发资格；§5 | 无效/离职负责人、无权限、重复提交；无完成字段 |
| P0 接收/成果/验收 | 接收动作、成果与阻碍、附件、验收结论 | 负责人/派发者；§5 | 操作权限/版本冲突；退回补充接口未核实，先设计占位 |
| P1 转派/延期/撤回 | 当前值→新值、原因、影响、复核链 | 授权管理者；§3/5 | 关键变更待审继续用旧值；撤回确认；通知基于真实结果 |
| P2 AI 首页/分析/风险/行动 | 范围、优先三件事、解释、来源、生成时间、关系图 | 本人/授权管理范围；§7 | 不把管理范围写成所有管理者均可查全公司 |
| P2 AI 建议/编辑/任务确认 | 内容、来源、候选负责人、编辑、人工确认 | 建议接收者及有派发资格者；§7 | 无来源不进入确认；无派发资格仅保存个人建议 |
| P2 AI 作业状态 | 生成、取消、失败重试、超时、限额/预算 | 同上；§7 | 不显示假实时进度百分比；失败保留范围与输入 |
| P1 我的/个人主页/编辑 | 真实头像姓名、组织、介绍、重点/动态/日志；修改头像介绍 | 本人；§4 | 组织角色只读；头像上传未接入不伪造保存成功 |
| P1 下属列表/详情工作台 | 搜索组织/成员，概览、资料、重点、日志、任务、AI摘要 | 授权管理者；§2/6 | 正在查看某某；不含私人备注、草稿、代操作 |
| P1 审批列表/详情 | 待处理/我发起，差异对比、申请原因、审核链，通过/驳回 | 独立复核人/申请人；§3 | 禁自审、驳回必填、缺独立复核人保持待审、冲突 |
| P1 消息中心 | 未读、类型、时间，标记已读、打开目标 | 本人；§6 | 已失去权限的目标安全拒绝；不生成假未读数 |
| P1 工作统计/明细 | 派发/逾期/按期验收/日报提交/待阅/部门分布，区间与口径 | 按角色范围；§6 | 零分母显示“暂无”，无权导出不显示动作；不按字数评分 |
| P1 组织/角色/审核策略/审计 | 组织树、成员归属、角色派发开关、复核人、前后值 | 管理员；§2/3 | 循环汇报关系、自授权、候选版本冲突；变更不是立即生效 |
| P1 设置/帮助/反馈 | 字体/通知等已支持项、会话退出；使用指南与反馈表单 | 本人；§4 | 不设计未支持的开关假状态；帮助反馈与成果反馈分开 |
| P0 系统状态 | 无权限/不存在/离线/冲突，返回/重试/重新读取 | 所有人 | 无权限不提供越权对象信息；不将 HTTP 错误退化成 Mock 成功 |

## 5. 五个主页面详细布局

### 5.1 导图：轻工作桌面，而非菜单大厅

顶部不展示页面名称，仅保留消息入口（真实未读数）。下一行 72～88dp 欢迎条：姓名与业务日期、小人物在右，文案只一句，不写虚构效率评分。

主体固定 2×2：左上公司重点（蓝）、右上公司任务（橙）、左下个人重点（紫）、右下个人日志（薄荷）。每格：小图标/标题 → 2 条短预览 → 查看全部。360dp 可每格 1～2 条；390dp 2～3 条；标题两行容错。公司任务用“标题 + 期限”，无完成率/状态勾选。个人日志突出“今天草稿”或真实最近业务日期，不捏造一条“已提交”。有派发资格才有独立浮动加号，底部内容加足够 padding，不挡查看全部。

四象限下可有一行“打开今天的时间视图”导航，不增加第五张概览卡。个人重点详情提供私人备注入口，公司正文与本人备注明确分开。

### 5.2 视图：日历为主体，议程为阅读补充

所有页面共享 PageFrame 删除顶部重复页名；无返回及操作时不占用工具栏，有操作或返回时保留内容内的 48dp 操作行，随页面滚动，不固定在顶部。正文业务标题保留。此规则覆盖下文旧版“页头名称”表述。

视图保留今天、周期前后箭头、日期选择、日/周/月分段及任务/日志文字筛选。2026-10-13 用户新参考图取代原日周时轴布局。

日：顶部七日日期带，下方完整纵向记录列表。任务和日志均出现，真实时段/截止时刻、标题、负责人或摘要；点击进入现有详情，按权限提供编辑草稿、修订或任务操作。不添加完成情况。

周：周一至周日纵向七日紧凑概览，无内部横向或纵向滚动。每行日期、最多两条固定宽度彩色胶囊、数量；点击日期打开当天完整记录弹层。七日纵向排列，记录使用 156dp 固定宽度胶囊；窄屏仅在可用宽度不足时收缩，点击日期查看完整内容。

月：周一开始七列网格，每格至多两条彩色简写（任·标题/志·标题），超过显示 +N。颜色采用主题集中浅色 tokens，稳定按记录分配，文字辅助区分。选日底色、今天描边；跨月填充留空，避免展示未查询数据。点击格打开当天完整列表，列表每行可进入对应详情。月历下仍显示选日议程。

日/周/月共用 selectedDate 和既有 Repository 范围/分页，日期切换、详情返回和权限继承。当天弹层在账户失权或切换时隐藏旧记录。加载、空态、错误/403 和重试保留日期控件。没有时段不编造会议长度，无新增 API、数据库或依赖。

验收与任务见 openspec/changes/flutter-calendar-agenda，运行证据见 mobile/docs/calendar-agenda-verification.md。设备与真实服务验收未据此完成。
### 5.3 日志：收件箱 + 写作纸张

页头日志 + 管理者专属“下属日志”文字入口。日报/周报/月报分段；日期筛选默认 `全部日期`，可清除；本人今日草稿作为一条暖色写作条，显示保存时间与“继续写”。下方按月份分组的行式记录：业务日期大数字/星期在左，标题和两行摘要在中，草稿/已提交/待修订是日志自身状态。无需每条彩色大卡或点赞社交流。

底部单一 `写今天日志`；若选定日期则 `写10月12日日志`。已有日报打开既有草稿/正式详情，不创建第二份。列表默认历史，不会被视图切换日期改变。

阅读页：`10月12日工作日志` → 作者/业务日/正式版本/提交时间 → 今日工作正文 → 关联任务行 → 阻碍 → 明日计划 → 工时（有值才显示） → 已读与评语。每节暖白连续文档，以细分隔/留白而非四层卡片分组。底部本人显示申请修订，管理者显示评语；历史入口在页头。评论按时间排列，非聊天气泡。

编辑页：日期/草稿保存提示 → 今日工作多行输入（优先占空间） → 关联任务选择 → 阻碍 → 明日计划 → 可选工时 → 附件（后端支持前明确不可上传）。顶部返回、底部 `保存草稿` 次按钮 + `提交日志` 主按钮；键盘打开时仍可滚到提交，字段标签常驻。失败面板紧邻操作，文本保持。可用正文不是自动生成评价。

关联任务落实（2.24）：多个可移除浅蓝胶囊，添加打开授权搜索多选弹层，确认才写入；全部现有taskIds贯穿读取/加密草稿/修订，旧单值兼容，无法查看仍保留关联。阅读/历史按项显示有权访问的任务入口；不以搜索或分页失败删除关系。键盘打开时内容可滚动，确认/取消在键盘上方。

下属日志：标题下成员选择器 + 日期筛选，显示授权范围；未选成员可列范围内记录，选后仍保留列表与日期，点成员名字进入该成员工作台日志分类。无草稿、无代提交。评语单独输入并显示真实发送结果。

周/月报告：区间 → 已收集日报数量与缺失日期 → 按工作/成果/阻碍/计划聚合 → 来源清单 → `生成总结草稿`；总结编辑与发布/保存按已存在契约落地，未有契约仅演示。

### 5.4 AI 地图：先给下一步，再解释关系

| 方案 | 员工首屏收益 | 手机成本 | 判断 |
|---|---|---|---|
| 关系图默认 | 看目标依赖关系 | 节点拥挤，需要缩放且难阅读 | 作为第二入口，保留完整能力 |
| 聊天默认 | 自由提问 | 要先组织问题，不便扫读来源，增加未确认功能 | 不选，不新增聊天协议 |
| 优先三件事默认 | 立即看到可处理事项 | 长分析需要进入详情 | 本轮推荐并用于原型，待视觉评审 |

页头 AI地图 + `建议草稿`；授权范围胶囊 `个人发展` / `公司走向`（公司标签仅拥有公司范围者；团队/部门角色显示相应实际范围）。生成时间与输入区间在正文前可见。简短解释条 + 小人物；其下 `优先三件事`、编号 1/2/3 行，每件含建议、为什么、来源数。数据不足时只显示实际数量，题头改为“建议先处理”。

发展分析/堵点风险/行动规划作为内容分段，不是再套三张入口卡；风险同时区分规则识别的真实逾期与 AI 推测，并写不确定性。关系图入口打开独立页：目标居中，上游来源、下游行动，图例和节点搜索，支持缩放/点节点详情，并提供同内容的列表替代；不用人物当图节点。

建议详情：建议 → 依据/不确定性 → 来源任务/日志链接 → 生成时间与范围 → 编辑建议/加入个人行动；有派发权限且来源有效才显示“确认创建任务”。确认页预填可编辑内容与范围内候选人员，清楚显示人工确认。无来源建议仅作为未证实提示，任务确认不可用。

生成中显示实际阶段文字和取消，无虚假 80% 进度；取消后保留原结果/输入。超时、限额、预算、服务未配置分开显示，不把固定样例标成实时结果。

2026-10-13 正式契约说明：已有API只支持date/period，scope由服务端身份决定，没有个人/公司切换参数；正式主页据实显示授权范围，日期周期通过紧凑入口修改，不将无效切换冒充过滤。确认任务接口无version前提，客户端重读只能缩小竞态，不能证明原子版本保护。原产品所需精细范围过滤仍保留为后续后端契约任务，非从产品范围删除。正式首页/建议/草稿/确认/地图/用量六屏已有HTTP/UI及实际渲染证据。

### 5.5 我的：个人身份 + 分组工作入口

顶部真实头像、姓名、部门/团队、介绍，右侧编辑资料；非本人工作台不复用“我的”标题。工作摘要一行两个指标（真实未读/待审，无权限不显示）；其下三组列表：工作（消息、统计、审批）、管理（下属工作台、组织/权限/策略/审计，按授权）、通用（设置、帮助）。不把每项做成同尺寸的大图标宫格。

个人主页是资料 → 个人公开重点 → 日期动态/日志时间线；按根产品方案 §6，编辑只允许头像/介绍，姓名及组织/角色为只读（2026-10-13 契约核对纠正）；头像上传未接入时保留当前头像引用。退出在设置下方，二次确认清空受保护栈，保留按账号隔离的草稿策略。

## 6. 二级页面布局契约

### 6.1 任务

列表：搜索/分组/负责人/期限/紧急度 → 行式记录；名称 2 行、负责人、期限、紧急文字；**派发列表及派发表单无完成情况、百分比进度、状态滤镜或完成勾选**。进度备注仅普通文字字段，不升级成状态控件。

详情：名称/分组/紧急 → 负责人/协作人/真实截止 → 内容/附件 → 流转时间线（派发、接收、反馈、验收、归档） → 当前权限下主操作。负责人未接收时为接收，接收后为提交成果，派发者待验收时为验收；不会同时显示一排不适用动作。转派/延期/撤回进更多菜单，各进入独立表单。只读观众无业务提交按钮。

派发纵向表单分三组：任务内容（名称/分组/正文）→ 安排（截止/紧急/进度备注）→ 成员与附件（一名主负责人/可选协作人/附件）。常驻标签，必填明确；底部派发主按钮，提交禁重。人员选择器独立页：范围提示、姓名/部门搜索、结果行、当前单选、确认。无效结果不能保存；附件未接入不制造成功。

成果反馈用“成果 → 阻碍 → 附件”；验收页上半阅读成果，下半结论/说明。退回补充与附件真实接口未核实，保持实施待办。转派/延期明确旧值、新值、原因及可能审核；撤回展示影响对象和原因，危险确认不使用普通橙色成功提示。

### 6.2 审批、修订与候选版本

列表待处理/我发起分段，行内申请类型、对象、申请人、提交时间与当前审核步骤。本人申请可看进展，不能出现通过按钮。详情先申请摘要/原因，其次逐字段旧值→新值对比（手机纵向叠放，新增/删除带文字），再审核链（人/节点/结果/时间/原因）。底部通过主操作与驳回次操作，驳回必填原因。旧有效版标“当前生效”，候选标“待审核”；按钮不能暗示已生效。

无独立复核人写“等待配置独立复核人”，不自动通过。版本冲突说明需重新读取，保留本地改动，不自动覆盖。日志历史按版本倒序可打开只读正文与变更理由，比较以业务日期相同为前提。

规划补齐 `/me/reviews`、`/me/reviews/:id` 语义路由；原有通用资源页可暂承载，实现阶段统一，不能写成已可导航。

### 6.3 成员工作台

成员列表使用组织筛选/搜索 + 真人头像/姓名/部门/团队行；不显示私人备注或草稿计数。顶部上下级范围而非任意全公司树。详情固定“正在查看：陈一诺”上下文条与返回本人，下面头像/组织，再横向分类概览、资料、重点、日志、任务、AI摘要。默认概览只读，分类可滚动但主列表竖向滚动；从日志进入时直接落日志并携带业务日期。

概览只展示授权摘要；日志沿用文档/评语；任务沿用任务详情操作权限；AI摘要用来源和范围提示。即使按钮隐藏，直接访问也须服务端鉴权。失去范围时清空该成员缓存并退出详情，不泄漏名字或内容。

### 6.4 通知、统计与管理

消息：全部/未读 + 类型筛选，今天/更早分组，未读文字/圆点双提示；点击打开真实目标，目标删除给安全不存在页。全部已读是文本按钮，需真实响应后刷新。

统计：区间/范围 → 指标值（同屏不超过 4 个）→ 趋势/部门分布 → 可点击明细；每个率注明分母/口径，页脚更新时间。无数据不画虚构曲线；零分母“暂无”；明细与导出同权限。原创图表不采用竞品营销截图。

组织：公司/部门/团队面包屑 + 可展开层级列表；新增部门/团队、成员归属、直属上级分别单列表单。角色：成员选择 + 当前授权 + 候选修改 + 理由。审核策略：策略范围 → 路由顺序 → 独立复核人 → 预览链。审计：时间/操作者/类型筛选 → 事件行 → 前后值和追踪信息只读详情。重要配置提交候选，显示生效规则，不当立即保存。

### 6.5 认证、重点、设置与系统状态

登录以品牌标题、一个小人物、账号/密码、登录、注册入口为核心，无工作数据。注册部门是加载的选择列表；错误就在字段下，密码可显隐。待确认只显示申请状态和退出/刷新，账号停用说明重新登录/联系管理员途径，不添加未定义客服电话。

重点详情用标题→正文→本人私人备注；本人重点编辑标题/正文/置顶顺序，归档在更多菜单。公司发布单独入口，受众/理由与审批显式呈现；首页公司块仍只读。

设置分组行与明确的当前值；仅已有能力做开关。帮助是搜索指南/常见问题，意见反馈表单不复用任务成果字段；缺后端明确提示未接入。无权限显示拒绝与安全返回；不存在显示目标不可用；错误保留已知上下文；离线草稿说明只在本机保存；冲突给返回编辑/重新读取两条路，重新读取前说明对未提交输入的影响。

## 7. 状态、适配与验收标准

| 状态 | 列表/日历 | 阅读/表单 |
|---|---|---|
| loading | 保留标题筛选，行/网格骨架 | 保留标题，文档骨架；已输入表单不清空 |
| empty | 实际区间/范围 + 原因 + 可用下一步 | 无权不当空数据；不存在提供安全返回 |
| error/offline | 内联原因、重试，禁止样例回退 | 保留输入、可保存本机草稿，禁止假提交成功 |
| forbidden/unauthorized | 清掉受保护内容，不残留截图式占位 | 安全返回/登录，登录后校验目标权限 |
| saving/saved | 局部刷新不跳列表顶部 | 禁止重复提交，真实响应后回详情；保存草稿≠提交 |
| conflict/pending | 明确当前生效/候选待审 | 保留输入、对比与重新读取；不覆盖最新版 |
