## 1. 目标与边界

本项目要复现的是 UI Notes 中“团团记账”这类成熟卡通生产力 App 的视觉气质：温暖、轻快、精致、有角色陪伴和丰富状态反馈，同时保持企业协作产品需要的信息层级、权限边界和可读性。

这里复现的是设计方法和视觉语言，不复制竞品截图、角色、Logo、文案、图标或专属插画。业务导航、接口、权限、日志、任务、审批和 AI 安全规则继续以 `方案.md`、`AGENTS.md`、接口契约和现有 OpenSpec 为准。

本基线覆盖：

- 颜色、表面、圆角、描边、阴影、间距、字体和动效 token；
- 原创 Q 版角色、业务图标、状态插画、背景纹理和素材许可；
- 首页、公司、日志、AI 地图、我的五个主入口及其主要状态；
- 日视图、周视图、月视图、卡片、弹窗、底部弹层、Toast 和图表；
- 360dp、390dp、412dp、字体放大、TalkBack 和减少动态效果验收。

不在本基线中新增后端接口、数据库字段、权限模型或 AI 能力。没有后端契约的内容必须标为未接入，不能用静态图片或本地样例假装完成。

## 2. 参考经验与取舍

前期研究团团记账公开展示页面后，提取出以下可迁移经验：

| 观察到的模式 | 本项目采用方式 | 边界 |
| --- | --- | --- |
| 奶油底与明黄构成品牌，语义色小面积区分状态 | 用语义色区分日志、任务、AI、审批和提示 | 不能用颜色替代权限、审核结果或状态文字 |
| 圆角卡片、彩色边框、轻阴影和纸张质感 | 统一 Material 3 主题和 `ThemeExtension` | 正文和长表单不铺满纹理或强渐变 |
| 功能入口使用彩色插画图标 | 业务图标放入统一图标托盘，保持功能识别 | 不把角色头像当任务、日志或审批图标 |
| 角色用于欢迎、引导、空状态、成功和营销反馈 | 使用与 App 图标呼应的原创鸭系形象 | 错误、待审、无权限优先显示业务信息，角色不庆祝 |
| AI 页面有气泡、快捷入口和确认卡片 | AI 地图使用建议、来源、确认和失败状态分层 | AI 只能由服务端调用，客户端不保存 API Key |
| 统计页面使用大数字卡、折线图和环形图 | 图表卡片由 Flutter 根据真实接口数据绘制 | 不使用生成图片代替真实图表 |
| 组件有明确的加载、空、错误和成功反馈 | 状态面板、Toast、底部弹层统一设计 | 不用静态成功画面掩盖请求失败 |

## 3. 视觉性格

关键词：**奶油白、明黄色、软边框、圆润卡片、轻量插画、清晰业务层级**。

页面的整体观感应像一个有陪伴感的工作台，而不是游戏首页或营销海报：

- 背景大面积使用奶油白和纸张纹理；
- 明黄承担品牌氛围、主操作和选中状态；
- 浅黄、浅蓝、珊瑚粉和少量橙色承担内容分区；
- 深棕灰文字保持清晰，不使用纯黑大面积压迫画面；
- 每个页面最多一个主要角色插画；
- 每屏保留一个明确的主操作，次操作降级为描边按钮、浅色按钮或文字按钮；
- 列表、审批和日志正文保持密度，插画不挤压核心业务内容。

## 4. 设计 Token

### 4.1 颜色

| Token | 色值 | 用途 |
| --- | --- | --- |
| `canvas` | `#FFFDF5` | 页面奶油背景 |
| `surface` | `#FFFEFA` | 卡片、输入框、弹层 |
| `yellow` | `#FFDA35` | 主按钮、选中托盘；配深色文字 |
| `butter` | `#FFF0AC` | 柔和品牌分区 |
| `ink` | `#3D352B` | 标题、正文、按钮标签 |
| `muted` | `#796F61` | 日期和辅助信息 |
| `accentInk` | `#775B10` | 可读的小字强调、图标、链接；Material primary |
| `outline` | `#CABB96` | 输入边界与未选标记 |
| `line` | `#EEE4CD` | 卡片与分隔线 |
| `success` | `#39734E` | 仅真实完成与成功语义 |
| `error` | `#B3433E` | 失败、危险与错误 |

奶油/白色承载主要内容，黄色集中在操作、选中和图标。禁止浅底黄色小字；Material primary 使用深琥珀色，主按钮单独使用明黄 fill + 深色 foreground。任务用户自定义标签和状态语义颜色不被品牌色覆盖。共享值维护于 `lib/theme/sunshine_palette.dart`。

### 4.2 形状、描边和阴影

| 对象 | 规则 |
| --- | --- |
| 普通卡片 | 16～20dp 圆角，1dp `outlineSoft`，轻阴影或无阴影 |
| 重点卡片/角色卡 | 20～24dp 圆角，浅色分区底，最多 2dp 下沿 |
| 主按钮 | 16～18dp 圆角，最小高 52dp，使用明黄底和深色文字 |
| 次按钮 | 16～18dp 圆角，最小高 52dp，暖白底和必要边界 |
| 输入框 | 14～16dp 圆角，最小高 56dp，错误状态使用 `error` 边界 |
| Chip/分段控件 | 胶囊形，视觉高度 28～36dp，交互区域至少 48dp |
| 图标托盘 | 12～16dp 圆角，容器 40～48dp，图标 24dp |
| 底部弹层 | 顶部 24～28dp 圆角，保留拖拽提示和关闭路径 |
| Toast | 14～16dp 圆角，图标与文字并列，保持短时可读 |

阴影只表现层次，不承担关键边界：普通卡片可用 `offset(0, 3) / blur 10 / 6%` 深橄榄阴影；弹层可用 `offset(0, 6) / blur 18 / 10%`。避免多层重阴影、发光和玻璃拟态。

### 4.3 间距和文字

- 间距 token：4、8、12、16、20、24、32dp；页面左右内边距默认 16dp；卡片间距 12dp；区块间距 24dp。
- 页面标题 24sp/700；区块标题 18sp/600；卡片标题 16sp/600；正文 15～16sp/400；辅助文字 13～14sp/400；按钮 16sp/600。
- 中文使用系统无衬线字体。角色和插画承担卡通感，正文不使用过度装饰字体。
- 长标题允许换行，卡片高度随内容增长；不通过缩小字体或固定高度截断文字。

## 5. 原创角色和插画

### 5.1 主角色方向

当前使用以项目 App 图标为参考生成的原创鸭系陪伴角色：welcome、journal、empty、assistant。角色用于问候、空列表和少量引导，不冒充员工头像，普通分区标题不重复堆叠角色；月历按用户要求在星期文字左侧使用14dp同行图标；错误、权限、保存等状态优先使用明确功能符号及文字。旧小猪/柴犬素材仅保留作历史回退。

主导航与业务卡片采用可辨识的功能图标，普通页面标题以文字为主。月历星期栏使用同行小图标，今天日期格不重复放角色，日期、节名及休/班标记优先；背景保持干净奶油色。状态反馈用明确图标、文字、边框或进度组件表达。角色不能冒充员工头像、审核人或当前用户。

以下是历史角色状态资产用途，不适用于柴犬：

- `welcome`：友好招手或趴在工作垫上；
- `empty`：等待用户创建第一条内容；
- `writing`：书写日志或整理任务；
- `explaining`：指向 AI 来源卡或说明；
- `success`：真实保存或提交成功后出现；
- `retry`：网络失败、超时或离线时整理笔记并提示重试。

失败、待审、无权限和冲突状态必须由准确文字、图标和操作完整表达，不能依赖角色传达状态。

### 5.2 业务图标

任务、日志、日历、审批、AI、成员、通知、导图和报告使用统一的原创彩色业务图标。图标需要保持功能识别，不用人物头像替换。

表单行的字段名与图标在同高区域内垂直居中；多行正文、参与人和附件的额外高度属于值区域，不能把字段名贴到图标上沿。任务参与人使用主题背景胶囊；标签选择前即可预览服务端背景色，选择后保留该色与勾选，并确保文字对比。

消息中心保留消息类型标题，其下展示已有摘要或通过既有授权详情接口读取的任务/申请名称，同对象共享请求；加载中、已删除/无权查看及无摘要明确区分。详情缓存随会话和现有通知刷新机制更新，不用对象ID或虚构名称填充。具体内容最多两行，已读/未读及时间独立显示。

图标素材导入规则：

- 一图一文件，推荐 1024×1024 透明 PNG 或 SVG；
- 角色和图标居中，四周留均匀透明边距，主体占 70%～80%；
- 不生成文字、数字、Logo、界面截图和模拟透明棋盘；
- 透明素材与完整背景素材分开生成；
- 生成图标联系表只能用于确认风格，不能直接作为生产资源。

### 5.3 资产来源和授权

优先使用项目自有 SVG、Flutter CustomPainter 和 image-2.5 生成的原创图像。外部素材只从官网或 GitHub 获取并记录来源、版本、许可证、作者和修改方式；OpenMoji 必须保留 CC BY-SA 4.0 署名。

每个进入仓库的生成资产都要登记到 `mobile/assets/licenses/generated-ui-sources.json`，至少包含：文件路径、生成日期、模型、提示词文件、参考图、是否含第三方角色、透明检查、文字检查、版权角色检查和产品批准状态。

当前素材来源、许可及加工清单见 `assets/licenses/generated-ui-sources.json`；生成与裁切工具保留在 `mobile/tool/`。早期生成提示词已退出当前文档入口。

## 6. 页面设计规则

### 6.1 五栏导航

从左到右固定为：**首页、公司、日志、AI 地图、我的**；默认进入首页。底部导航使用清晰的功能图标、明黄选中托盘和未读语义，不能用角色头像替换导航图标。

### 6.2 导图

导图保留四象限业务结构，但采用成熟 App 的功能入口卡片：彩色图标托盘、入口标题、数量或最近更新时间、状态标签和轻量进入提示。页面上方可以放一个高度有限的角色欢迎区域，不得让大插画占据主要工作内容。

顶部操作区随页面滚动，不固定在视口中。页面不额外重复展示“导图”等页面名称。

### 6.3 视图

视图页顶部只保留日期、日/周/月切换和必要操作，不显示重复的页面标题。

日视图：

- 使用纵向列表或时间线展示日志、任务和审批记录；
- 每条记录使用语义色标识类型、时间和来源；
- 点击记录打开详情或编辑页；
- 空、错误、无权限和加载状态使用统一状态面板。

周视图：

- 保持纵向七日布局，一次展示完整星期；
- 日期按纵向排列，不采用横向滑动；
- 记录使用定宽胶囊，推荐 156dp 左右，不横向拉伸覆盖全屏；
- 同一天多条任务按现行月历排序完整显示，点击日期进入清单。

月视图：

- 使用圆角日期格和充分留白，不画密集直线表格边框；
- 每个单元格完整展示正式任务，周高随行数增长，不以`+N`折叠；
- 任务、日志、审批使用不同浅色和小图标；
- 点击日期或预览打开当日记录详情；
- 密集任务按可变周高和月份单一滚动完整可达，不裁切或嵌套日格纵滑。

### 6.4 日志

日志列表、编辑器和阅读页以内容为主，使用浅粉或奶油分区卡片表现情绪和状态。日志正文、业务日期、来源、关联任务、保存状态和评语必须可读。

日志编辑器保留输入内容，失败、冲突、离线和权限错误不能清空正文。提交成功后才显示成功角色或成功 Toast；保存草稿不等于正式提交。

### 6.5 AI 地图

AI 页面采用“建议卡 + 来源 + 人工确认”的结构：

1. 授权范围、日期周期和生成时间；
2. AI 建议摘要；
3. 优先事项列表；
4. 依据、来源任务/日志和不确定性；
5. 编辑、确认、取消和重试。

AI 气泡可以使用奶油黄色，角色只作为辅助解释。无来源、超时、限额、预算不足和服务未配置必须分别表达。客户端不能保存或输出 API Key，不能把预设样例标记为实时分析。

### 6.6 我的、成员、审批和统计

- 我的页采用资料区、工作摘要和分组列表，不把所有入口做成同尺寸图标宫格；
- 成员页优先显示真实头像、姓名、组织范围和授权摘要，不能用卡通角色冒充员工；
- 审批页用旧值→新值对比、审核链和明确原因，驳回必须填写原因；
- 统计页使用大数字卡、折线图、环形图和可点击明细，图表数据必须来自真实接口并注明口径和更新时间。

## 7. 组件和状态

### 7.1 公共组件

建议统一维护：

- `AppIconTile`：统一业务图标托盘；
- `AppMetricCard`：指标和趋势；
- `AppStatusPanel`：loading、empty、error、forbidden、offline；
- `AppMascotPanel`：角色、标题、说明和可选 CTA；
- `AppRecordCard`：日志、任务、审批记录；
- `AppSegmentedControl`：日/周/月或列表筛选；
- `AppConfirmSheet`：确认、审核和危险操作；
- `AppToast`：保存、失败、重试和权限提示。

### 7.1.1 组件实现边界

卡片、弹窗、底部弹层、Toast 和图表必须使用 Flutter 代码实现，不能把 image-2.5 生成的整张 UI 图片作为生产组件。这样才能承载真实文字、接口数据、权限状态、字体放大、TalkBack、点击行为和响应式布局。

image-2.5 只用于生成角色、业务插画、状态插画、业务图标、纸张纹理和装饰贴纸。组件视觉参考板可以用于确认颜色、比例和层级，但不能替代可交互的 Flutter 页面。

后续实现顺序固定为：

1. 先建立 Flutter 组件展示页，集中展示默认、按下、聚焦、禁用、加载、成功、错误和空状态；
2. 再迁移到首页、公司和日志等代表页面；
3. 使用 360dp、390dp、412dp 和字体 1.5 倍截图对照检查；
4. 最后再把组件迁移到任务、审批、成员、AI 和统计页面。

### 7.1.2 卡片 `AppRecordCard` / `AppMetricCard`

卡片采用“浅色页面背景 → 圆角业务卡片 → 彩色图标托盘 → 标题与辅助信息 → 数据/日期/状态 → 进入箭头或主操作”的层级。卡片必须体现业务差异，不能把任务、日志、审批和统计都画成同一种空白矩形。

普通业务卡片遵守：

- 奶油白或语义浅色表面；
- 16～20dp 圆角；
- 1～1.5dp 暖纸色边界；
- 16dp 内边距，卡片之间 12dp 间距；
- 44～48dp 彩色图标托盘，图标保持功能识别；
- 标题、负责人/来源、日期和状态分层排列；
- 右侧使用小箭头、数量或状态胶囊；
- 轻微偏移阴影，不使用厚重发光；
- 不让整张卡片全部使用同一种饱和色。

指标卡片可以使用大数字、单位、趋势线和短说明，但同屏指标不超过 4 个。空值、零分母和无权限必须使用明确状态文字，不能画虚构曲线。

卡片状态要求：

- 默认：表面、边界、标题和辅助信息清晰；
- 按下：轻微缩放或下移，100～160ms；
- 聚焦：提供可见焦点圈，不依赖阴影；
- 禁用：降低对比度并解释原因，不能只降低透明度；
- 加载：保留卡片结构，用骨架或局部加载，不显示假数据；
- 错误：在卡片内显示原因和重试入口，保留已知上下文；
- 非交互卡：不显示点击箭头和按压动画。

### 7.1.3 弹窗 `AppConfirmDialog`

弹窗用于确认提交、删除、驳回、退出、版本冲突和需要明确同意的操作。它必须突出“操作对象、影响范围、风险和下一步”，不能只显示一句模糊的确认文案。

样式规则：

- 页面上覆盖半透明遮罩；
- 使用白色或奶油色主体表面；
- 20～24dp 圆角；
- 16～20dp 内边距；
- 标题、说明、影响范围和操作区分组；
- 主按钮使用明黄底和深色文字；
- 取消按钮使用浅色描边或文字按钮；
- 错误和危险操作使用珊瑚色，不使用普通橙色伪装为成功操作；
- 文本较长时允许弹窗增高或转为底部弹层，不固定截断；
- 不在弹窗中放大角色插画，角色只能作为很小的辅助反馈。

交互规则：

- 默认焦点落在安全或取消操作，危险操作不能默认选中；
- 提交中禁用重复点击并显示真实处理状态；
- 失败时保留弹窗和用户输入，提供重试或返回编辑；
- 点击遮罩关闭前，必须根据操作风险决定是否需要二次确认；
- TalkBack 能读出标题、影响范围、按钮语义和当前焦点。

### 7.1.4 底部弹层 `AppBottomSheet`

底部弹层用于日期选择、成员选择、审批确认、任务操作和筛选条件，不用于承载整个页面的主要内容。

样式规则：

- 顶部 24～28dp 圆角；
- 顶部显示短拖拽提示，但拖拽不是唯一关闭方式；
- 使用白色或奶油色表面；
- 内容按标题、说明、选项列表和操作区分组；
- 选中项使用奶油黄背景、深棕灰图标和非颜色选中标记；
- 列表行最小高 56～64dp，触控区域至少 48dp；
- 底部保留 SafeArea；
- 操作按钮位于内容之后，不遮挡列表；
- 内容超出屏幕时允许内部滚动，页面背景不跟随错位。

日期和成员选择必须显示当前范围、已选值、清除路径和确认动作。审批和危险任务操作必须显示对象、影响范围和原因输入，不用一行彩色按钮替代说明。

### 7.1.5 Toast `AppToast`

Toast 用于短时反馈，不用于承载必须持续阅读的错误或审批信息。需要用户处理的错误必须同时在页面内保留状态和重试入口。

样式规则：

- 小型胶囊容器，14～16dp 圆角；
- 左侧使用状态图标，文字保持一到两行；
- 薄荷表示真实保存成功；
- 浅黄表示提醒或待处理；
- 珊瑚表示失败或危险；
- 表面使用高对比度文字，不能只靠颜色表达状态；
- 轻微上移和淡入淡出，160～220ms；
- 不使用大面积插画、复杂渐变或持续漂浮动画；
- 默认不阻塞页面操作，不覆盖底部导航和键盘；
- 允许用户在 TalkBack 中读取完整文字。

Toast 文案必须对应真实结果：请求失败不能显示成功，保存草稿不能显示正式提交成功，离线本机保存不能显示服务器已同步。失败 Toast 应提供重试或进入详情的可达路径。

### 7.1.6 图表 `AppChartCard`

图表使用 Flutter 图表组件或自有绘制代码，根据真实接口数据渲染。image-2.5 生成的图表只能作为视觉参考板。

- 折线图使用深琥珀主线，节点和趋势说明保持清楚；
- 环形图使用金黄、珊瑚、暖灰和浅蓝，扇区数量控制在可读范围；
- 柱状图使用圆角柱体，避免过度立体和强渐变；
- 每个图表都有标题、统计口径、更新时间和明细入口；
- 无数据不画虚构曲线，零分母显示“暂无”；
- 图表必须提供摘要文本或列表替代，支持 TalkBack；
- 导出和明细使用同一服务端权限范围。

### 7.2 状态要求

| 状态 | 必须表现 |
| --- | --- |
| loading | 保留上下文骨架，不显示虚假数据 |
| empty | 说明范围和下一步，角色可选 |
| error | 内联原因、重试路径和已输入内容 |
| forbidden | 明确无权限，不能伪装成空数据 |
| unauthorized | 安全返回登录，不能泄露业务内容 |
| saving | 禁止重复提交，显示局部处理中 |
| saved | 只有真实响应成功后显示 |
| conflict | 保留本地输入，提供重新读取和继续编辑 |
| offline | 说明本机草稿或离线限制，不伪造服务端成功 |

## 8. 动效规则

AI办事结果标题使用真实业务语义：处理结束不一律显示“已办妥”。检查结果分别为“材料已核对”“需要补充材料”“有些内容需核对”“需要重新检查”；任务创建显示“任务已创建”，反馈显示“已提交反馈”并保留“等待验收”正文。复用当前纸卡和字体，不新增开发说明或视觉样式。

动画服务于反馈和层级，不把业务页面做成游戏：

- 卡片按压：轻微缩放或下移，100～160ms；
- 页面切换：淡入或轻微位移，160～220ms；
- 状态切换：使用 `AnimatedSwitcher`；
- AI 处理中：星点轻微旋转或淡入淡出，角色本身保持稳定；
- 提交成功：短暂勾选和 Toast，不能循环播放；
- 视图切换：日期内容淡入，不能阻塞点击。

必须提供 reduced-motion 分支：关闭持续漂浮、旋转和大幅位移，只保留颜色、透明度和结构变化。动效不能掩盖错误、权限和保存状态。

## 9. 可访问性和响应式验收

- 所有可操作区域至少 48dp；
- 颜色状态同时有文字、图标或形状提示；
- TalkBack 能读出日期、记录类型、事件数量、选中状态和按钮动作；
- 360dp、390dp、412dp 宽度下不横向溢出；
- 字体 1.3 倍和 1.5 倍时，标题、按钮和卡片允许换行；
- 周视图保持纵向七日结构，月视图不因记录预览挤压相邻单元格；
- 关闭角色和装饰后，页面仍能完整理解；
- 图表提供摘要文本或明细入口；
- 不把插画中的文字当作业务信息。
