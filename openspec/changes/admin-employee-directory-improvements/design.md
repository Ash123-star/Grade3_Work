# 设计

沿用 `users.team_id`、`reporting_relations`；身份证号由 `V35__employee_identity_card.sql` 新增 nullable 列及唯一索引，性别沿用 `users.gender`。主线已包含 V35，手机端复用该列及唯一索引，不新增迁移。管理员创建用例在同一事务内校验部门、组和同部门团队长及以上上级后写用户、角色、汇报关系和审计。目录 SQL 在公司范围内关联团队与上级，并对部门筛选在服务端验证；身份证号仅返回存在标记。Web 管理员修改复用既有领域验证与最终应用器，在事务中直接应用并审计；待确认账号启用时旧待审成员申请标记为已处理。历史成员申请若目标版本失效则详情提示当前版本并引导管理员直接确认。公司事项页面隐藏内部排序、展示设置和版本字段，提交时保留原值和内部版本。

备选方案是新增单独的管理表或客户端筛选；会复制既有组织数据或使分页统计错误，因此不采用。另一个方案是移除整个系统审核，会影响手机端和普通员工权限；按用户确认，仅 Web 管理员的操作走直接生效，其他入口继续使用现有审核。

2026-11-18 补充：年龄不新增持久化字段。Web 目录内部读取身份证号，服务端按中国时区当天和证件出生日期计算周岁，在响应前移除完整号码；无证件时返回 null，不回退历史 `users.age`。编辑表单随新输入的证件号即时计算年龄，保存时不传年龄，手机端年龄同样只读，员工可在本人资料录入证件；不根据姓名猜性别或生成真实身份号码。

“申请与审核”改为当前待办而非历史列表：复用原审核可见范围，只返回 PENDING；成员确认还要求目标账号仍为 PENDING 且员工版本等于申请目标版本。已决和失效旧申请保留在数据库供审计，Web 管理员直接修改继续写“修改记录”而不产生申请。备选方案是删除 `review_requests` 历史，会破坏任务审核与追溯，因此不采用。

2026-11-20 修订：取代上述员工自助录入设计，证件号仅由管理员维护。本人资料只读脱敏号和派生年龄；服务端拒绝员工写入证件号或年龄，普通资料更新不触碰证件列。

## 2026-11-21 输入与目录改进
姓名按Unicode码点2–50计数，支持汉字（含扩展区）、字母和组合标记以及内部空格、·、连字符、撇号，禁止连续分隔符及控制字符。仅Web管理用例调用新输入策略，避免未审批修改手机端注册契约。手机号使用可维护的公众移动号段清单。身份证地址使用带来源、版本及许可的现行/历史县区级代码集合；保留既有1900年日期下限及标准校验位，新增所选性别与顺序码奇偶一致性。
比较外部实名接口与本地字典：本批选本地字典，避免费用、凭据和外部服务依赖；不能证明号码实际签发或姓名归属。字典资源随代码发布，不改数据库结构。
先预检查账号、手机号、证件号全局唯一性并一次返回字段错误；数据库唯一约束兜底，利用驱动的约束名将并发冲突映射为相同业务错误，不在SQL失败事务里继续查询。编辑证件号排除自身。错误响应可选fieldErrors，不输出冲突对象或证件原文。
列表保留员工/账号、部门/组、角色、直属上级、状态、操作六列；详情使用已授权目录返回的脱敏数据，沿用同一公司范围，无额外公开个人资料接口。窄屏以CSS卡片呈现，列内容可换行。

用户批准五点后补充：业务职位使用独立 users.business_position（NONE/GENERAL_MANAGER/DEPUTY_GENERAL_MANAGER），通过新增V36迁移实现；保持五种权限角色。相比新建总经理/副总权限角色，该方案不将业务任职与系统权限混用。仅Web管理员可以修改任职，携带现有用户版本/原因，在同一事务内写用户、职位、审计。部门经理及公司级任职人员可跨部门选择在职创始人、总经理、分管副总，普通人员仍在同部门选择业务管理人员；未任职管理员不因ADMIN身份自动获得上级资格。沿用reporting_relations，因此手机端原有manager_id和审核关系读取同一结果，不新增第二套关系。
