# Design

## Context

已有 Vue/Vite 工程以 AI 和审计为主；注册接口只能创建待确认员工。现有组织修改及 COMPANY_ITEM 均采用候选审核。用户已明确直接创建员工并选择本地运行加云端说明。

## Goals / Non-Goals

仅 ADMIN 员工账号与公司重点简易后台；不开发日志、任务、报表、AI 和独立注册 UI。不修改 Android。

## Decisions

- 比较 Flutter Web、重建前端与复用 Vue：选择复用 Vue，依赖最少、适合表单和桌面目录。
- 比较直接复用公开注册再审批与独立管理员创建：选择后者，事务插入 ACTIVE/EMPLOYEE、user_roles 和脱敏审计，强制首次改密；不允许客户端指定角色或公司。密码沿用 BCrypt 和12字符/72字节限制。
- 比较改安全代理白名单与独立管理控制器：选择 `/api/admin/console`，现有过滤器认证，应用服务逐请求重读用户并校验 ACTIVE、ADMIN、已改密，避免修改共享 Security/OpenApi。
- 已有人事和公司重点修改仍走现有审核，不扩大管理员免审权限。后台提供本人申请/分配审核列表和详情，调用既有审核契约；无审核人维持待审，提示补齐直属关系。
- 账号由唯一 account/phone 约束去重；重复返回409，不自动重试 POST；失败保留表单，成功清空临时密码。服务端返回不含密码和哈希，列表包含停用人员。创建无幂等键，重复同账号409且无重复人员。
- 员工信息本批覆盖姓名、手机号（创建时）和部门；已存在手机号只读，避免引入额外资料审核语义。停用复用 USER 候选与会话撤销机制。
- 公司事项复用 COMPANY_ITEM 审核应用器、版本校验和公司锁的十项置顶约束。列表含已撤下，支持重新提交恢复；正文纯文本转义。
- 前端采用 sessionStorage 会话，鉴权错误清除受限内容；切换账号/登出废弃旧请求。宽屏侧栏和窄屏自适应，原生表单标签/键盘可操作。
- 本地 Vite `/api` 代理，生产 Nginx 静态文件和同源 API 反代，服务器地址不写死在前端。

## Risks / Trade-offs

直接创建为 ACTIVE 是管理员录入的明确例外，不改变公开注册。没有有效独立审核人时员工关键修改与事项维护仍待审，不允许自审。
无需新增表或字段，因此无新迁移；回滚前端入口和新增管理代码即可，已创建员工及审计需保留，不删库。
旧 AI 验证脚本针对旧入口，仍保留但本次后台使用独立验收用例。混合未跟踪用户文件不得提交，推送依仓库规则停下记录。

## Validation

批次实现完成后统一执行后端脚本、Web 类型检查/构建、Playwright后台用例和严格规格校验。真实 HTTP/PostgreSQL 覆盖创建、改密、重复/角色注入、员工修改审核、事项审核和公司隔离。单元测试覆盖输入与权限。非功能验证安全隔离及事务原子性；浏览器覆盖空/错误、键盘、窄屏。

## Open Questions

无阻塞产品问题；Issue 编号、运行环境和实际云端上线不伪造，分别记录。
