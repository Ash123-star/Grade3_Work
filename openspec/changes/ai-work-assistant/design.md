## Context

本设计对应用户选定的三项能力：聊天/截图转任务、提交前检查、公司办事助手。用户要求统一放在 AI 地图、尽量自动办事，沿用当前应用的视觉风格，文案自然克制，并在适当位置加入流畅动效。用户已批准实施，现已新增运行代码与V14/V15迁移；实际验收结果和未完成范围以validation.md和tasks.md为准，正式自动写入保持关闭。

实施分支为 `codex/ai-work-assistant`，保留前一批AI布局及lockfile混合改动，未自动提交或推送。下表保留提案时的基础核查，用于解释本次技术决策；不把当时缺口当成当前实现状态。

| 领域 | 已观察到的基础 | 本次需要补齐 |
| --- | --- | --- |
| Flutter | `/ai` 主导航、三分析 Tab、底部按钮；团团 `SunnyPaperTokens`、`PaperSurface`、本地素材和字体；受保护路由 | 办事列表、输入区、详情、追问、执行授权、检查卡与状态恢复 |

`方案.md` 与 `collaboration-backend` 当前要求建议人工确认；`ai-map-direction-ui` 要求保留分析入口。新需求改变主入口和授权执行方式，本变更提供对应 delta；旧分析输出仍不自动执行。`tuantuan-ui-migration` 的三个 Tab 和底部“开始分析”属于现阶段布局，新工作台上线后在 AI 首页范围内替代它，其余团团样式要求继续遵循。不得把同一页面同时按两套规格验收。

## Goals / Non-Goals

**Goals:**

- 让用户从一句话/截图开始，自动完成信息提取、受权检索、准备和可授权的内部办理，并能在同一事项中追加材料和继续处理。
- 减少表单填写、重复找资料和人工初检；只问真正缺少或存在歧义的信息，保留原始依据。
- 任何执行均可归因到用户指令/有效授权、具体计划版本、当前权限及业务结果；出现重试、取消、重启或并发时结果真实一致。
- Android 提供完整体验；服务端和 Web 使用相同契约与规则，Web 新工作台 P1 单独验收。
- 把体验与可靠性一起验收：有恢复路径、可读的中文、真实状态、合适动效、键盘和无障碍适配。

**Non-Goals:**

- 不接管任意软件或外部网站，不监控工作群、不自动读取相册/剪贴板、不替用户发外部消息。
- 不增加员工派发权限，不让管理员查看他人办事原始私有材料，不让 AI 审批或宣布交付已经被业务验收。
- 不把长期记忆、自述、模型常识或用户截图升级成公司制度；不以 AI 评分衡量员工。
- 不在首期引入自动日报、发展预测、复杂图谱、向量服务或通用 BPM 引擎。

## Decisions

### 1. 技术路线比较与推荐

2026-10-22 Web续办批次沿用现有v1契约：比较直接读取宽松对象、引入校验库与纯TypeScript边界解析，选择后者，与Android身份/版本/状态/消息/回执校验一致且不新增运行依赖。错误正文不能决定鉴权清理，非JSON的401/403/404同样清空私人内容。分页沿用服务端nextCursor，刷新重读已展开页并按id/版本合并，失败不清空旧历史；不引入客户端自算游标。消息、确认和删除409立即GET恢复，保留合法输入，计划/版本/对象变化后换请求键；不自动重交旧计划。删除必须验证id与CANCELLED回执。结果更新移除当前焦点按钮时，把焦点交给新的状态标题；输入中的刷新不抢焦点。此批不新增API、迁移、权限或自动写入开关，完整双端/读屏验收仍按11.2记录。

2026-10-22边界补齐：继续使用服务端确定性校验；对多个已有任务要求模型逐项提供本次用户原句，原句必须只命中一个可读候选，模型的taskId不能替换目标。单一入口选择仍优先。缺负责人/同名和缺期限一起汇总，不在第一个缺项处提前结束；不完整批次不创建可能错位的依赖步骤。单计划最多10动作、新建任务超过5项时保留原请求并询问本批选择，不能静默截断。人员/期限原句保存于不可变计划而不进入普通任务字段。

Web实际窄屏链路发现底部sticky输入框可覆盖长查询结果，改为跟随正文排列，键盘仍可聚焦输入；用长结果定位回归与真实390px页面留证。Android固定五栏上方的输入布局沿用既有实现，本次未改Flutter视觉。

结果核对复用现有动作回执和同库事务，不引入第二张补偿表。领取前优先核对UNKNOWN及有回执的过期RUNNING步骤：取得actor→事项→步骤锁后，比对动作指纹，存在一致回执只恢复步骤/事项，不再次调用业务；没有回执且原事务锁已释放才可证明该原子动作未提交，保留次数并重新校验后续执行。回执不一致保持RECONCILING、阻止整个事项继续，允许取消并由维护人核对，不盲重试。连接/提交结果不明时记录UNKNOWN，数据库不可用则由租约恢复；UNKNOWN不当作失败传播给依赖。全部现有业务动作必须继续保持业务/回执同事务，这条证明不适用于未来外部系统副作用。

未知结果尚未核对时，新补充指令以409 OUTCOME_PENDING暂停并保留用户输入，避免跨计划重做；取消/删除将UNKNOWN一同停止并推进fence，保留已存在正式记录。耗尽核对按实际回执区分失败与部分成功，其他失败依赖不覆盖核对状态。SSE断线移除订阅后容器可能已释放异步上下文，关闭采用幂等尽力清理，不再次向已释放连接分派。

未接入的报销/采购等申请由服务端约束结果文案：单纯申请不转换为模型猜测的任务动作，答复明确仍需在相应系统提交，标题不采用模型声称的“已提交”。明确另有已接入任务操作时继续适用原授权规则。所有有动作计划的答复只说明已整理，实际“已创建/已提交”来自业务回执，避免执行前的模型文本冒充结果；这不增加外部系统工具或权限。

界面将步骤处理完成与材料合格分开：事项SUCCEEDED且报告NEEDS_FIX/UNVERIFIABLE/STALE仍显示补充材料/需核对/重新检查；PASS显示材料已核对。任务创建显示任务已创建，反馈显示已提交反馈并保留等待验收正文。两端复用现有卡片与状态文字，不重写历史私人标题，不新增样式或开发说明。

正式资料冲突比较同范围全部有效来源，补充不同标题的重叠约束和同字段不同清单ID；无法证明重叠约束一致时暂停，提供双方来源，由维护人核对。与另一次模型判定相比，这条路线不增加外发或预算，也不让供应商自行消除冲突；保守判定可能要求人工核对本可兼容的规则。它不代表对任意自然语言矛盾都有完备识别，自动写入仍受代表集发布门槛限制。删除命令先验证实时身份，再查幂等回执，首次办理才锁未删除事项；同键重发返回原删除受理结果，同键异内容仍冲突。入口关闭还在提交锁内复查。

本轮沿用 POI/PDFBox 的独立受限进程，模板二进制预填也放入相同进程，不在主服务解析 Office 文件。只替换姓名、部门、日期、事由四类明确占位符，不执行公式或填入审核链，避免引入第二套解析/身份规则。预填为只读即时下载，返回前再次校验身份与来源版本。正式资料消费采用公司范围共享事务锁，最终发布/撤回采用排他锁；相较仅锁已引用资料行，此方式还阻止校验后新增同级冲突资料的竞态，当前公司规模下以短事务换取确定性。解析和模型调用保持在锁外。

失效计划重试沿用持久 PREPARE 步骤，记录被替代计划版本。已成功动作按业务指纹复用回执；未执行动作只在旧授权、来源、当前目标和人员仍一致且未过期时延续授权，其余重新确认。当前步骤校验不因已完成对象后来变更而阻塞，确认依赖不完整时整体回滚。计划仍不可变，GET 确认卡仅投影待确认动作。

| 决策 | 候选与代价 | 推荐及理由 |
| --- | --- | --- |
| 自动办理 | 一次模型自由调用任意工具：难约束、难恢复；外置通用工作流引擎：引入运行/运维体系；单体内持久有限状态执行器：需要明确动作模型 | 采用 Spring Boot 模块化执行器、PostgreSQL 步骤记录与现有 outbox。当前只覆盖有限内部动作，便于复用权限、事务和恢复测试 |
| 截图识别 | 直接发送多模态模型：当前 DeepSeek 配置能力未确认；商业 OCR：增加数据出域和凭据；自部署 OCR：增加 CPU/内存和模型包 | 首期使用服务端自部署 PaddleOCR 适配器提取文字/位置，再由 DeepSeek 理解文本。模型和依赖只从官网/GitHub 取固定版本；隔离运行、不开放公网、不引入百炼。版本、中文表格效果与 CPU 基线必须在实施任务中实测，不通过不得宣称截图功能完成 |
| 文件解析 | 所有文件交给模型：数字与公式不可靠；确定性解析与模型结合：工程量增加 | PDFBox 读取 PDF；Apache POI 读取 DOCX/XLSX；图片/扫描页走 OCR。结构字段用确定性规则核对，语义问题作为辅助意见。实现时锁定兼容版本并记录许可证 |
| 公司知识 | 直接复用成长记忆当制度：权威混淆；新独立向量库：过重；正式制度模型加现有受权检索组件 | 新建正式资料与版本，复用授权和文本检索基础，不混用个人记忆的事实类别，不强制 pgvector |
| 自动授权 | 每步确认：打断过多；全权代理：超出业务边界；按动作和对象限定授权 | 本次明确指令优先，长期授权可选、默认关闭、可撤回、有期限。每次执行再验权限，关键修订照常走复核 |
| 页面结构 | 三个功能 Tab：让用户先分类；纯聊天瀑布：结果难找；输入区加事项卡及可续办详情 | 首页一处输入、进行中/近期事项，同一事项内持续追问和展示结果。按用户的事情组织信息 |

### 2. 端到端业务流程

1. 用户输入文字、主动粘贴文字或选择截图/文件，可从已有任务“交给 AI 检查”带入 taskId 与版本。系统创建私有办事事项和不可变消息，返回可恢复 id。
2. 校验成员已确认、公司、上传权限、文件类型/大小、额度与可用能力；处理上传、提取文字、页码/框坐标与内容哈希。明显无效输入立即反馈，不调用模型浪费预算。
3. 理解意图，生成受限结构化计划：查询规则、找模板、创建任务、准备反馈、检查交付或提交反馈/复核申请。每个字段记录来自用户、文件、已发布规则还是推断；模型输出不进入执行器前必须通过 schema、来源和权限校验。
4. 在当前授权集合内匹配人员、任务和正式流程。使用现有任务参与人/派发关系判定操作权，不将“能查看”误当“能派发/反馈/验收”。同名人员、缺负责人/期限、模糊相对日期、规则冲突等一次汇总询问；已知字段不重复填。
5. 形成版本化计划并判定执行依据。查询/检查自动执行；有明确用户指令或范围匹配的预授权时，合规普通写入自动执行。其余只展示一次具体操作确认卡，不重复询问已授权步骤。
6. 服务端调用业务应用接口完成动作，持久回执、审计和 outbox。按依赖顺序执行；一个事项默认最多 10 个动作、一次最多创建 5 个任务，超过分组确认，不无界循环。
7. 返回自然语言结果卡和真实对象链接。任务办理完成与任务工作完成是两种语义：“已创建任务”“已提交反馈，等待验收”必须分开；等待审批不是已经批准。
8. 用户以后在同一事项里上传交付文件，说“检查后提交”。按当时任务、清单、制度和附件版本检查；通过且有提交指令/授权才提交反馈，最终仍由有权人验收。纯“帮我看看”只检查。

示例闭环：群聊截图 + “按这张图给李明派任务” → 提取报价要求 → 查询已发布报价流程/模板 → 缺期限则询问 → 创建任务及交付清单 → 李明主动进入其授权任务上传成果 → 检查数量/金额/材料 → 提交反馈 → 原派发者人工验收。原始私有截图不会因建任务自动分享给李明；只分享用户已授权的必要任务内容和附件。

“先给王经理看”不等于王经理有验收权限。若现行流程已指定其为合法复核人则按规则办理，否则提供可选的评阅/任务草稿或询问；不得让模型改写验收人、审核策略或任务状态机。

### 3. 角色、数据范围与自动执行边界

服务端从登录会话生成 actor，禁止模型/客户端通过 ownerId、companyId、role 指定执行身份。所有者办事事项默认私有，即使是其管理员或上级也不能据管理范围直接读取事项、原始截图与对话；业务动作创建的任务/反馈/制度仍按业务对象的正常范围可见。首期不共享整个事项，多人协作通过任务链接在各自私有事项内进行。

| 动作 | 默认自动性与权限 |
| --- | --- |
| 提取主动提供的材料、查询有效规则、找模板、检查已授权文件 | 已确认成员可在本人当前可读集合内自动执行；上传不等于向公司公开或发布制度 |
| 准备任务/表单/修订草稿 | 自动准备私有计划，不声称已创建正式任务 |
| 创建/派发任务 | 需既有派发资格、人员范围、有效必填项，并有本次明确指令或适用的长期授权；员工无资格时保留草稿，可由用户选择交给有权人，AI 不冒用上级 |
| 提交任务反馈、附件关联、发起关键修订申请 | 需既有参与角色/修订权限、当前版本与明确指令/有效预授权；关键修订只创建待审候选，旧值继续生效 |
| 制度草稿和发布申请 | 指定维护权限；公开生效必须由独立复核人审批，自动办理不能自审 |
| 验收、审批同意/驳回、付款、外部发送、删除、权限修改 | 不在自动动作白名单；审批仍在原审批入口由真人处理，其他未接入行为不得执行 |

长期授权只允许“创建任务”“检查通过后提交反馈”等细分动作，可限制接收人/部门、任务集合、单次数量，默认 30 天到期，用户可缩短并随时撤回。不能设置“永久全权”。公司开关可进一步收窄，不能替用户默认为其开启。截图单独上传默认整理材料并准备方案；只有用户主动选择“按图创建任务”等明确动作或匹配的预授权才执行。截图中“忽略规则”“你拥有管理员权限”等文本始终是数据。

确认绑定 `planVersion + planHash + actionSet + targetVersions + sourceVersions + permissionRevision + expiresAt`，默认有效 10 分钟。任何对象、接收人、分享范围或规则版本改变即失效，只重新确认受影响动作。授权撤回与动作提交按同一用户授权修订锁串行化；撤回先提交则动作拒绝，已提交动作保留回执，撤回阻止下一步，不承诺逆转历史副作用。

账号待确认、调岗、停用/退出、越权来源、审批自审等均沿用现行拒绝语义。检索、摘要、缓存、SSE、历史读取和下载也检查实时范围；权限丢失后清空客户端相关内容和预览，不能通过事项计数、标题或旧引用泄露。

### 4. 持久状态、事务、并发与恢复

本次实时恢复批次比较继续轮询、原生 EventSource 与带认证的 fetch 流：轮询仅作失联兜底；EventSource 不能设置 Bearer 头，不能把会话放入 URL；Web 采用 fetch/AbortController 解析 SSE，Android 继续使用 Dio。事件只携带序号和版本，正文重新 GET。GET 使用只读可重复读快照，使正文版本与 eventsCursor 一致；游标不得超过当前事项最大序号。连接先发送心跳，按持久序号重放；实时身份/事项失权时发无正文的 access-lost 并关闭。来源/目标权限变化即使未修改事项版本，也发送不推进持久游标的 refresh，客户端重新鉴权获取脱敏详情。

两端只接受递增事件序号，忽略重复/乱序；用 GET 版本拒绝较旧结果，权限刷新允许同版本替换。账号、事项或请求上下文变化立即废弃旧响应并清除私人输入、材料、选项和授权。流断线重连及回到前台均重新 GET，轮询兜底；事件不执行任何业务动作。通知从事项状态事务集中写 outbox，仅进入需补充、需确认、失败/部分成功或办妥时发送，处理中/等待复核不逐步通知；使用事项版本作为稳定去重键，投递沿用原 outbox 唯一通知 id。验收覆盖真实 HTTP 流重连、非法游标、撤权/删除、同版本来源失效、重复投递，以及两端乱序与账号切换。完整真实双端登录/读屏仍按11.2独立验收。

事项状态：`QUEUED → PREPARING → READY → EXECUTING → SUCCEEDED`；可分支到 `WAITING_INPUT`、`WAITING_CONFIRMATION`、`WAITING_REVIEW`、`PARTIAL`、`FAILED`、`RECONCILING`、`CANCEL_REQUESTED → CANCELLED`。事项另存 `version`、`planVersion`、`currentStepId` 与已完成动作计数；计划改变必须新增版本，不能在后台扩大已确认动作。

步骤状态：`PENDING / RUNNING / SUCCEEDED / WAITING / FAILED / SKIPPED / CANCELLED / UNKNOWN`，保存类型、依赖、输入摘要、重试次数、预期版本、动作键、结果引用和错误类别。用户看到业务状态，内部状态名不直接展示。

- PostgreSQL 是权威状态库；工作进程通过短事务 `FOR UPDATE SKIP LOCKED` 领取步骤并设置租约。OCR/模型调用在事务外进行，避免长时间锁表；回写时用版本与 fencing token 拒绝过期 worker。
- 任何本地业务写入在同一个数据库事务内完成“再次授权/版本检查 → 执行业务应用方法 → 记录 action receipt → 步骤完成 → 审计/outbox”。AI 模块不得直接写 tasks/review 表，也不得模拟 HTTP 调用自己的 Controller。跨模块适配如不能加入同一事务，必须先补充应用接口和幂等回执后才开放该动作。
- 唯一动作键为 `(company, actor, workItem, planVersion, stepKey)`；同键同规范化 payload 返回原回执，同键不同内容返回 409。POST 接口的客户端幂等键另防断线重发；跨事项语义相似仅提示可能重复，不凭模型判断合并或静默丢弃用户请求。
- 批量多任务逐动作提交，先校验全批格式、权限和依赖；已经提交的步骤不因后一步失败被假装回滚。界面明确“已创建 2 项，1 项待处理”，重试只继续未成功项。
- 读取/解析/模型步骤瞬时失败可指数退避，默认最多 3 次；参数错误、越权、版本冲突、预算不足不自动反复重试。每次重试重新验证来源、权限与预算。
- 服务重启回收过期租约。已有回执则直接完成；可证明未执行则重领；无法确定副作用时进入 `RECONCILING`，查询业务回执/动作键，不能盲目重做或提示用户再点一次。首期没有外部写动作，不能假借“结果不明”掩盖本地事务设计缺陷。
- 用户取消不等于撤回已派发任务：取消请求阻止之后的步骤；正在提交的动作按上述锁顺序决定提交或取消，返回已完成清单。不自动删除、撤回、归档已有业务对象；如需要撤回，进入原业务权限和流程。
- 审核申请被拒绝时保存理由与候选版本，修改后新计划重提；最终通过仍校验原业务版本与禁止自审。无独立审核人保持待审，不自动通过。
- 用户追加或修正输入生成消息与新计划版本，取消未执行旧步骤；已成功结果作为既成事实引用，不重新创建。事项成功后追加需求开启新一轮计划，保留原回执。
- SSE 事件带单调序号和最小业务数据，`Last-Event-ID` 恢复，重复/乱序客户端按版本忽略；断线或切换页面通过 GET 恢复权威状态，不靠局部 provider 当存储。通知只在完成、需用户补充或可操作失败时触发，不逐步骤刷屏。

### 5. 输入、OCR 与文件解析

本次续做比较全局收紧附件上传和按AI用途校验两条路线：保留已有头像/普通任务附件兼容，采用共享的 `AiFilePolicy` 限值及签名策略，AI上传通过可选 `purpose=AI_WORK` 提前拒绝不支持的材料，事项接入和提取时仍重复验证。能力接口公开同一组格式、字节、页数、像素、单元格和解压限额；深度文档校验继续在子进程中完成，错误仅以白名单代码传回，不回传解析异常正文。

首期文字 1–10,000 字；每条消息最多 5 个附件，每个 1 字节–10MB，总计不超过 30MB；支持 PNG/JPEG、PDF、DOCX、XLSX。文件签名、扩展名和解析器允许列表共同校验，不能信任客户端 MIME。损坏、加密、宏、压缩包、旧版 DOC/XLS、嵌入可执行对象等不进入自动解析。PDF 最多 50 页、单图最多 20MP、XLSX 最多 50,000 单元格、解压后不超过 100MB；限值可配置但前后端能力接口一致。

解析在资源隔离 worker 中执行，设置 CPU/内存/30 秒单文件时限及临时目录清理；禁止宏、脚本、外部链接和解析器联网。读取 XLSX 缓存值并标注公式单元格，不擅自执行未知公式；无法验证的公式结果为无法核实。扫描 PDF 逐页 OCR，图章/签名只能说明有图像，不能验证真伪。

模型输入遵循最少必要原则：先在服务端提取和筛选与本次事项有关的字段，屏蔽密码、密钥、证件/手机号等无关敏感内容，不把整张图、完整聊天或无关文件全文默认发送给供应商；需要核对的业务数值保留其必要上下文和来源。不能可靠完成脱敏且含高敏内容时停止外发，要求用户裁剪或补充必要文字。客户端可预览/裁剪选中的截图，但不静默改原始证据；脱敏规则版本进入处理记录。私人备注和未提交日报无论操作者级别都不从系统检索送入模型。用户明确上传的私有办事材料只用于本次事项，不自动成为公司记忆或训练资料。

提取结果包含文本、文件哈希、页码/段落/单元格/框位置、语言、提取器版本和质量标记。识别不清的负责人、日期、金额、数量不得仅凭模型概率写入；需可核实结构来源或用户明确补充。截图缺年份/“周五”缺参考日期时使用用户请求发生时间（Asia/Shanghai）和来源日期分别记录；发现旧聊天或多种解释则询问，不任意补成周五 17:00。公司正式规则可明确约定日截止时点，使用时显示最终具体时间。

重复附件以公司+用户可访问内容哈希复用解析缓存；缓存命中仍检查读取权和当前文件版本。不同用户的私有相同文件不泄漏存在性。支持选择预览、移除与重传，发送之前不触发正式业务动作。AI 文件访问通过受控 `AttachmentApi`，不拼公开 URL、不接受模型提供的任意 URL。

### 6. 公司规则与可执行流程

本次续做采用以下细化路线：正式资料继续在 PostgreSQL 中先过滤公司/组织/正式版本/有效期，再以中文二元词和英文词检索并排序；不新增向量服务。列表支持分页，AI 使用本次输入及已提供材料检索，不再采用空查询前8份。来源保存原文行/段定位，模型引用必须属于实际提供集合；同级同标题正文不一致或同流程稳定清单项矛盾时展示双方依据并停止写入。自然语言隐含矛盾仍需人工核对，不宣称能完整判定所有语义冲突。

公司授权限制复用现有 `review_policy` 与 POLICY 独立复核，不新增免审核管理通道。允许动作、最长1–30天、对象1–100个、每批1–5项只作为个人授权的上限。新增 V16 公司授权修订号和授权绑定修订号；任何公司AI授权策略变更均使旧授权失效，后续放宽不能自动恢复。个人授权默认不存在，已有明确指令或本次确认仍按正常业务权限处理。动作提交按用户锁→公司行共享锁→事项锁进行；POLICY更新的公司行排他锁决定公司收紧与在途提交顺序，个人撤回由同一用户锁串行。

相似任务在受权任务集合内按同一主负责人和标题词重合匹配，最多展示3项。发现候选后暂停该项自动新建，用户可打开已有任务继续或明确选择仍然创建；不能依据相似度自动覆盖、合并或吞掉请求。候选读取和确认时再次鉴权；匹配是有界提醒，不是全库语义去重保证。

正式资料类型为 `POLICY / PROCEDURE / TEMPLATE`，保存公司、维护者、适用部门/团队、版本、生效和失效时间、原文、附件、来源位置、替代关系、审核信息及状态。草稿只对维护者/合法审核人可见；关键组织资料发布、改动、撤回通过独立复核，审核期间旧有效版本继续使用，定时生效/失效由服务端业务时区判定。

指定资料维护权限默认归管理员，授权他人通过既有角色/权限审核；可读范围与维护权限分离。普通员工不能把上传截图变成制度，管理者也不能用私人办事对话覆盖正式规则。权限、适用范围与时效过滤在检索前执行；同级正式规则冲突时列出冲突依据并暂停相关写入，不能按“最新”或相似度偷偷选择。不存在规定时只回答已查到的信息并提供维护入口，不编造流程。

流程定义为受审核的声明式数据：所需字段、资料清单、适用范围、已接入动作类型、字段映射和目标路由。不能上传脚本、SQL、任意 URL 或新工具名。DeepSeek 可以建议映射，服务端只接受允许字段和动作；目标审批人由业务规则路由，制度文本不能改变权限。

首期可执行流程目录只有任务创建、任务反馈和已有关键修订申请。报销/采购等未接入领域可查制度、模板、准备材料，返回“材料已整理，还需要在××提交”，不能伪造提交回执。模板下载仍鉴权；预填使用受控字段，服务端计算字段、金额公式与审批状态不由模型指定。

检索优先返回已发布正式规则并附标题、版本、有效期和可打开位置；历史任务仅作为另行标识的参考，不充当制度。当前权限或来源有效性改变时，使依赖的答案、检查和待执行计划失效；已发生业务保留审计，不偷偷按新制度重做。尚未失效但版本更新的计划须重新比对影响，受影响写入重新确认。

### 7. 交付检查与提交

本次续做保留检查与提交的组合动作，但将 `CHECK_DELIVERY` 与 `PREPARE` 归为只读业务动作：写入开关只阻止正式业务变更，不阻止私人报告。比较仅依赖模型意图与服务端收窄意图，采用后者：用户明确只检查时，即便模型建议提交或存在长期授权也只检查；不通过保留报告和材料，人工核对始终由用户在现有入口主动选择。提交仍重查报告解析器版本、当前角色/阶段、授权及快照，不新增隐含接收或验收动作。

任务增加版本化 `acceptanceChecklist`，条目包含稳定 id、标题、必须性、证据类型、结构化约束、来源版本与 `confirmed/inferred` 类别。明确用户要求及有效制度能生成已核实条目；模型推断项只作建议，不自动成为硬性条件。已发布任务清单变更走现有关键修订，旧清单审核通过前生效；无清单的历史任务可做内容初检，但不能声称满足完整验收要求。

检查输入绑定 `taskVersion + checklistVersion + policyVersions + attachmentHashes + parserVersion + checkerVersion`。每项结果为 `PASS / NEEDS_FIX / UNVERIFIABLE / NOT_APPLICABLE`，整体只有全部必须项可核实通过才为 `PASS`；不适用项需有明确规则或人工依据，不能由模型为通过而自选。材料是否齐全、结构化数量/日期/币种/单位、可计算金额用规则核对；语义覆盖、措辞和版式意见标为辅助意见，不能把供应商“高置信”当成通过标准。

未提交的检查报告和材料仅发起者可读，任务可见权不自动开放他人的检查草稿；选择正式交付时，只把用户授权分享的文件、必要检查结果及未核实清单作为业务记录按任务范围共享，私有对话/原图不随报告间接公开。历史证据入口分别鉴权，不能从正式反馈跳到发起者私有事项。

结果必须定位缺失的材料和矛盾字段，提供补传/补说明/打开文件，不只有分数。OCR 模糊、损坏、加密、无来源、签字真伪、复杂公式无法核实则如实保留，禁止静默跳过。金额用十进制定点与明示币种/舍入规则，不把不同币种相加；格式规范化不能改变业务数值。用户可修改输入或上传新版本重新检查，旧报告只作历史。

用户说“检查后提交”或在该任务范围内设置授权时，通过后可自动追加 `FEEDBACK` 和受保护交付附件引用，返回“已提交，等待验收”。单纯检查不提交。提交事务重新比对任务、清单、规则、文件哈希、当前阶段和参与角色；变化返回冲突并重新检查，绝不能拿旧报告提交新文件。任务接收动作不是隐含步骤：尚未接收时按当前状态机提示接收，只有另有明确指令才执行。

不通过/无法核实时不自动提交。用户可选择“提交人工核对”，须主动确认未核实清单和说明，留下非通过报告，且不能绕过任务模块本身的硬约束或制度禁止；如硬约束不满足，只能补齐或由有权人按正式流程修订要求。AI 不自动触发 `ACCEPTED`、`ARCHIVED` 或复核通过。首期不修改原文件；建议修正内容可复制或保存草稿，不能无声改动报价数字。

### 8. 数据模型与约束

以下是逻辑模型；实施按最终数据库现状分配下一个未使用 Flyway 版本，不预占 V14、不改 V1–V13。所有业务实体带 company_id，外键用 `(company_id, id)` 防跨公司关联，版本正数、状态白名单及有效期约束在数据库和领域共同保证。

| 新实体/扩展 | 关键字段与一致性 |
| --- | --- |
| `ai_work_items`、`ai_work_messages` | owner、状态/版本、计划版本、摘要、消息顺序、创建/更新时间、保留期；用户+公司+更新时间索引；同事项消息序号唯一 |
| `ai_work_plans`、`ai_work_steps` | 不可变计划内容/哈希/来源清单；步骤唯一键、依赖、状态、租约、fence、attempt、输入摘要、结果引用；队列状态+next_run_at 索引 |
| `ai_action_receipts`、`ai_work_events` | 动作唯一键、请求哈希、执行 actor、业务 id/版本、授权依据和执行时间；事项内事件递增序号；与业务动作同事务 |
| `ai_work_authorizations`、`ai_work_confirmations` | actor、动作/对象范围、公司策略版本、有效期/撤销时间、授权修订；确认绑定的计划和来源版本、一次性消费记录 |
| `ai_file_extractions` | 私有文件引用、hash、parser/OCR 版本、状态、定位结果、质量和错误、过期时间；用户隔离的解析去重 |
| `procedure_documents`、`procedure_versions`、`procedure_chunks` | 类型、范围、生效状态与 activeVersion；不可变正文/模板附件/流程定义；复核 id；版本和位置唯一的受权片段及检索索引 |
| `task_acceptance_items` / 清单版本快照 | task、清单版本、稳定条目 id、来源与确认类别；写入任务创建事务，修订生效时更新，不把 inferred 当硬性条目 |
| `task_delivery_checks`、`task_delivery_findings` | 检查版本清单与 hash、逐项状态、证据位置、模型/规则版本、报告到期时间；owner+task+created_at 索引 |
| `task_deliveries`、`task_delivery_files` | task、提交 actor、反馈事件序号、报告 id、提交模式/说明、附件 hash；提交动作唯一，交付与事件同事务 |
| `attachment_bindings` 与附件元数据扩展 | 用途、公司、资源 id、附件 id、分享范围、hash、检测类型/清理期限；新绑定由对应资源鉴权，不用单一 task_id 覆盖旧关联 |

外部请求重试键新增通用执行幂等表或模块专用唯一记录，不复用仅有 task_id 的旧 `idempotency_keys` 存任意流程结果。调用旧 TaskApi 时同时传稳定动作键以兼容已有派发去重。

资料、历史和审计按用途分开：默认原始办事材料在事项完成 30 天后清理，解析缓存 7 天，私有对话/检查报告 90 天，授权/动作审计 365 天；均为待公司部署配置确认的默认值。已关联正式任务交付的附件和已发布制度按业务保留策略保留，删除私有事项不级联删除正式业务/审计。过期或用户删除后立即禁止新的检索和生成，异步清理缓存/临时文件，备份恢复重放失效标记。来源附件已清理时只显示不可查看的历史定位，不恢复已删除原文。

备份恢复失效采用独立标记文件和运维CLI，与新增管理员恢复接口比较，CLI无需扩大线上权限或暴露私有事项，适合当前单机Docker部署。导出合并旧标记并原子替换文件，部署流程持续导出和独立保存；恢复时停止全部API/worker，在事务内重放、清私有数据、提高租约fence，保留正式业务和幂等回执。CLI校验指定API已停止，多副本停机仍由部署流程保证。审计365天后仅清授权/动作详情，保留最小追溯元数据；不得删除动作回执导致重放。无新增数据库结构。

删除尚未完成的事项须先按取消语义停止后续步骤并核对在途提交，再清理私有内容；不得出现页面删除了但队列继续派任务。未完成事项超过90天无活动先停止待执行步骤并提醒清理，需合法保留的审计只存最少摘要和引用。制度草稿/私有资料的自动清理不影响其他用户已合法提交的业务副本。

### 9. API 与跨端契约

Flutter恢复批次（8.2）：保留现有REST/SSE契约，选择在repository边界严格解析事项/分页/能力DTO，而非页面逐字段猜测默认值；必需身份、版本、已知状态或嵌套结构缺失时返回可恢复错误，未知状态不得落入成功。列表去重保留较新版本。GET失效时清除受保护内容；命令失败的401/403/404同样立即清除，409刷新后由用户重新核对。请求键绑定具体动作与请求版本；相同未确认请求重发保留键，版本/选定对象改变后换键。消息提交与确认/取消/重试互斥，选择弹层和晚到回包均受账号/权限代次约束。验收覆盖真实HTTP协议、离开重进、断线重发、冲突、失权和取消后真实回执；不新增数据库迁移或扩大自动写入范围。

新增接口共享当前认证、统一错误和 traceId，返回显式 `contractVersion: 1`。命令白名单拒绝未知字段、伪造执行 actor 和模型指定服务端状态；分页使用现有游标格式。所有写接口说明用途、权限、参数、返回、错误、版本及幂等，不能只添加路由。

| 接口 | 用途及关键条件 |
| --- | --- |
| `GET /api/ai/work-capabilities` | 返回当前 actor 可用动作、文件限值、自动授权状态及功能开关；不返回密钥或内部提示词 |
| `POST /api/ai/work-items` | `{text, attachmentIds, taskId?, taskVersion?}` + Idempotency-Key；仅创建本人的私有事项；返回 202、id/状态/版本，未在响应前承诺业务成功 |
| `GET /api/ai/work-items`、`GET /api/ai/work-items/{id}` | 本人分页、消息/步骤业务摘要、已执行回执/结果链接、待补信息与当前版本；所有引用重新鉴权 |
| `POST /api/ai/work-items/{id}/messages` | 追加文本/附件/消歧答案；带事项 version、Idempotency-Key，生成新计划，不改原消息 |
| `POST /api/ai/work-items/{id}/confirm` | 带 version、planVersion、planHash、选定动作与 confirmationId；仅对尚有效计划确认，服务端校验不可由客户端替换对象 |
| `POST /api/ai/work-items/{id}/cancel`、`.../retry` | 带 version 和幂等键；返回真实已完成清单；retry 只对可重试且未成功步骤有效 |
| `DELETE /api/ai/work-items/{id}` | 本人操作，If-Match事项版本和幂等键；202返回删除受理回执，立即隐藏私有正文并阻止新步骤，核对在途提交后按用途清理；不删除正式业务 |
| `GET /api/ai/work-items/{id}/stream` | 受保护 SSE，支持 Last-Event-ID；只推已持久化事实和可展示摘要，不输出推理链或供应商原始流 |
| `GET/POST /api/ai/work-authorizations`、`POST /{id}/revoke` | 本人授权列表/创建/撤回，带版本/动作白名单/范围/有效期；不能授权本人没有的业务权限 |
| `GET /api/procedures`、`GET /api/procedures/{id}` | 查询/下载当前适用的正式资料和来源；草稿独立维护权限，不因 AI 可读而全员开放 |
| `POST /api/procedures`、`POST /{id}/revisions`、`POST /{id}/publish-requests` | 有权维护人创建草稿、版本候选、申请发布/撤回；带版本/理由/幂等，接现有独立 review 流程 |
| `POST /api/tasks/{id}/delivery-checks`、`GET .../{checkId}` | 异步检查指定材料；必含 taskVersion 和文件集合；复用检查领域，与办事执行器共享逻辑，不建立第二套规则 |
| `POST /api/tasks/{id}/deliveries` | taskVersion、checkId/checkVersion、attachmentIds/hashes、mode、text + 幂等键；创建反馈、交付、附件绑定与回执的单事务应用方法 |

不增加新“随意执行工具”的公开接口。读取类也有 actor/公司校验；有 ID 不等于有访问权限。任务创建的 acceptanceChecklist 为可选新字段，旧请求继续有效；通用 events 不接受 AI 随意扩展字段，附件交付走新应用方法后复用既有 FEEDBACK 状态转换。

错误分层：400（无效输入/超限/未知动作）、403/404（按现有资源隐藏规则拒绝）、409（版本/计划失效/幂等冲突/非法转换）、413（请求体超限）、415（不支持类型）、422（材料无法解析/必要字段歧义）、429（限流/预算）、503（模型/OCR 暂不可用）。HTTP 接收成功与异步业务失败分开，GET 返回 `state + recoverable + nextAction + sanitizedError`。开发日志保留 traceId、阶段、耗时、hash 和错误类别，不打印密钥、原图、私有正文或供应商原始上下文。

### 10. UI 结构、文案与动效

“当前小程序风格”按仓库正在使用的 Flutter 团团风格理解，本提案不创建微信小程序或新视觉体系。沿用 `SunnyPaperTokens`、`PaperLayoutTokens`、`PaperSurface`、现有按钮/弹层、TuantuanDisplay 重点字体及本地素材；不退回 cute_ui 包默认的小圆角，也不加新 UI 框架。颜色以当前 ThemeExtension 为准，奶油 `#FFFDF4`、薄荷 `#E6FAEF`、AI 浅紫 `#F1E7FF`、浅蓝/珊瑚状态色，正文保持对比。

**AI 首页：**

- 简洁顶栏“AI地图”，右侧只有有需要的历史/更多操作；不加脑图标、范围横幅、日期筛选、用量/重置或旧分析 Tab。
- 中间按“需要你处理”“正在办理”“最近办过”组织真实事项；没有对应记录就不显示空分组。卡片给出事项标题、一句进度或结果、必要的接收人/期限及一个主操作。状态属于办理事项，不给派发列表加完成情况字段。
- 底部固定输入区在五栏导航正上方，placeholder“说说要办什么…”，附件按钮文案“添加图片或文件”，发送按钮“发送”；可展开多行并预览选中的材料。键盘弹出时输入区随键盘抬升，五栏避让或收起以腾出空间，键盘关闭恢复固定顺序；输入区不遮住最后一张卡。
- 空状态使用现有小幅困团素材和一句“把事情交给我”，提供三个可直接开始输入的例子：“截图建任务”“检查交付”“找制度和模板”。它们只填入可编辑请求/打开选择器，不另开三个互斥工作流，不作为长期大欢迎卡占屏。
- 不增加“把下一步想清楚”卡片、“今天优先三件事”、通用说明大段文字或底部独立“开始分析”按钮。长规则、依据、已执行细目按需展开。

**事项详情：**

- 展示原请求/材料缩略图、当前进度、结果卡和后续输入区；不把每次模型 token 做成对话气泡。
- 缺少信息时用一张补充卡集中列出必要字段，能选人/日期/任务就不要求打字；只展示当前范围内候选，不列出无权对象。
- 需要确认时说清“给谁创建什么、什么时候、会分享哪些材料”，主按钮“创建任务”“提交反馈”等，避免“确认执行计划”。已授权步骤无需再确认。
- 检查结果直接写“缺少成本明细”“数量需要核对”“签字需要人工确认”，附定位和补充入口；通过时写“材料已核对”，实际提交后才写“已提交，等待验收”。

**文案约束与样例：**

| 场景 | 可用产品文案 |
| --- | --- |
| 处理 | “正在整理要求…”“正在核对材料…”；只对应已开始的步骤 |
| 消歧 | “找到两位李明，这项任务交给谁？” |
| 缺期限 | “这项任务什么时候交？” |
| 不清晰 | “这张图有几处看不清，换一张清晰的，或补充文字。” |
| 完成 | “任务已交给李明” + 查看任务；不能写“任务已完成” |
| 部分完成 | “已创建 2 项，还有 1 项需要处理” + 继续处理 |
| 未接入 | “材料已整理，还需要到采购系统提交” + 可用入口 |
| 故障 | “暂时没能处理，内容已保留” + 重试；不把内部异常原文展示给用户 |
| 权限变化 | “你目前无法办理这项操作” + 返回/联系管理员的现有入口 |
| 取消 | “已停止后续办理，已创建的 2 项任务仍保留” + 查看 |

禁止在用户界面常驻展示 API、RAG、OCR、幂等、数据库、模型 schema、Mock、技术路线、traceId 或实现说明；演示环境标识、用户确需知道的分享范围/不可用原因/未核实项目仍用正常字号自然表达，不能为“页面干净”隐藏关键事实。详细诊断留在开发日志/有权管理页。正文 15–16sp、辅助字段不低于 13sp，关键结果/错误/确认不做低对比小字。

**动效：**

| 位置 | 动效及触发 | 边界 |
| --- | --- | --- |
| 按钮/卡片按下 | 复用 100–160ms 轻压；反馈点击已接收 | 提交禁重复，非交互卡没有假点击效果 |
| 上传 | 缩略图 160–220ms 淡入，真实字节进度 | 取消选择不显示成功；上传完成不等于识别完成 |
| 正在办理 | 局部星点/指示器与真实阶段文字 | 不伪造百分比、思考步骤或无限装饰；离屏/后台暂停装饰 |
| 卡片补充/结果替换 | `AnimatedSwitcher` 与尺寸过渡 180–240ms | 保持滚动锚点和输入焦点，不刷新跳顶，不逐 token 变高 |
| 完成 | 服务端回执后一次 250–350ms 勾选淡入 | 不循环庆祝，待审/失败不播放成功 |
| 打开详情/补充弹层 | 复用现有 160–220ms 淡入/轻移 | 手势可中断、键盘不遮主操作、无强制等待动画 |

优先复用现有 motion token，新增值集中放 ThemeExtension，不能散落 magic number。遵循系统 disableAnimations/减少动态效果：移除循环、缩放、大位移，仅保留静态状态或极短淡入。TalkBack 状态只在阶段变化时播报一次，不能按帧或 token 播报；焦点在卡片变化后保持。触控≥48dp、正文对比≥4.5:1，不只靠颜色；360/390/412dp 与 1.5 倍字体不截断主操作。截图/文件预览含语义名称，上传进度有可读替代。

### 11. 质量目标与验收方法

- **正确性**：三条真实业务闭环各有正常/异常验收；关键数值比较有确定性单元测试。代表性中文截图和文件样本至少 60 份，覆盖清晰/模糊/多页/数字/日期/同名/注入，记录逐字段准确率、需追问率和来源定位率；自动写入测试集误派人/误改金额/误期限为 0，所有必须字段来源/补充可追溯。未达要求就关闭相应自动动作，不能拿单个样例当整体能力合格。
- **权限与隐私**：跨公司、同公司范围外、待确认、禁用、草稿、私有材料、来源撤权、管理员越界、SSE/缓存/下载/统计全部做负向测试；模型和日志中不出现密钥/私人备注/未提交日报。新上传的私有截图仅作为本次办事材料，不能自动进入长期公司知识库。
- **可靠性**：并发确认、双端重发、worker 崩溃和业务事务后断线，各模拟至少 20 次，正式动作无重复，回执可恢复；取消与撤权边界有可复现提交顺序测试。文件解析失败不丢输入，不影响任务/日志手工使用。
- **性能目标**：在记录配置的本地/测试服务器、20 并发下，排除文件上传耗时的事项接收/详情 P95≤1秒；清晰单张 1080p 中文截图本地 OCR P95≤5秒；普通任务不因后台 OCR 排队显著退化。模型端到端耗时独立记录，不伪装固定 SLA；超出运行超时返回可恢复状态。
- **视觉与易用性**：代表机型 profile 模式滚动/卡片切换目标≥95%帧在 16.7ms 内，无超过 100ms 的主线程停顿；测量时注明机型和采样范围。5 名首次使用者各完成截图建任务/文件检查/查规则，至少 4 人无需口头指导完成且能区分“已提交”与“已验收”；记录失败点后修正。TalkBack/1.5字体/减少动画为交付检查项。
- **证据分离**：确定性模型/OCR桩用于自动化控制故障，不等同真实服务验收；至少用部署选定 OCR 和已配置 DeepSeek 跑代表样本。未获得环境凭据/配额时记录阻塞，禁止勾选真实服务验收任务。文案截图只证明 UI，不证明业务执行。

## Risks / Trade-offs

### 实施记录（2026-10-21）

- 实际采用V14与V15，交付检查为202持久作业，GET可恢复；文件解析采用独立子JVM，OCR独立内网容器。模板预填目前针对正文安全占位，不编辑二进制Word表单。
- 视觉原型为 `mobile/prototypes/ai-workbench.html`，真实Flutter控件截图覆盖360/390/412宽度、360的1.5倍字体、首页/确认/真实回执；证据目录见validation.md。沿用纸卡、薄荷/淡紫、中文字体和原导航素材，无新增资产许可负担。
- 真实OCR+DeepSeek的60份合成截图不等于全部代表场景验收；存在OCR/严格字段校验失败，OCR性能尚未达标。保留自动写入关闭、未通过任务和阻塞，不调整原验收阈值。
- 已有相似任务提醒、公司收窄策略与两端SSE/GET恢复；Flutter正式响应校验、续办/冲突/账号隔离见8.2批次证据。完整语义冲突/多任务矩阵、文档操作系统沙箱、审计保留/备份删除重放、真实设备/人测及完整真实跨端验收仍待补，不归档本变更。

- [自然语言理解错误] → 关键字段有来源/确定性校验，含糊时追问，批量动作有边界；金额、人员、期限不能靠生成文本猜测。
- [OCR资源与文件解析攻击] → 固定依赖、隔离限额、禁外连、解压/像素/页数限制及清理任务；无法支持的格式明确留给人工。
- [全自动预期超过现有权限] → 明确员工无派发资格、审核独立性和已接入动作目录，不能借“自动办理”扩大角色。
- [制度不完整/互相冲突] → 正式发布、时效和适用范围管理；冲突暂停相关写入，不用历史记忆或模型常识补规则。
- [旧文档/活动 change 与新入口冲突] → 实施批次 1 完成追踪和基线映射，UI 切换前同步过时规格，旧历史和 URL 兼容；不改动无关旧任务勾选。
- [公共接口仅声明或未满足同事务] → 实施前对 TaskApi/AttachmentApi/ReviewApi 做定向适配验收，未具备幂等和回执的动作不开启自动模式。
- [Web 页面落后] → P0 要求相同服务端契约，P1 新页面单独跟踪；发布说明明确 Android 已交付范围，不冒称双端 UI 完成。
- [模型成本/上下文过大] → 全部 AI 调用统一计入公司+用户预算及并发限额，解析/检索先裁剪去重，重试也记账；额度不足保存事项，禁止出现“任务已创建”的假结果。
- [原始材料与业务保留期不同] → 资源用途独立绑定、删除不级联正式记录、历史证据失效可解释；默认保留期须部署确认。

## Migration Plan

2026-10-22 冲突协调以 [协调方案](reconciliation-2026-10-22.md) 为准：主分支已发布 V14/V15 保留，AI 未发布脚本改为 V16–V18；旧 AI 历史仅在严格白名单校验的恢复副本转换并验证后切换。用户已授权按确认规范整理混合工作区，原先“不在混合区自动提交”的暂停由本次授权解除，仍保留远程认证、验收和独立审阅要求。

1. 规划完成后先关联正式 Issue/Sprint，按模块认领；同步 `方案.md` 和现有 AI 页面/行为约束，确认本 change 的取代范围。不在现有混合工作区自动提交/推送。
2. 新增 Flyway 迁移、索引、review kind 和兼容字段；先在含历史任务/附件/审批的数据库快照上演练。新表空表启动，旧分析作业、记忆、任务不自动转换或重新执行。
3. 部署本地 OCR/解析 worker 及资源限额；补环境变量示例但不提交真实凭据。DeepSeek 使用既有服务端凭据配置；新预算调用统一接入，不能另开不受预算管控的通道。
4. 分别用 `ai_workbench_enabled`、`ai_work_execution_enabled`、`ai_ocr_enabled` 开关控制入口、写入和截图能力。先启用读取/准备/检查，再对已验收动作启用授权执行，最后切换新 UI；公司/用户长期授权仍默认关闭。
5. 先完成当前批准批次，再统一执行受影响后端测试脚本、Flutter analyze/test/APK 构建、严格 OpenSpec 校验及真实服务/设备验收；不在实现过程中重复跑全量检查。代码交付包含正反链路、数据库和文案截图。
6. 回滚先关闭执行开关，禁止领取新写步骤，等待或核对在途事务；保留回执和已创建业务，读历史结果仍可。可切回旧 AI 页面，已提交动作不反向删除。数据库采用向前兼容迁移，不 DROP 新表或回退已发布 Flyway；旧版本如不认识新增复核 kind，须先禁该类申请并排空/处理存量或部署兼容版本，不能直接回退。

## Open Questions

以下均记录默认设计和关闭条件，不把未知事项隐藏在实现任务中：

- Issue/Sprint、模块实际负责人和估算尚未关联，见 `tracking.md`。不影响提案审阅，业务代码实施前需完成追踪。
- 正式制度、模板与独立复核人需要由公司提供/指定；测试可用明确标识的测试资料，正式上线没有有效规则时只能做基于已知任务的办理，不假造公司规定。
- OCR 的固定版本、目标部署 CPU/内存及中文样本效果待实测；推荐本地方案不变，未达标准先关闭截图自动写入，支持文字和人工补充。若以后改外部 OCR/多模态供应商，另行比较与更新外部数据处理设计，不在本提案默认启用。
- 本设计默认的材料保留期和性能基线机器需在部署前确认；更改默认值须同步能力接口、清理任务与验收文档。
- Web 新工作台安排 P1；若要求与 Android 同批交付，将对应任务提升 P0 并补齐完整 Web 视觉/交互验收，不能只打开后端接口即宣称完成。
