## Why

员工每天重复把聊天内容录入任务、找制度和模板、核对交付材料，现有 AI 地图以分析建议为主，无法直接减少这些操作。本变更把 AI 地图升级为统一办事入口：用户交代事情或提供截图，系统在授权内完成可执行步骤，只在缺信息、需决定或发生异常时打断。

## What Changes

- **MVP / P0**：连通“聊天、截图转任务 → 按公司规则找资料和办理 → 交付前检查 → 提交反馈、进入原有人工验收”的业务闭环；一次输入可触发多个有依赖的步骤，不要求用户选择 AI 功能类别。
- **MVP / P0**：服务端持久化办事记录、执行步骤、依据、授权与结果。明确指令且有权限的普通动作自动执行；截图中的指令只作为材料，须有本次用户指令或适用的长期授权才能执行。关键业务修订和独立复核规则继续生效。
- **MVP / P0**：检查材料完整性与可核实字段，区分“检查通过、需要补充、无法核实”；不把模型判断当作最终验收，不用无法解析的文件冒充检查通过。
- **MVP / P0**：新增正式公司制度、流程和模板的版本化维护、独立发布审核、受权检索及可执行入口；只执行已接入的任务和复核操作，其余流程提供依据和材料，不宣称已经办理。
- **MVP / P0**：沿用现有团团界面、组件、离线字体和素材。输入区固定在五栏导航上方，卡片展示真实进度和结果；文案以办事为目的，禁止开发术语、流程架构说明和无助于决策的常驻小字。动效服务于上传、处理、卡片变化和真实完成，并支持减少动画。
- **BREAKING（新界面）**：AI 主入口从三个分析 Tab 和“开始分析”改为办事工作台；保留旧分析记录与受保护的既有路由兼容，不迁移成任务，不从首页主动推荐预测或堵点分析。旧 `/api/ai/jobs` 保持兼容，新自动办理使用独立契约和开关。
- **MVP / P0**：覆盖权限撤回、重复提交、并发修改、重启恢复、取消、部分成功、结果不明、文件损坏、知识过期、模型故障及预算不足；基础任务和日志不依赖 AI。
- **Should / P1**：在同一工作台补齐 Web 办事界面；P0 已要求共享 API、跨端续办和授权一致性，不能用 Web 旧版页面称为新功能双端交付。

非目标：本次不做发展预测、堵点评分、自动日报、交接包、催办、外部聊天平台抓取、自动读剪贴板、任意电脑操作、对外发信、付款、删正式记录、修改权限、AI 代审批或独立报销系统。语音、复杂 CAD/压缩包/旧版 Office 解析、向量数据库及新图谱引擎不在首期范围。

## Capabilities

### New Capabilities

- `ai-work-execution`：用户故事 E1–E4；自动办理的授权、执行状态、事务幂等、恢复取消与版本化确认。
- `ai-work-intake`：用户故事 I1–I3；文字、截图和文件接入，来源定位、实体消歧与任务结构化创建。
- `ai-delivery-check`：用户故事 D1–D3；交付清单、证据检查、结果解释与提交反馈的闭环。
- `company-procedures`：用户故事 K1–K3；正式制度和模板、版本审核、权限检索、入口办理与失效传播。
- `ai-workbench-ui`：用户故事 U1–U3；统一办事台、产品文案、状态动效、无障碍及会话恢复。

### Modified Capabilities

- `ai-map-direction-ui`：AI 主导航改为办事入口，发展分析作为兼容的辅助路由；澄清“发展分析内不增加聊天”不禁止独立的办事工作台。
- `collaboration-backend`：AI 业务动作允许在明确指令或有效预授权下由服务端调用普通业务接口；旧分析建议仍须人工确认，模型始终没有直接写库与审批权。
