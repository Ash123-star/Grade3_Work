# Design

## Route and boundary
直接清库/改写旧场景V1会毁坏现有业务或使Flyway校验失败；推荐新建空库，继续正式V1–V23结构迁移，再选择独立db/scenario-annual2026目录，历史表flyway_annual2026_history。默认SCENARIO_DATASET=legacy保留旧行为，用户显式选择annual-2026，关闭开关时不运行任何场景。初始化管理员先于场景执行，维护账号建议sysadmin避免与场景admin冲突。

年度初始化仅允许默认公司的初始化管理员存在，拒绝已有其他用户、业务或旧场景历史；整个场景SQL同事务，冲突回滚。复用同一DataSource、BCrypt摘要和当前V23结构。重复启动Flyway跳过；不在旧库迁移/重置密码。初始化数据明确为历史夹具，不假称历史HTTP操作。

固定2026年6—11月。每名正常人员每月6项任务，林予安从10月入职开始，停用人员保留停用前任务，待确认无公司任务。任务开始日期和1–8天工期按确定性散列错开，状态事件有序且不超过首次初始化时间，未来任务只有提前派发事件。角色专属任务标题、公司重点分组、前一阶段任务引用及跨人交接评论构成关联，不新增依赖图字段。

每人每日唯一日志，工作日为主、少量加班与缺交，正文包含多项工作且taskIds/log_tasks一致；至少覆盖当天一个实际参与的任务，空排期日可记录已经创建任务的复核/准备，不提前记录未开始任务的成果。未来无日志。新成员不生成入职前数据。仅最新少量通知等待投递，不制造大量历史未读提醒。

公司重点10条；Mock五色来自mock_repository的seedTasks。真实标签ID由数据库提供；用户随后授权合并live-task-label-selector并行修复，创建页通过真实标签资源选取；未运行联调，不宣称端到端已验证。当前任务卡片仍按管理授权范围查询，不宣称其已改为个人范围。

## Fresh initialization compatibility (#73)

已发布 V1 不改写；追加 B1 作为新库初始化快照，仅修正改期候选的申请人/有效直属上级筛选，其他初始数据与历史增量继续复用。直接改 V1 会破坏校验，V7 又无法修复尚未执行成功的 V1，因此采用新库 B1、旧库 V1–V6 的 Flyway 原生基线机制。

年度入口只对没有任何场景历史的库建立空历史表，元数据阶段固定 `target=0?` 并清空脚本加载路径，之后正常执行 B1 与 V2–V6；不使用自动 baseline(0)，不登记跳过的业务版本。已应用 V1/V6 的库不执行 B1，历史、人工修改及密码保持原样。B1 继续锁表并拒绝非空业务库；只有旧 baseline(0) 的失败库保留现场，使用另一个明确的新空库，不删历史或 repair。legacy 入口保持原样。运维步骤与限制仅维护在现有年度场景文档。

## Credentials and deployment

云端反馈旧服务没有显式DB_URL：新增--source-url/--source-user供运维核对后指定原连接，可选root-only密码文件，仍拒绝不明Spring命令行覆盖。显式用户名同时写入新库环境，不通过猜测默认值或读取未解析的配置文本决定数据库。
账号短名至少3个合法字符，场景密码沿用正式12字符/72字节规则，示例test12345678。真实密码不入SQL。系统服务仍运行宿主JAR，原实例内新建库，不新建Docker数据容器；确认实际连接后以同一个DB_USER创建空库，独立root-only环境文件覆盖DB_URL/场景选项。保留旧库、备份、原配置以供切回；会话和客户端草稿需重新登录/按账号隔离。

## Existing annual database enrichment

2026-11-06 用户授权在现有本地及云端年度库补齐多创始人、个人资料、团队与月历溢出数据，并部署最新代码。采用新增 V4/V5 增量迁移：优于改写已发布 V1 或手工散落 UPDATE，保留历史校验、事务失败回滚和重复启动跳过能力。不改变正式数据库结构、用户角色、状态、汇报关系、审核权限或月历布局。

V5 仅处理 annual-cm/annual-peer 中 annual-* 虚构成员；只填空资料、不覆盖已编辑字段。无团队人员按现有部门进入对应组；无部门的创始人/管理员进入综合管理部/组，隔离公司使用本公司的运营组，归属冲突整体拒绝。待确认成员可有预分配团队但不激活、不生成任务、不伪造入职日期。非场景维护管理员不补造个人信息。V5 手机号使用 000 占位；V6 仅将该精确格式转换为符合现有资料校验的虚构 1990000 演示号，不表示真实联系方式。

每位在职普通员工在 11 月 6—11 日追加 8 项重叠计划，关联参与人、兼容分配表、标签、派发事件和场景审计；不生成未来完成记录、日志或通知。云端先运行已发布 V2/V3 追加三名创始人。执行前备份实际业务库；本地沿用 flyway_local_annual2026_history，云端沿用 flyway_annual2026_history，不伪造或 repair 历史。

验收按用户要求只运行编译、规范校验及实际数据/部署核对，不运行测试套件。核对场景人员团队非空、公司/部门一致、在职资料完整、创始人四名及目标日每位在职员工至少 8 条关联任务；界面 +N 由用户设备验收。云端保留未提交改动，更新镜像后重启实际 systemd API，移动端使用公网 API 地址。
历史初始化批次曾按用户要求跳过编译、测试及真实迁移。2026-11-06 的新增授权与验证范围以上节为准：已实际完成本地 V4–V6、后端打包和公网 APK 编译，云端 V2–V6 也全部成功；不运行测试套件，设备验收待用户执行。云端四名创始人、人员归属与资料、每位在职员工八条新增任务均已实际核对，迁移与备份证据见现有年度场景文档。PR #74 已合并并重启实际 systemd API，公网健康检查正常；Android 公网版 APK 已覆盖安装到模拟器。节假日云端网络问题在同仓库双入口修复中跟踪。
