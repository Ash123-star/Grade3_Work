# 后端模块化架构与接口契约重构

## Why

当前后端已经覆盖认证、组织、任务、日志、审核、通知、统计、附件和 AI，但 Controller、用例编排、领域规则和 SQL 访问集中在少数 Java 文件中。多人并行开发时容易产生跨模块依赖、重复权限校验和接口文档漂移。

## What Changes

- 建立 API、应用、领域、基础设施四层边界，并按认证、组织、任务、日志、审核、消息、分析、AI、附件划分模块。
- 保持现有 REST 路径、错误格式、分页格式和数据库兼容性，先通过端口/适配器隔离公共契约与模块实现。
- 为所有 HTTP 接口补充用途、权限、参数、返回、错误、幂等和版本要求的 JavaDoc，并生成独立架构文档和接口文档。
- 统一跨模块公共契约：身份上下文、数据范围、分页、错误、版本和事件，不允许业务模块直接依赖另一个模块的 Controller。
- 记录迁移阶段约束和后续拆分任务，避免把文档设计误报为全部代码已完成。

## Impact

- 影响 `server/` 的包边界、接口注释和应用服务依赖方向。
- 新增 `docs/backend-architecture.md` 与 `docs/backend-interface.md`。
- 不改变已发布 API 路径、数据库迁移历史或客户端请求格式。
