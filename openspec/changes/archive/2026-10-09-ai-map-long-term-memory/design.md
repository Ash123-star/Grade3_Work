## Context

根目录《AI地图长期记忆技术方案.md》是本变更的详细设计，涵盖页面、知识库入库、切片索引、文本 RAG 与图模型、更新/遗忘、API、部署与验收。《方案.md》第 7 节同步设计方向。本变更进入实施，状态以经过验证的任务为准。

原 Flutter 页面包含发展分析、堵点风险、行动规划；后端 Ai.java 处理区间 AI 作业。现在单一发展地图、长期记忆、RAG 与同容器 Neo4j 已进入实施和测试。此处描述目标设计，具体完成状态以 tasks 与验证记录为准。

## Goals / Non-Goals

**Goals:**

- 一个发展分析页面，个人/组织切换数据范围，记忆管理作为辅助交互。
- 建立可追溯、可纠正、可遗忘的记忆知识库，用 RAG 检索有效经历、成果、目标与经验支撑分析。
- 两端使用同一服务端契约，图谱路径、模型输入及历史输出都按实时权限校验。

**Non-Goals:**

- 不新增独立风险页、行动清单、通用聊天页或自动派发。
- 不微调模型，不承诺经营与晋升预测，不将建议转成事实记忆。
- 不归档未完成变更，不把未经验证的实现报告为已交付。

## Decisions

### 单一发展页面

保留经历→成果→经验→目标→缺口→建议这一条主线，Android 使用路径卡片，Web 可使用关系图，辅助抽屉处理证据与记忆纠正。相比保留三页，单页更符合本次明确范围，避免演示清单被误认为成果。

### PostgreSQL 权威记忆与 Neo4j 投影

记忆版本、来源、关系与删除排除规则保存在 PostgreSQL；Neo4j 只做可重建投影。业务与 outbox 原子提交，图更新幂等、带版本与删除墓碑。相比同时写两库，此方案能处理乱序、失败和重建。

### 三层知识库与受控入库

原始资料保留在业务系统，精选记忆保存有效事实及待确认观察，检索层保存必要原文证据片段与索引。AI 推荐候选内容与证据位置，服务端按来源、版本、权限、敏感过滤和去重规则入库；结构化事实自动生效，能力观察待确认，关键组织陈述独立审核。未选中资料可重新提取，但不绕过入库规则送给生成模型。相较模型直接决定写入，此设计保证权限、确认和业务审核可执行。

证据片段按日志字段、任务事件与复盘段落切分，不跨权限、来源版本或类别拼接。新增 knowledge_chunks、knowledge_index_jobs、rag_retrieval_runs，保存定位、版本、索引状态与引用清单。有效记忆状态与索引就绪状态独立；候选不进入正常 RAG，索引失败可独立重试，不回滚业务提交。

### 事实、观察和推测分开

确定性类别与记忆状态独立；自述不能替代验收，AI 能力观察需确认，确认不改变确定性类别。正式记录修订复用候选版本、独立审核和 optimistic version 校验，禁止自审。私人纠正不修改正式日报；正式事实争议可暂时排除记忆。

### 授权检索与最小化上下文

先由 PostgreSQL 得到当前允许的记忆、关系和来源集合，Neo4j 每个中间节点与边都限制在集合内，再读取来源正文。禁止任意 Cypher。个人目标与偏好只允许本人；管理者只能查看范围内组织记忆，不能穿透私人目标。相较先全图检索后过滤，避免路径和统计泄露。

### 文本 RAG 与图谱融合

流程是目标构造查询→授权文本召回→有限图路径补证→按排名融合与确定性排序→同事件去重→有限证据上下文→DeepSeek 生成→引用、来源版本与权限复核。首期中文关键词/标签/全文检索，图谱提供跨经历关系；RAG 不要求向量。最多召回 50 个文本片段、选取 12 个上下文片段作为可调整初始预算，输出空间单独预留。检索未命中说明信息不足，不补造个人或公司事实。

文本证据、图路径及本次来源清单可定位；合法引用不保证语义支撑，结构化事实可字段比对，非结构化结论纳入抽样评估，无法支撑的断言移除或降为待验证推测。相较将全部历史拼入提示，RAG 控制成本并减少过时和无关信息。

### 向量作为可选扩展

以后用 pgvector 扩展 PostgreSQL 语义检索，独立嵌入模型需验证中文召回、维度、版本与数据处理范围；不假定 DeepSeek 对话 API 提供嵌入。启用前评估优于文本基线才增加部署与成本。向量计算和排序在当前授权集合内进行，不采用全局召回后删无权结果；近似搜索过滤造成召回不足时按授权集合精确查询或文本降级。

### 服务端 DeepSeek 与异步契约

拟新增 /api/ai-maps/development 与 /api/ai-memories 契约，包含 knowledge-status 和 evidence 辅助读取；作业区分 MEMORY_EXTRACT、KNOWLEDGE_INDEX、DEVELOPMENT_ANALYSIS、MEMORY_FORGET。复用生命周期，旧区间接口继续供其他业务使用。密钥在服务端环境，输入字段白名单与敏感过滤，模型无数据库凭据。两端只展示校验后结论，流式消息可报告阶段，不直接渲染未经检查的模型内容。

### 删除先停用、后清理

遗忘立即阻止检索和结果提交，再异步清理切片、全文/可选向量索引、图谱、摘要、缓存及检索/分析快照。排除规则和墓碑防止回填、索引重建与乱序事件复活；来源和权限变化使依赖结果失效。索引滞后只允许预算内直读当前有效记忆，不回退旧内容。删除自己的分析记忆不删除公司正式事实，作用范围明确。备份恢复先重放遗忘记录；不承诺撤回已发往供应商的数据。

## Risks / Trade-offs

- [中文检索召回不足] → 用目标标签和关键词补充全文检索，以中文评估集验证，再决定分词或嵌入扩展。
- [检索未命中却编造方向] → 返回信息缺口；按人工标注评估 Recall@K、引用正确性与事实支撑程度。
- [索引乱序或不同版本混用] → 保存来源/切片器/检索器/嵌入版本，复核有效版本，重建后切换读取版本。
- [图投影延迟] → 返回投影版本，滞后时不使用旧关系结论；按授权文本检索降级。
- [误把观察当事实] → 记录 provenance、claim_type、来源版本与候选状态，确认不自动升级为事实。
- [权限在生成途中变化] → 输入、提交、读取与 SSE 终态重新鉴权，失效结果不得返回。
- [自动提取费用增加] → 事件去重、增量提取、批处理与公司/用户预算，失败可暂停重试。
- [单容器多进程耦合] → Neo4j、PostgreSQL、Redis 共用一个 data 容器，独立卷、认证与联合健康，入口处理信号和进程退出联动，限制图数据库内存并验证重启。

## Migration Plan

1. 新增 OpenAPI 和下一版本迁移，保留原业务表和区间 AI 接口。
2. 加入事件提取、入库规则、记忆版本、排除策略与证据切片，先处理新事件，再分页回填和建立文本索引。
3. 在同一 data 容器部署 Neo4j、PostgreSQL、Redis，构建投影并验收版本、索引重建、授权文本/图检索与融合排序。
4. 接入 RAG 发展分析与记忆管理，在功能开关下完成引用、召回、纠正和降级验证；可选向量另行启用评估。
5. 两端切换为单一页面，旧演示行动清单不转入成果记忆。
6. 回归、恢复演练、文档同步后按流程归档。

回滚通过关闭生成与投影消费者、保留数据库新增表实现；继续提供基础日志和任务。不回退删除/排除规则，不恢复已遗忘记忆，不把旧演示结论作为回滚数据。
