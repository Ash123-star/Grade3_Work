## Why

用户希望 AI 地图只围绕一个功能：持续记住个人与公司做过的事，基于可追溯的经历、成果和目标分析发展方向。现有三个入口及区间 AI 总结缺少长期记忆机制，不能支撑跨项目成长分析与持续纠正。

## What Changes

- **BREAKING**：AI 地图收敛为单一“成长与发展地图”，移除堵点风险、行动规划独立入口及演示行动清单；建议作为分析内容展示。
- 建立个人与组织分域的记忆知识库，分为原始资料、精选记忆和检索索引；规则/AI 提取候选，服务端校验入库，能力观察待确认，关键组织陈述独立审核。
- 使用 PostgreSQL 保存权威记录与证据切片、Neo4j 保存可重建关系投影、服务端 DeepSeek 提取和生成；文本 RAG 与授权图谱检索融合排序，有限上下文生成带引用的分析，未命中说明信息不足。
- 首期关键词/全文检索，后续按评估可选 pgvector 与独立嵌入模型；纠正和遗忘同时影响切片、全文/可选向量、图谱与历史分析，排除规则防止重建复活。
- 增加异步发展分析、记忆管理和反馈契约，所有输入、图遍历、输出及缓存均按实时权限校验。
- 实施根目录《AI地图长期记忆技术方案.md》及《方案.md》的 AI 规划；按用户要求 Neo4j、PostgreSQL 与 Redis 同数据容器运行，分别认证并保留独立数据卷。

## Capabilities

### New Capabilities

- `ai-long-term-memory`：记忆知识库入库、来源切片与索引、文本 RAG 与受限图检索、引用与效果评估、发展分析、纠正和遗忘闭环。

### Modified Capabilities

- `data-infrastructure`：单容器从 PostgreSQL/Redis 扩展为 PostgreSQL/Redis/Neo4j，验证三进程联合健康、持久化与退出联动。
- `ai-map-direction-ui`：用单一发展地图替换三个入口，个人/组织切换仅改变数据范围，证据与记忆管理作为辅助交互。

## Impact

涉及 Flutter AI 页面、Web AI 页面、Spring Boot 入库/索引/RAG 作业与权限服务、PostgreSQL 增量迁移、outbox 消费、Neo4j 同容器部署、OpenAPI、中文召回和引用评估。pgvector 与嵌入模型作为可选依赖，首期不增加独立向量服务。既有区间 AI API 保留供日志等业务使用，新增独立契约，不把旧输出当成事实记忆。未完成变更不归档；实施任务按实际验证更新。导航遵从 AGENTS.md：左至右导图、视图、日志、AI地图、我的，默认导图。
