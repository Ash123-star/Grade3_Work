## Context

导图使用通用 PageBody 的纵向 ListView 和 Wrap，卡片按内容定高、底部固定留白 96，无法利用视口剩余高度。四块标题位于图标下方，预览固定 take(3)。

## Goals / Non-Goals

**Goals:** 图标与标题横排；四块等高填充可用区域；内容区使用剩余空间；小屏和大字体可访问。

**Non-Goals:** 不修改其他页面布局，不新增接口、审核流程、Web 页面或 AI 能力。

## Decisions

- 导图单独使用受视口约束的 Column，两行 Expanded 的 Row 各包含两个 Expanded 卡片。保留页面最大宽度 760，间距 12；替代按内容高度的 Wrap，保证整屏适配。
- 问候区缩小插画和间距。常规高度下不滚动页面；极矮屏幕按字体缩放设定最小可用高度并允许外部滚动，避免强行压缩导致溢出。
- 卡片标题使用 28 像素图标、横向标题；底部保留查看全部，中间 Expanded ListView 使用全部已加载记录而非三条截断，长标题最多两行。
- 派发按钮仍位于右下角，仅有权限时为其预留 72 像素底部区域；无资格时仅保留 12 像素边距。
- 数据范围仍由现有 recordsProvider 和服务端授权决定。审核版本、跨端数据契约无变化；DeepSeek 密钥仍由服务端管理，页面不调用 AI。

## Risks / Trade-offs

- 大字体横向空间不足 → 标题可换行，页面具备最小高度和滚动兜底。
- 已加载条数少于服务端总数 → 查看全部进入原列表，不承诺首页自动加载后续页。
- 布局改变影响点击和滚动 → 运行现有布局及 UI 测试，并在 Android 模拟器检查四块和派发按钮位置。
