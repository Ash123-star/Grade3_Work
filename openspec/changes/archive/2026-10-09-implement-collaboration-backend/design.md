## Context

方案.md 为基线，现有 mobile/docs/API_CONTRACT.md 是演示契约。已有独立数据基础包采用另一套 UUID 表结构，本后端采用独立 deploy/backend、Redis 配置及 Flyway 空库，不覆盖数据基础包。后端为单公司起步，所有业务记录仍带 company_id。

## Goals / Non-Goals

目标：真实 PostgreSQL 持久化、Redis 限流、五角色鉴权、业务闭环、独立审核、通知统计、AI 草稿及可运行验证。
非目标：Flutter 网络接入、Web 页面、短信供应商、厂商推送、跨公司匹配、生产域名上线。

## Decisions

1. Java 21 + Spring Boot 3.4 + JDBC + Flyway 模块化单体。业务字段使用 JSONB，所属公司、用户、版本、状态、时间等查询约束使用实体列；SQL 查询先过滤公司及范围，不依赖客户端。
2. 不透明随机 Bearer 会话，数据库只存摘要。每次请求读取当前角色、组织、账号状态，停用和调岗即时生效。BCrypt 密码；初始化仅在数据库无管理员时根据环境变量创建，不公开默认密码。新用户 pending，唯一手机号，不模拟短信。
3. Android/Web 共用 /api 的显式 REST 契约，列表为 items/total/nextCursor；与演示 command DTO 的映射在前端 data 层完成，不修改演示界面。统一错误含 traceId。
4. 私人备注和未提交日报永不穿透。管理者范围由部门/团队计算；任务接收范围独立于任务参与可见范围。汇报循环和跨公司关联由服务端校验。
5. 组织/权限/公司展示/提交日报修订/任务关键修订生成候选版本。审核按团队、部门、指定复核人排队，去重并排除申请人；无公司独立复核人时待审。事务和版本比较保证旧值在最终通过前生效。员工注册时自动提交归属申请，由初始化管理员独立审批；确认归属后员工可申请复核职责，由管理员独立审批，不赋予管理角色或公司业务读取范围。管理员申请的后续配置可交由该指定复核人处理。
6. 任务流转事件支持接收、反馈、验收、归档；列表不暴露完成情况。派发必须带幂等键，同键异内容冲突。事务 outbox 到消息表，提醒去重；SSE 从已投递通知按递增序号重放，避免内存广播丢消息。
7. 日志按 businessDate 唯一；日周月计算 Asia/Shanghai 边界再转 UTC，周一起算。统计及导出用相同范围，返回分子分母和更新时间。
8. DeepSeek 密钥仅在服务端环境变量。请求先筛选日志、任务、个人重点，保留明确来源，不传手机号和私人备注。异步 job 保存脱敏输入、输出片段和用量；流式 HTTP 读取 SSE，超时重试仅在尚无输出时，取消中断请求。Redis 按日预留 token 预算，数据库保存用量，结构校验后仅生成建议，确认命令再进入正常任务权限和幂等路径。

## Risks / Trade-offs

- 首次独立复核人配置死锁 → 员工本人提出职责申请，管理员作为独立审核人审批，正式组织修改仍走审核。
- AI 供应商不可用 → job failed 可重试，日志任务事务完全独立。
- 大组织分页与权限查询 → 查询先限定范围并限制页长；后续根据真实负载优化索引。
- 外部生产凭证缺失 → 本地模拟 DeepSeek 验证流式和失败分支，正式接入需配置真实密钥。

## Migration Plan

Flyway 初始化版本化表和部门；环境变量初始化管理员；Compose 使用独立卷/端口。部署前备份，回滚应用不倒退数据库，破坏性变更使用后续向前迁移。验证脚本使用独立测试数据库。

数据库追加公司关联复合外键、任务主负责人唯一约束和公司复核策略版本。复核策略仅可调整任务的团队/部门层级，公司独立复核不可关闭；策略变更本身沿用候选和审核流程。AI 建议编辑校验来源及版本，保留原生成时间并记人工编辑时间；重建该 job 的候选节点时清理相关旧关系，避免悬挂连接。
