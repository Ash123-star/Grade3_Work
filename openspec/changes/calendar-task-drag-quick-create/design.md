## Goals / Non-Goals

**Goals:**

- 在现有 Flutter 月历上提供可预期的长按拿起、目标日期反馈、跨周／跨月移动和空白长按创建。
- 只平移排期，保持已有任务时长、时刻、人员、标签、内容、附件与生命周期不变。
- 通过服务端鉴权、版本控制、持久化幂等和审核闭环保证正确性；正式日期始终来自服务端生效版本。
- 补齐本链路的区间查询、旧接口兼容、取消恢复、可访问替代操作及真实链路证据。

**Non-Goals:**

- 边缘拉伸、日／周时间轴分钟级拖动、批量移动、重复任务、离线自动写入、外部日历同步。
- 更换月历库、重做主题、重排五栏导航、接管 D 的溢出／节假日或 B 的人员／多标签设计。
- 在下属工作台开放创建／拖拽写入，或改变任务改期权限、审核层级及免审策略。
- 在任务派发表格增加完成情况或替代状态字段；新增 AI 调用、客户端密钥或外部服务。

## Decisions

### 1. 在现有月历中增加交互层

| 路线 | 取舍 |
| --- | --- |
| 扩展现有 Flutter 月历，提取拖拽控制器与几何命中接口（采用） | 保留现有条带、颜色、周首、主题和记录计数；便于与 D 共享布局，但需明确滚动坐标与手势所有权 |
| 更换第三方整套日历 | 自带拖动能力可能较多，但现有月格、溢出、字体与滚动规则需要重做，首批成本和回归范围过大 |
| 前端改日期后直接更新展示 | 无法保证审核、并发及跨端一致性，不能满足本批验收 |

沿用 Flutter 原生长按拖拽与 Overlay 能力，不引入新的外部日历依赖。建议提取 `calendar_drag_controller.dart` 与纯函数 `calendar_schedule.dart`；任务条带及单元格提供可复用命中区域，拖拽控制器不在绘制组件中处理 Repository 或业务写入。

D 提供“可见日期→屏幕矩形”和当前纵向滚动控制接口；C 消费同一套几何数据。日期落点、任务条带和 `+N` 区域按绘制层级命中，避免在任务文字上误触空白创建。共享组件增加显式 `readOnly`／交互回调，成员工作台保持只读。命中基于真实布局尺寸和字体缩放，不按屏幕宽度写死坐标。

### 2. 以抓取日期计算平移量

拖拽数据至少包含任务 ID、服务端版本、会话标识、原起止时间、按下的业务日期 `anchorDate`。长按跨周／跨月续段时，锚点是手指实际命中的那一天，不能把续段起点或任务首日强行吸附到手指下。

平移量为 `targetDate - anchorDate` 的上海业务日数。服务端在 `Asia/Shanghai` 下对有效 `startAt` 和 `deadline` 同时 `plusDays(moveDays)`，再以带时区时间／UTC 保存；空开始时间保持空。客户端以相同纯函数预览，但服务端重新计算权威候选。

日差使用无时区的年月日序号计算，客户端可用 UTC 构造日期标签后作整日差，不能用设备本地午夜的秒数差向下取整，以免设备处于夏令时地区时偏移一天。开始时间存在时必须严格早于截止时间；相等或倒置的存量区间保持只读并提示不可移动，不自动修正。

例：任务为 11 月 2 日 09:00 至 11 月 4 日 18:00，用户拿起 11 月 3 日的条带并放到 11 月 5 日，应得到 11 月 4 日 09:00 至 11 月 6 日 18:00。跨月、跨年、闰日按日期运算；历史任务起止倒置、时间无法解析或计算越界时拒绝移动并说明原因，不修补原数据。零位移在客户端结束预览，服务端也拒绝零位移请求。

任务排期以 `startAt/deadline` 为本批权威字段；日／周展示中的 `endAt` 不引入新的业务结束时间语义。具体时刻保留，首批不新增“只能移动到未来”的限制；沿用既有时间合法性规则。

### 3. 手势和交互状态

长按采用 Flutter 默认阈值 500ms、边缘热区 40dp、停留 500ms 后启动自动滚动。任务条以原片段尺寸浮起 8dp，不通过缩放暗示时长变化；跨周续段保持同一任务身份和日期锚点。

| 状态 | 事件及行为 |
| --- | --- |
| `idle/pressing` | 阈值前的移动交给普通滚动；短按沿用现有点击行为；已知无权限或只读场景不拿起任务 |
| `dragging` | 一次轻微触觉反馈；浮动预览略高于触点，显示原排期／目标日期；原任务保留弱化参照，目标高亮；暂停页面横滑和普通点击 |
| `dragging` 的边缘停留 | 同一指针持续停留时调用既有纵向滚动；每帧更新真实命中日期；离开热区、松手或取消即停止，不叠加第二套翻月动画 |
| `confirming` | 合法非零落点打开确认，显示原／新排期并要求原因；此时结束 Overlay 和自动滚动。取消不发送请求 |
| `submitting/unknown` | 单次交互只发一个命令；禁重复确认；断网／超时保留同一命令和幂等键，提示“提交结果待确认”，可同键重试 |
| `pending` | 以原生效日期显示任务，可在详情／提示中查看改期候选和审核申请；不把候选作为第二条正式任务绘制 |
| `applied/rejected/failed` | 重新读取任务与审核结果；生效后刷新日期，驳回／冲突保留原服务端值并说明原因 |

无效落点包括月标题、底部栏、弹层、没有完成加载的月份及网格外；松手在这些区域不申请。加载失败的相邻月可重试，不能用空数据冒充可落点月份。连续月份滚动、相邻月份日期区域的具体绘制由 D 维护；C 不启用当前仍为空白占位的格子作为假日期。

多指插入、系统返回、应用切后台、路由变化或会话变更均清除拖拽态和计时器。提交前取消不产生业务写入；请求发出后关闭页面只结束本地展示，不能承诺撤销已送达服务端的申请，恢复页面时继续确认结果。

### 4. 兼容扩展专用改期接口

| 路线 | 取舍 |
| --- | --- |
| 兼容扩展 `/reschedules`，新增互斥日期平移模式（采用） | 复用 `RESCHEDULE` 权限、`TASK_RESCHEDULE` 审核类型与时间线，保持旧客户端只改截止时间的行为 |
| 复用 `/revisions` 提交整份候选 | 开发量看似小，但会重验或替换人员、标签、附件等字段，扩大日期拖拽的写入范围 |
| 新增独立移动接口与新审核类型 | 隔离明确，但需要新增审核种类和更多公共契约，本批没有必要 |

新增请求模式：

```http
POST /api/tasks/{id}/reschedules
Idempotency-Key: <同一次移动持续使用的键>
If-Schedule-Constraints-Match: <读取到的约束版本>
Content-Type: application/json

{"version":7,"moveDays":2,"reason":"项目排期调整"}
```

- `version` 为正的 32 位整数；`moveDays` 为非零 32 位整数，拒绝布尔、字符串和浮点数的隐式转换；计算结果须在服务端声明的日期范围内。新模式的 `reason` 去首尾 Unicode 空白后为 1–1000 个 Unicode 码点；不改变旧模式的校验规则。
- 新模式只允许这三个业务字段，拒绝同时传入 `deadline/startAt/candidate` 或人员、标签、权限、状态等额外字段；无效模式不得回退到截止时间修改。
- 保留旧请求 `{"version":7,"deadline":"2026-11-06T18:00:00+08:00","reason":"..."}`，旧模式不新增幂等键必填要求，其已有审核记录保持可处理。
- 新模式要求 1–128 个可见 ASCII 字符的 `Idempotency-Key`，不允许空白或控制字符；客户端使用安全随机 UUID，不用时间戳独立充当键。返回既有审核申请结构，`id` 表示审核申请 ID，不是任务 ID；客户端按审核结果解释 `status/target_id/expected_version`，不能将返回记录当作已移动任务。
- 使用既有 `GET /api/reviews/{id}` 查询已确认的申请状态；超时且未取得 ID 时重放相同命令确认。收到旧服务端“不支持字段”响应时明确提示功能尚未可用，不能静默降级成只移动截止时间。
- 列表及详情增加服务端计算的 `capabilities.reschedule` 动作权限，基于新模式部署开关、最新身份、可读范围和 `RESCHEDULE` 规则；同时返回 `scheduleConstraints`。它不是任务完成情况，不作为派发表格列。能力或约束缺失／无效时保守禁用新写入，避免假定功能已部署。

HTTP／错误语义沿用统一错误模型及 `traceId`：

| 情况 | 结果 |
| --- | --- |
| 无效或失效会话 | `401`，停止交互并清理受保护本地状态 |
| 可读但无改期资格、待确认／停用／失权 | `403`；跨公司或不可见任务按现有隐藏资源规则返回 `404` |
| 缺字段、非整数／零位移、混合模式、无效时间 | `400`；新增错误码 `INVALID_MOVE_DAYS/INVALID_RESCHEDULE_MODE`，复用 `INVALID_DATE/IDEMPOTENCY_REQUIRED` |
| 过期版本／当前状态不允许／同键不同内容 | `409`，区分现有版本冲突码、`INVALID_TRANSITION`、`IDEMPOTENCY_CONFLICT` |
| 同版本已有待审 MOVE／约束版本过期／分页快照已变化 | `409 RESCHEDULE_PENDING/SCHEDULE_CONSTRAINTS_CHANGED/CALENDAR_SNAPSHOT_CHANGED`，不能自动改意图重提 |
| 版本无法再递增／范围记录超过预算 | `409 VERSION_EXHAUSTED`／`422 CALENDAR_RANGE_TOO_DENSE`，不能回绕或截断 |
| 明确业务拒绝 | 撤除预览并展示服务端原因，不自动覆盖新版本 |
| 超时、断连、无法确认事务是否提交的 `5xx` | 视为结果未知，保留同键确认入口；不能仅凭传输异常宣称服务端未写入 |

### 5. 应用层负责原子性、幂等和审核

Controller 只做协议绑定和校验；改期应用服务编排事务、最新身份、任务读取／锁定和审核调用；纯领域函数计算日期；Repository 负责幂等记录、任务读写。HTTP Controller 与 `TaskApi`／应用接口统一委托，避免两条实现路径对平移候选解释不同。

新建 `task_reschedule_commands` 保存公司、申请人、键、命令摘要、任务 ID、审核 ID、创建时间。采用公司／申请人／键唯一约束，并对任务和审核建立公司一致的关联约束；按 `(company_id, actor_id, idempotency_key)` 查询重放，不从客户端接收公司或申请人身份。复用创建幂等表会混淆摘要版本与对象语义；新表使改期逻辑与既有创建记录兼容。

同键请求使用事务级串行锁／唯一约束，摘要覆盖任务 ID、版本、平移量、规范化原因和申请时约束版本，摘要算法／规范化版本落库并保留旧版本重放算法。先校验最新会话、公司、资源访问及申请身份资格；命中同键同摘要时返回原申请，不能因任务版本、状态、约束窗口或待审占用变化而把重放重新当作创建；同键不同摘要返回 409。新命令再校验部署开关、约束版本、业务版本和合法状态，服务端从任务列生成 before/candidate，在同一事务内创建审核申请及幂等记录；任一步失败全部回滚。新的幂等记录不能暴露给其他账号，保留期不短于对应审核记录，不能按客户端超时删除。

不同键的新命令在任务行锁内检查：同一任务同一生效版本最多存在一个待审 MOVE 申请，重复者返回 `409 RESCHEDULE_PENDING`，不自动替换、撤回或新增第二条。只有具备原申请读取资格时才返回其 ID，不泄露他人的原因或候选；旧版本待审申请不阻止当前新版本申请。同键重放先于该占用检查。创建侧在任务锁内不对既有审核行加锁，避免与审核侧“审核行→任务行”的锁顺序形成环路。

沿用 `TASK_RESCHEDULE`；新候选增加服务端生成的 `scheduleMode=MOVE/moveDays/startAt/deadline`，`before_value` 保存原排期。旧候选仍只有 `deadline`。审核生效适配层按候选模式处理：旧模式保持原行为；新模式再次核验申请人当前资格、任务版本和有效区间，在同一事务中更新 `tasks.start_at/deadline`、`body` 中对应字段及版本，追加一次 `RESCHEDULED` 事件、审计与 outbox 通知，其他字段和生命周期不变。

无独立审核人继续待审，自审拒绝，驳回要求原因，审核时版本冲突不得写入。不同申请基于同一版本并发通过时，最多一个能生效，另一申请显示冲突，不能覆盖后续版本。审核链选择始终由已部署公共审核服务负责，本变更不手写新的通过／免审分支。

客户端提交前持久化最少命令信息和键，复用受保护本地存储按公司／账号隔离；不得保存访问令牌于命令体，不把业务原因写普通日志。前台恢复时恢复未知结果确认；退出账号清除对应本地交互数据，禁止跨账号重放。确认待审后保存审核 ID，使用既有通知刷新，并在页面恢复／主动刷新时查询审核和任务，不能只依赖 SSE 一次事件。

### 6. 月历必须从服务端取到完整相交区间

兼容扩展任务查询 `GET /api/tasks?from=<带时区时刻>&to=<带时区时刻>`，范围 `[from,to)`，两者必须同时存在且 `from < to`，单次跨度最多 62 个上海业务日；与显式旧 `date/period` 日期过滤同时提供时拒绝歧义，旧请求行为不变。Controller 自动填入的默认 `period` 不视为用户混用过滤。任务 `startAt/deadline` 为包含结束日的排期端点，查询条件为 `COALESCE(start_at,deadline) < to AND deadline >= from`；缺开始时间按截止时刻处理。恰好开始于 `to` 的任务不属于该范围，截止于 `from` 的任务属于起始业务日。

保留当前服务端 task scope、参与人过滤及稳定分页，`ownerId` 保留为经同样范围校验的 `participantId` 别名。本批不新增成员工作台写入或重定已有成员筛选；若后续实现成员查询，继续使用其独立授权契约。列表追加动作字段不返回任务正文；任务管理只读phase按2026-11-05确认的任务查询契约提供，派发表单仍不接受状态；动作资格批量计算，避免逐项重复读取身份／组织资料。

任务范围查询第一页返回 `snapshotToken`，新版月历后续页携带原令牌（旧客户端无令牌仍可按原契约读取）。采用只读一致性事务，在同一数据库快照内计算“公司／用户／当前授权上下文／规范化过滤／有序任务 ID 与版本”的摘要并读取总数及该页；后页重新计算，变化返回 `409 CALENDAR_SNAPSHOT_CHANGED`。令牌不是授权凭证，每页仍校验最新权限。只在 task 范围查询增加该协议，不建设新的游标平台、Redis 快照服务或全局授权版本系统。

客户端增加任务月历专用完整读取适配，保留 `readCompleteList` 已有的总数、重复记录和游标循环保护；不改变日志／人员分页语义。快照变化时丢弃本轮部分结果，从第一页最多自动重读 1 次，仍变化则显示重试态。正常结束须同时满足实际条数等于可信总数且页链结束，不能仅凭总数相等忽略额外页；零记录首屏必须为空且无后续页。未知筛选必须明确报错，不能静默忽略后把其他人的结果标为该成员。

审核生效后失效原／新日期覆盖的已加载月份缓存、当日清单、任务列表与详情，主动读回服务端。待审不改动日期缓存，撤销或驳回也不伪造日期变化。另一客户端刷新后读到同一生效版本；双端一致性用 Android 与独立 HTTP 客户端验证，已有 Web 入口可加抽验，本批不新增 Web 页面。

### 7. 空白创建复用既有表单

新增明确的 `initialBusinessDate`／等效路由参数，仅在“新建任务”初次初始化时消费。表单显示所选日期并把截止时间选择器定位该日，具体时间由用户确认；不擅自填人员、生成开始时间或自动提交。开始时间继续遵守既有选填规则。用户后来手动改日期、取消时间选择、表单重建或服务端失败，不得把其输入重新覆盖为最初所选日期。

空白命中优先排除条带、`+N`、日期上的既有按钮；允许有任务单元格的剩余空白。长按期间开始滚动或多指操作则不创建。表单继续使用 B 的人员／多标签契约、附件上传和校验、既有创建幂等及审核结果解释：返回创建待审时只提示待审，正式任务在服务端生效后才进入月历；取消或校验失败不生成正式任务。

快捷创建权限等同现有派发权限；待确认账号、无派发资格、只读成员工作台均不开放。用户经受支持的创建入口打开表单时服务端仍需鉴权，不能凭日期参数扩大权限。

### 8. 可访问性与验收安排

保留现有点击入口，通过任务语义操作／详情动作提供“移动到日期”，复用同一确认和服务端命令；对跨日任务，替代操作明确选择新的开始日期，无开始时间任务选择新的截止日期。该动作独立于旧详情的截止时间改期表单，不恢复转派入口。提供可读的原／新排期与结果反馈，不依靠颜色或触觉传达唯一信息。减少动画时保留目标反馈并弱化位移动画，字体放大不压缩到不可读。

按批准批次先实现再集中验收，实施期间只做解决具体阻塞所需定向检查。验收包括日期纯函数／权限和幂等单元测试、Widget 手势与路由测试、HTTP 契约测试、真实 PostgreSQL／审核整合测试、至少一条 Android 入口至数据层系统链路。Mock 只证明交互及适配。

真机／模拟器记录 360／390／412dp、1.0／1.5 字号、跨周跨年和加载失败、返回与切后台；TalkBack 能完成替代操作，主要操作触达至少 48dp。安全验证越权与调岗失权；可靠性验证提交成功响应丢失后的同键重放及并发审核；性能用 profile 模式记录连续跨月拖动 10 次，目标设备 60Hz 下超过 16.7ms 的帧比例不高于 5%，不出现超过 100ms 的持续卡顿，记录设备、样本和结果，未达到则保留任务为未完成。

### 9. 健壮性边界、资源预算与范围冻结

**日期边界必须显式。** 列表在页级、详情在响应中返回 `scheduleConstraints`：业务时区、`minDate/maxDate`、约束版本、查询／记录上限。日期采用真实 `YYYY-MM-DD`，时间采用带时区 ISO 格式；禁止依赖设备时区或以 UTC 日期充当目标日。初始写入日期窗口沿用现有选择器：按服务端上海业务年 Y，包含 `[Y-2 年 01-01, Y+8 年 01-01]`；2026 年对应 2024-01-01 至 2034-01-01。该窗口只约束本批新移动目标及快捷创建，不禁止读取历史任务、不批量修正存量数据，也不为旧接口追加新政策。开始时间存在时，新起止日期都必须在窗口内。服务端跨年／配置更新导致约束版本变化时，拒绝旧约束提交并要求重新确认，不能自动夹到边界；提交携带 `If-Schedule-Constraints-Match` 头，服务端不信任客户端自报窗口。

月历日期选择调用显式传入服务端边界，并在调用前检查初值；禁止触发 `premium_pickers.dart` 的默认夹取，也不修改该共享选择器对其他页面的全局行为。对无效闰日、日期溢出、超长／非整数输入直接拒绝。对极端历史数据或未来时区规则中不能同时保持本地时刻和实际时长的平移，返回明确时间错误，不自动更正时刻。版本达到最大值不能回绕为负数或零。

新移动模式必须携带上述约束版本头，缺失／无效返回 `400`，新命令已过期返回 `409 SCHEDULE_CONSTRAINTS_CHANGED`；已存在的幂等命令仍以原约束头确认结果，不重新判定为新申请。快捷创建通过既有创建接口携带同一头，服务端校验新申请的约束版本及所选日期；不带该头的历史创建调用维持原契约。日期窗口是本次交互支持范围，不能替代公司／人员／标签权限校验。

申请生成时由服务端保存约束版本及窗口快照，连同候选保持不可变；审核仍重新校验当前权限、业务版本及时间合法性，但不会仅因日历跨年而改写已确认候选或把日期挪至新窗口。重新选择日期／约束后确认的新意图使用新键，结果未知的旧命令则逐字复用已持久化的原命令和约束头；两者不混用。

**预览与正式数据分离。** 拿起／悬停只更新控制器和 Overlay，不先写任务 Repository／Riverpod 正式缓存。因此取消或失败只撤除临时层，露出最新服务端值，不能把抓取时旧快照写回覆盖 SSE 或其他客户端已生效的新版本。若任务在拖动／确认期间已变更、撤回、归档或不可读，结束本次交互并提示重新读取，不自动把原日差施加到新版本。

**旧异步结果不得复活。** 异步完成前核验公司／账号、单调递增的会话代次、交互代次、请求代次及组件是否仍有效。A→B→A 切换、同账号重新登录、快速切月或旧请求晚到都不能靠相同用户 ID 判定仍有效；旧响应不得重开确认、跳回旧月、覆盖新数据或显示旧权限结果。屏幕旋转／尺寸变化重新计算命中区域，无法恢复真实几何时取消拖拽；键盘或弹层插入时不把下面日期当有效落点。

**网络与重试有上限。** 新移动单次请求超时初值 15 秒，含退避的单次前台确认预算 45 秒，最多追加 2 次同键确认重试；使用退避与随机抖动，`429` 尊重 `Retry-After` 且不突破预算。明确业务 `4xx` 不自动重试，权限错误立即停止。耗尽后保持“结果待确认”和显式同键确认入口，不能换键、无限轮询或冒充失败回滚。切后台停止确认重试；恢复前台后查询已知审核 ID，未知命令由用户继续确认，不实现离线任务队列。幂等本地保存失败时不发送请求，防止丢键后重复申请；新模式关闭时允许有资格用户只读重放已存在的键，未命中的键拒绝创建。

**滚动和读取有上限。** 自动滚动只使用一个 ticker，最高速度初值一屏／秒；离开热区、到日期边界、加载失败或交互结束立即停止。不因刷新、错误恢复或旧回调再次自行启动。新增预取仅限当前月相邻的前后各一个月，同时最多 2 个任务范围读取；不借拖拽无限预取未来月份。

本批任务范围查询初始上限为 62 个业务日、5000 条记录；一次完整读取最多 200 页，包含最多一次整轮重读的前台总预算为 45 秒。超过范围返回 `400 INVALID_RANGE`，记录密度超限返回 `422 CALENDAR_RANGE_TOO_DENSE`，客户端给出缩小范围／进入既有任务列表的入口。越界游标、重复游标、空页仍有后续、总数异常、重复 ID／版本、令牌缺失／变更、达到页数／时间预算但尚未完整结束均视为读取失败；不得截前 N 条当成功，也不得据部分数据计算 `+N`。总数相同但 ID 被替换或排序改变须由快照摘要识别。最后一个完整快照可在授权仍有效时作为标明过期的只读内容保留，刷新成功前不开放本次改期落点；失权则立即清除，不保留受保护兜底内容。

**快捷创建不扩大命中和写入范围。** 当日没有可用空白时，保留现有创建入口并传入所选日期，不把任务条或 `+N` 强行变成创建热区。只把合法的日期值传给表单；恶意／错误路由日期必须给出校验反馈，不回退到今天。用户手动修改后的字段不会被初值、重建、旧请求或切月重新覆盖。创建仍走已有幂等与审核，不把新移动的幂等表挪作通用表单平台。

| 范围 | 本批允许 | 本批禁止 |
| --- | --- | --- |
| 已有任务业务数据 | 同步平移 `startAt/deadline`，并维护版本、事件、审计和 outbox | 顺带修改参与人、标签、内容、附件、生命周期或完成字段 |
| 日期与权限 | 服务端声明边界并逐次鉴权；历史数据继续按既有范围只读 | 凭客户端日期／ID 扩权、夹取日期、自审或新增免审 |
| 月历和创建 | 现有组件的交互层、滚动适配、创建日期入参 | 重做 D 的布局／节假日，接管 B 的人员／多标签实现 |
| 查询与基础设施 | task 范围查询的一致性令牌与资源限制、新增专用幂等迁移 | 全局分页平台、全局授权版本系统、新消息队列／数据库或修改旧迁移 |
| 发布与回滚 | 兼容消费者先全量部署，再打开新模式；保留待审候选和幂等关联 | 旧审核实例解释 MOVE、存在未处理 MOVE 时直接退回旧审核代码 |

本节的超时、预取、页数和密度值为明确的初始工程预算，服务端／客户端配置和契约测试必须一致，调优记录在验证报告；不得通过静默截断或自动改日“满足”预算。验收门槛为每项正向／异常场景均有证据，权限、待审旧值、幂等、日期准确性、分页完整性或真实系统链路任一未通过即不得交付。

## Risks / Trade-offs

- [月历续段及连续滚动仍有历史验收缺口] → 与 D 统一组件与坐标契约，补齐本链路必需缺陷后才能验收跨月拖动；不把布局文档当完成证明。
- [当前用户工作区有其他修改] → 本次仅写独立 change，后续实施／提交前隔离修改，禁止混入他人配置或详情页改动。
- [新版候选被旧服务端审核代码忽略] → 扩展候选消费者先完成全量部署再开放新命令；滚动部署期间关闭平移入口，回滚前检查待审 MOVE 候选。
- [异步审核可能让用户误以为拖拽失效] → 确认前说明需审核，提交后显示待审提示与申请入口，保留原排期。
- [网络错误不能代表事务失败] → 持久化同一幂等命令，未知结果用重放确认，避免换键制造重复申请。
- [公共审核计划与当前实现不同] → 沿用已生效服务端策略；C 与 E 在实施任务 1.2 明确接入版本，跨模块差异留在待办，不自行更改策略。
- [新增动作权限与日期查询扩大回归面] → 只增加必要字段／过滤，保留旧模式回归测试；列表不增加业务状态列。
- [快照摘要增加范围查询成本] → 仅用于有上限的 task 范围查询，在同一只读快照内计算并设置查询预算；测量数据库耗时，不为此扩展成全局分页平台。
- [日期选择器静默夹取／设备跨年导致日期变化] → 使用服务端范围和约束版本，过期时重新确认；旧共享选择器行为不全局改动。

## 落点、读取及完整行修订（最终设计）

落点以实际抓取日为锚点，保持整段时长；最后已展示的不可变日期快照贯穿预览、释放和确认，显示整段候选范围。禁止释放坐标或滚动静默重算日期，也不以扩大后端限流掩盖重复读取。
