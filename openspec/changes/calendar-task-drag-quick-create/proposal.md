## Why

当前月历以任务展示和日期点击为主，用户调整排期需要离开月历操作，无法像苹果日历一样长按任务并拖到目标日期。根据用户提供的最新分工，成员 C 负责月历拖动与快捷创建；本变更为这两条交互建立可实施、可验收的前后端闭环，保持服务端权限、版本和审核规则。

## What Changes

- **C-09 补正：** 正式任务取消三行容量限制，第四行及以后全部展示；正式条与拖动候选共同决定周高度，取消后保留正式任务所需高度。

- **P0／C-09：拖动避让。** 用户于 2026-11-04 确认密集目标周应向下撑高。候选按日期区间进入空行，原任务不挪位；跨周／月分段由可变高度月份时间线承载。取消恢复，布局补偿维持手指日期。详见 `drag-lane-layout.md` 和 `verification-lane-layout.md`，接续 PR #67。

- **P0／C-01：任务长按拖动。** 在“视图→月”长按可改期任务条后拿起任务，显示浮动预览、目标日期与有效落点高亮；普通日期点击和现有详情入口继续可用。
- **P0／C-02：整体平移日期。** 以手指拿起时命中的业务日期为锚点，按上海业务日期计算平移天数；已有开始时间和截止时间同时移动，保持时长与时刻。跨周续段操作同一任务；历史任务没有开始时间时仅移动截止时间。
- **P0／C-03：跨月与手势协调。** 支持拖到可视区域边缘停留后自动纵向滚动至相邻月份，覆盖跨年和闰日；拖动期间协调日期点击、空白长按、普通滚动与页面横滑，避免误触。
- **P0／C-04：真实改期申请。** 松手到合法新日期后确认原排期、新排期与原因，兼容扩展既有改期接口，以版本号、幂等键和独立审核提交候选。待审时正式任务留在原日期；审核生效后按服务端结果刷新。
- **P0／C-05：失败恢复。** 覆盖取消、无效落点、同日无变化、失权、版本冲突和网络异常。超时采用同键重试确认申请结果，不生成重复审核或提前宣告失败、成功。
- **P0／C-06：长按空白快捷创建。** 长按某日单元格内的可用空白区域打开既有创建表单，带入该日期；有任务的日期仍可使用剩余空白。继续执行人员、标签、时间、创建权限和幂等校验。
- **P0／C-07：可用性与一致性。** 为精细拖动提供可访问的“移动到日期”替代操作；覆盖大字体、屏幕阅读器、减少动画、真实接口和跨端日期一致性。
- 补齐本链路必需的月历区间查询：按任务区间与月网格相交取数，保留原有日期查询兼容性、分页和服务端数据范围。
- **健壮性与范围约束：** 预览不修改正式数据缓存；异步结果按会话及交互代次隔离；日期边界由服务端声明，禁止选择器静默改日；限制同任务同版本的待审移动、网络重试与自动滚动资源；月历分页校验一致性，失败或截断时不把部分结果当完整数据。具体约束和异常场景同步到设计、规格及任务。

首批不包含任务边缘拉伸调整时长、日／周时间轴分钟级拖动、多选批量移动、重复日程、外部苹果日历同步，以及下属工作台的写入入口；D 的月历布局、溢出与节假日功能继续由对应变更维护。

## Capabilities

### New Capabilities

- `calendar-task-drag`：月历长按拿起、日期锚点、跨周跨月移动、反馈、取消恢复和可访问替代操作。
- `calendar-task-quick-create`：单元格空白长按、所选业务日期预填、复用创建表单与权限隔离。

### Modified Capabilities

- `collaboration-backend`：补充只允许日期平移的改期命令、服务端版本及权限校验、候选审核、幂等重放，以及月历区间相交查询的可验收要求。

## Impact

- **负责人及协作：** C 主责交互、任务改期服务、接口适配和测试；按本次最新分工，D 协调共享月历布局／滚动接口，B 协调创建表单／人员／多标签契约，E 协调审核及公共契约。仓库旧分工描述不自动扩大本次 C 的职责。
- **涉及模块：** Flutter `features/calendar`、`core/state`、Repository／模型、既有表单与路由；服务端 task 的 Controller／应用／领域／基础设施、既有 review 应用边界；新增 Flyway 迁移保存改期幂等记录。同步 SpringDoc、`docs/openapi.json`、`docs/backend-interface.md` 和验证文档。具体设计见 `design.md`。
- **修改边界：** 日期平移只允许更新起止时间及配套版本／事件／审计／通知；快捷创建只新增本入口的日期预填和约束校验，不改既有表单业务字段与授权。本次不改人员、标签、组织范围、审核政策、通用分页平台或共享选择器的全局行为；查询一致性及资源限制仅作用于本链路的任务范围查询。
- **复用和兼容：** 不更换整套月历，不复制创建表单；既有 `POST /api/tasks/{id}/reschedules` 的截止时间请求保持兼容，增加互斥的 `moveDays` 请求模式。不会以客户端提交整份任务内容的方式平移任务，以免误改人员、标签等字段。
- **关联变更：** 复用 `mobile-page-experience-refresh` 和 `mobile-calendar-readability-swipes` 的展示／滚动规则；`frontend-requirements-adjustment` 中停用旧详情改期入口的安排仍保留，本变更新增月历改期入口，实施时同步交叉引用。审核沿用已生效的服务端公共策略，本变更不重定审核层级或新增创始人免审例外。
- **实施基线缺口：** 原任务条使用 `IgnorePointer`，改期仅处理 `deadline`，HTTP 月历缺少任务范围语义，历史存在跨周续段失败。本次已实现对应接入和修复；实际验证范围及未通过项目见 `verification.md`，不能将实现等同于全部验收通过。
- **验收目标：** 在真实后端完成“拿起→跨月移动→确认→待审原位→独立审核→日历／详情／列表同步”的核心链路；覆盖快捷创建正向和无效输入、权限拒绝、并发与超时重放；提供安全、可靠性及可用性证据，Mock 和 APK 构建不能替代验收。
- **追踪与状态：** 更新于 2026-11-03（Asia/Shanghai），关联 Issue #58，Sprint 2026-11 月历交互，独立分支 `feature/58-calendar-task-drag`。主体已实施，真实 Android 跨月改期/独立审批/快捷创建链路及 Docker 边界专项已通过。全仓仍有失败，模拟器 profile 10 次拖动慢帧比例未达标，TalkBack/完整设备人工矩阵与 B/D/E 人工确认仍待完成。默认开关关闭；按用户 2026-11-03 授权已推送[草稿 PR #59](https://github.com/Ash123-star/Grade3_Work/pull/59)并以[中文评论](https://github.com/Ash123-star/Grade3_Work/pull/59#issuecomment-6596996618)列举工作，当前任务 35/40；保留未通过项并等待审阅，不归档。详细证据及交付门槛见 verification.md。
