# Design

## Context

2026-11-26 用户确认移动端首版、Web 后置，先完成 HTML 原型检查与评审，再迁移 Flutter。基线 `480d31a` 没有 CRM 数据接口；已有 Web 是默认关闭的候选实现，不是移动端交付。真实岗位权限与来源契约仍待 B/C/D/E 对齐。

## 移动原型与需求映射

维护入口：[交互原型](../../../mobile/prototypes/crm-customer-workspace.html)。本批视觉和交互已获用户授权；原型为合成数据，不连接后端。Flutter 迁移以原型评审为依据。

| 需求 | 页面与层次 | 验收 |
| --- | --- | --- |
| 个人/企业统一查询 | 公司原“今天”按钮位的“客户目录”入口，目录搜索、类型筛选，每页最多 4 条 | 返回保留条件、页码及位置 |
| 客户资料 | “档案”展示身份、负责人和授权联系信息，补充说明折叠 | 企业多联系人分行，未授权字段不渲染 |
| 商城会员、演出年卡和差异权益 | “会员”切换资格，显示有效期、计次/不限次和使用记录 | 过期提示，权益使用与活动参与分开 |
| 商城订单 | “业务→订单”，独立详情显示来源状态及获准金额 | 金额受限时不输出数值，不把订单额称为营收 |
| 赛演、私宴、企业参访、沙龙 | “业务→活动”，独立记录展示时间、负责人、参与员工 | 四类均有实例，客户与业务信息不堆在同一面板 |
| 服务是否完成 | “业务→服务”默认待完成，可切换全部；详情展示交付记录 | 活动结束或内部任务完成不自动等于服务完成 |
| 权限与失败 | 评审工具切换完整/受限合成响应、无权限、失效会话、空和失败 | 不把原型演示视为岗位授权或服务端安全验证 |
| 少跳转、少滚动 | 底部三分区，左上返回；业务每页 3 条；长说明按需展开 | 390×844 常用操作可达，320×568 和 1.5 倍字体允许必要滚动、无裁切 |

选择“目录→分区详情→独立记录”，避免全部资料展开成长页，也避免每一类都跳新页面。客户身份摘要常驻，业务正文只在记录页。返回恢复原分类、分页和滚动。使用现有自有鸭系素材与主题 token，不新增第三方资产。

提示分层：整页失权/会话失效替代内容；来源不可用/请求失败留在当前分区；无结果提供清空条件；补充说明折叠。底部弹层仅作短筛选。触控目标至少 48px，支持键盘、焦点恢复和 Escape 关闭。

本批修改原型 HTML/CSS/JS、验证脚本及现有规格/索引，不修改 Flutter 正式代码、后端或数据库。用户继续授权新增/编辑客户、企业联系人维护及公司入口的原型设计；核销、导入、合同及绩效仍不在范围。权限演示不定义真实岗位政策。

### 客户维护与公司入口

2026-11-26 用户更正入口布局：撤销独立客户卡片，复用现有按钮排。本轮只调整 HTML 原型；正式 Flutter 的日期状态、日历滚动/拖动、任务派发和权限行为不变。原型月历/日周安排仅用于布局和入口恢复演示，不宣称实现正式日历功能。

- 公司页沿用现有 DateControls 的年月栏、日/周/月切换和双按钮操作排：左侧“派发任务”保留，右侧原“今天”替换为“客户目录”；“今天”移至顶部年月筛选栏右侧，视觉为小按钮，点击区域仍为至少 48px。不增加客户卡片、欢迎插画或额外入口区域，日历占据剩余主体空间。新增只放在客户目录，待完成服务沿用目录筛选；目录顶部返回公司时保留日期、视图和滚动位置，底部新增与分页保持分行，详情档案标题旁编辑。主导航依旧五栏。
- 新增/编辑采用独立短表单而非多步向导；名称为必填，负责人示例默认陈晨，电话与企业初始联系人可后补，备注折叠。编辑锁定客户类型，商城会员、权益、订单状态均不在表单里。企业联系人用短弹层增改，超过两条收起更多。联系方式为脱敏既有值时仅展示旧值，留空表示不替换，不把脱敏文本写成完整号码。
- 保存只改变页面内存，刷新重置，界面明确说明。不访问真实服务或持久存储。模拟成功、失败和版本冲突；失败保留输入，冲突要求用户重载资料后重做，不能直接覆盖。授权示例中查看与维护独立；联系字段受限时不显示或改写该字段。
- 相同规范化名称或已知电话只提示可见范围内的疑似重复，不自动合并；可在短弹层查看已有档案摘要后返回原表单，或明确确认“仍新建”。最少必填和负责人默认是可逆原型假设，实际字段规则、版本/幂等、审核及字段写权限需 B/C 对齐，不能把原型保存视为真实客户维护完成。
- 验收覆盖公司→目录→新增、年月切换/今天回跳、返回恢复日期视图、个人/企业新建、详情编辑、联系人增改、重复核对、取消保护、字段错误焦点、保存失败/冲突、只读及受限字段；新增成功进入详情，目录保留原筛选，编辑返回原档案位置。弹层支持 Escape，退出未保存内容需确认。

## Flutter 迁移边界

原型布局已获用户确认。Flutter 原生组件逐一对应原型：公司沿用日历及日期状态，客户入口复用原按钮位；目录和详情使用相同的页长、固定底栏、卡片、颜色、圆角、字体、提示和弹层。浏览器评审工具不进入页面布局，系统状态栏和返回手势由设备承担。客户详情仅在左上角保留返回目录入口，底栏只保留档案/会员/业务及业务分页，不再预留第二行返回；Android 系统导航区延续底栏表面色。

A 阶段未确认完整的移动 CRM 正式读写契约，选择在既有 `USE_MOCK` 模式运行原生页面和账号范围内的临时数据，不向候选地址写入。合成数据不持久化、不上传。以下 D 批次接入已确认的客户读取及线下业务契约，其余 A 联调事项仍独立跟踪。

## 产品界面与联调交接

Flutter 面向用户的页面不显示构建环境、样例或原型标记，也不提供切换测试角色、账号、场景和派发资格的入口。保留真实业务需要的空、失败及权限提示。选择字段统一使用 `PremiumDropdownField` 的底部弹层，取消不修改原值。HTML 保留评审工具；`USE_MOCK` 中客户修改只在当前进程内生效。正式构建只开放已有授权接口，不回退到样例。

## Goals / Non-Goals

### 二期 D：线下业务与服务交付（#109）

以公司、C 的 `customerId` 和用户 ID 关联单一线下记录，客户和负责/参与员工均可作为查询入口，返回同一个记录 ID。首版支持赛演、私宴、企业参访、沙龙。复用 `customer_progress` 会混淆自由文本进度与交付事实；新建跨域汇总服务会阻塞其他成员接口，选择独立模块、同库复合外键和按需查询，不改 C 的状态和接口。新增 V41，保留客户及历史员工关联；回退应用可保留新增表，不回写已发布迁移。

创建时活动为 `SCHEDULED`、服务为 `PENDING`。管理员直接建档；编辑基础资料、结束活动、确认交付均须填写理由、提交当前版本及幂等键，复用审核事务和 outbox。只允许已有活动结束后单独确认交付；审核前不修改正式记录，驳回保留旧值且需理由。每条记录同时只允许一项待审变更；交付后仅可审核修改标题、日期及人员，不能重置状态或更换所属客户。

首版仅本公司 ACTIVE 且已改密的 ADMIN 可查看、创建、提交和决定；直属上级也必须满足同样条件且不是申请人，否则保持待审。申请人可按修复后的直属关系重新分配，也可撤回；申请人失权后，同公司合格管理员可清理待审项，不可借清理读取候选或代审。撤回标记为 `SUPERSEDED`，不改变正式记录。审核列表、详情和推送按当前授权过滤；失权后不得读取候选或作决定。变更生效时再次校验版本、身份及适用的客户和员工状态。操作幂等键按公司及操作者隔离，相同请求返回提交时的回执、不同请求重用键返回 409。正式状态以详情为准，跨公司查找按不存在处理。

Flutter 复用现有公司入口、C 客户分页、CRM 分层组件、真实会话和审核入口。增加客户业务列表、员工视角、独立详情及申请表单，保留演示分支和五栏导航。不接入合同、权益核销、商城、内部任务、绩效或奖金。统一验收包括真实 HTTP/PostgreSQL 主链路及权限、版本、幂等，以及 Flutter 正式客户端的交互、小屏大字与会话切换。

客户浏览、搜索、类型筛选、上下页、分层详情、维护交互和公司入口。已完成审批的 HTML 布局是 Flutter 迁移依据，真实客户维护接口为后续批次。非目标：订单导入、核销、统计营收、归档合同或改变管理员授权。

## Decisions

以下为已实现的 Web 候选与公共读取设计；平台方向以上方移动端优先决策为准。

1. **独立 `/crm` 模块及其会话。** 将 CRM 塞入管理员后台会混淆管理员资格与客户查看权；新建独立站点又需第二套构建、路由和部署。复用 Vue/Vite 及同源登录，有独立路由、会话存储键与构建开关 `VITE_CRM_ENABLED=true`。沿用 ACTIVE、已改初始密码的认证前提；不假定任何业务角色有读权。若入口有变，只调整前端入口，后端政策不受影响。
2. **统一客户投影＋按需读取记录。** 备选为浏览器并发调用五个模块接口，能快速并行但会增加请求数、权限判定分散、产生多个查询口径。推荐由服务端归集授权后的首屏投影，各卡片仅在打开时查详情。不做数据库或公共权限变更。联调路径及字段集中于 `web/src/crm/contract.ts` 与 `api.ts`；这些是 A 的候选输入，供 B/C/D/E 对齐，不写入正式 OpenAPI 快照。
3. **授权数据优先。** 服务端在响应、计数、搜索、分页和深链处均须检查当前公司、客户范围、字段、关联关系；`403`/`404` 不泄露对象是否存在。界面对可选字段只按实际返回展示，不用角色、空字符串或默认值推导权限。不信任未约定字段、无效 ID 或记录类型；不可用状态不绘制残留数据。无持久客户缓存，请求中断和序号防止旧请求覆盖当前会话/视图。浏览器只暂存此入口的令牌，登出撤销并清空界面。
4. **候选契约。** 目录 `GET /api/crm/customers?search=&type=&cursor=&limit=20`，合法类型 `PERSONAL|COMPANY`，游标可选、由服务端提供前后页；返回 `items/total/nextCursor/previousCursor`。详情 `GET /api/crm/customers/{customerId}`，基础字段和 `memberships/benefits/orders/activities/services` 投影；每类为 `AVAILABLE`（授权条目或空）/`RESTRICTED`/`UNAVAILABLE`；有限条目可由服务端标示是否还有数据，首版不以局部列表计算总数。单记录 `GET /api/crm/customers/{customerId}/records/{kind}/{id}`；只有服务端显式返回 `canOpen: true` 时在列表提供入口，深链再次鉴权。字段和标识见类型定义；只读无写入、版本、幂等键、迁移或 outbox；读响应应禁止存储。过期会话 401，拒绝 403，找不到 404，其他失败可重试。金额仅展示授权来源文本，不作为财务营收。
5. **回滚与验收。** 将入口开关移除可关闭，不留迁移或生产数据。Playwright 使用合成契约响应测试 1440/390/320px、键盘、权限状态、失败/重试和路由；这些只验证客户端交互，真实角色越权要在后端完成后再测试。无真实接口时页面反馈失败，不回退模拟客户。

## Risks / Trade-offs

- 若 B/C/D/E 确认的协议不同，调整适配器并重放浏览器用例，不把候选结构当服务端已发布能力。
- 被裁剪的关联记录需后续确定完整检索方式；不得把当页数量称为总数。
- 移动端优先已由用户确认；Flutter 布局已按获准原型迁移。真实客户字段权限及源系统是否有权开放尚待确认；这影响真实接入与发布，原型合成数据不能证明已授权。
