# Design

## Context

基线 `480d31a` 没有 CRM 数据接口。分工文档以 Web 独立授权入口为建议，甲方角色矩阵和商城联调未确认。因此本批只实现可关闭的独立客户端与契约夹具，实际部署保持关闭。

## Goals / Non-Goals

客户浏览、搜索、类型筛选、上下页、关联记录跳转及授权失败反馈。非目标：维护客户、订单导入、核销、统计营收、归档合同、改动 Android 或管理员授权。

## Decisions

1. **独立 `/crm` 模块及其会话。** 将 CRM 塞入管理员后台会混淆管理员资格与客户查看权；新建独立站点又需第二套构建、路由和部署。复用 Vue/Vite 及同源登录，有独立路由、会话存储键与构建开关 `VITE_CRM_ENABLED=true`。沿用 ACTIVE、已改初始密码的认证前提；不假定任何业务角色有读权。若入口有变，只调整前端入口，后端政策不受影响。
2. **统一客户投影＋按需读取记录。** 备选为浏览器并发调用五个模块接口，能快速并行但会增加请求数、权限判定分散、产生多个查询口径。推荐由服务端归集授权后的首屏投影，各卡片仅在打开时查详情。不做数据库或公共权限变更。联调路径及字段集中于 `web/src/crm/contract.ts` 与 `api.ts`；这些是 A 的候选输入，供 B/C/D/E 对齐，不写入正式 OpenAPI 快照。
3. **授权数据优先。** 服务端在响应、计数、搜索、分页和深链处均须检查当前公司、客户范围、字段、关联关系；`403`/`404` 不泄露对象是否存在。界面对可选字段只按实际返回展示，不用角色、空字符串或默认值推导权限。不信任未约定字段、无效 ID 或记录类型；不可用状态不绘制残留数据。无持久客户缓存，请求中断和序号防止旧请求覆盖当前会话/视图。浏览器只暂存此入口的令牌，登出撤销并清空界面。
4. **候选契约。** 目录 `GET /api/crm/customers?search=&type=&cursor=&limit=20`，合法类型 `PERSONAL|COMPANY`，游标可选、由服务端提供前后页；返回 `items/total/nextCursor/previousCursor`。详情 `GET /api/crm/customers/{customerId}`，基础字段和 `memberships/benefits/orders/activities/services` 投影；每类为 `AVAILABLE`（授权条目或空）/`RESTRICTED`/`UNAVAILABLE`；有限条目可由服务端标示是否还有数据，首版不以局部列表计算总数。单记录 `GET /api/crm/customers/{customerId}/records/{kind}/{id}`；只有服务端显式返回 `canOpen: true` 时在列表提供入口，深链再次鉴权。字段和标识见类型定义；只读无写入、版本、幂等键、迁移或 outbox；读响应应禁止存储。过期会话 401，拒绝 403，找不到 404，其他失败可重试。金额仅展示授权来源文本，不作为财务营收。
5. **回滚与验收。** 将入口开关移除可关闭，不留迁移或生产数据。Playwright 使用合成契约响应测试 1440/390/320px、键盘、权限状态、失败/重试和路由；这些只验证客户端交互，真实角色越权要在后端完成后再测试。无真实接口时页面反馈失败，不回退模拟客户。

## Risks / Trade-offs

- 若 B/C/D/E 确认的协议不同，调整适配器并重放浏览器用例，不把候选结构当服务端已发布能力。
- 被裁剪的关联记录需后续确定完整检索方式；不得把当页数量称为总数。
- 甲方入口、真实客户字段权限及源系统是否有权开放尚待确认；这影响启用和放行，不阻塞关闭状态下的客户端实现。
