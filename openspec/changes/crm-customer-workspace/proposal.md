# Proposal

## Why

P0 / 成员 A / 二期 / #105。运营查一个客户时需要跨商城、活动和人工记录找资料，难以区分没有记录和没有权限。先完成独立的 CRM 只读查询端，供联调时组合真实关联记录。

## What Changes

- 2026-11-26 用户确认移动端首版、Web 后置。先完成奶油黄 HTML 原型，经检查与用户评审后迁移 Flutter；已有默认关闭的 Web `/crm` 保留为后续参考。
- 移动客户目录支持搜索、类型筛选和短分页；客户详情按档案、会员、业务分区，具体业务记录独立展示，底部提供常用切换与返回。
- 统一详情区分会员资格、权益、订单、活动和服务进度，展示服务端授权返回的字段；清楚区分未授权、未接入、空结果和失败。
- 首版查询只读；原型使用标注的合成数据，正式 Android 接入待原型评审与真实契约确认。B 的权限矩阵、C/D/E 的数据写入、实际接口上线和最终云端联调不在 A 当前实现内。

## Capabilities

### New Capabilities

- `crm-customer-workspace`：移动端优先浏览授权客户及对应业务记录，Web 后续补齐。

### Modified Capabilities

无。

## Impact

移动 HTML 原型、分层交互及验收规格；已有 Web 入口、视图和只读客户端契约保留为后续候选。不增加后端表、权限规则、外部调用或 Flyway 脚本。真实验收依赖后端成员确认协议并实现公司、数据行、字段和记录关联权限。
