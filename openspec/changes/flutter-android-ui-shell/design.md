## Context

产品方案要求交付 Flutter Android 软件，导航从左到右为“我的、AI 地图、日志、视图、导图”，默认进入导图。导图需要展示公司十大重要展示项、公司十大派发任务、个人十大重要展示项和个人日志；管理者在有派发资格时看到圆形加号。公司区域只读，个人重点和日志可编辑。当前没有移动端工程，因此本变更先解决工程、页面、视觉和接口边界，不把 mock 数据当作真实业务数据。

## Goals / Non-Goals

**Goals:**

建立可直接运行的 Flutter Android 应用；完成五栏导航及其所有方案中明确的主要页面；统一轻松可爱的卡通风格；让空、加载、错误、无权限和无数据状态完整可见；为每个业务域提供可替换的 repository 接口和 mock 实现；确保后续真实 API 接入只需替换数据源。

**Non-Goals:**

本阶段不实现真实登录、服务端鉴权、数据库同步、DeepSeek 调用、推送、文件上传和最终生产素材采购；不把静态 mock 数据作为验收完成的后端功能；不改变 Web 端实现。

## Decisions

1. **工程结构。** 使用 `mobile/` 作为 Flutter 工程根目录，按 `core`、`features`、`shared` 和 `data` 分层。页面只依赖 feature controller/provider，controller 依赖 repository 接口，mock 与 Dio 实现可替换。这样可以先完成界面评审，再逐域接入服务端。

2. **路由。** 使用 go_router 配置根壳层和五个 StatefulShellBranch，保持各 tab 的导航栈。初始 location 为导图；未登录时预留认证重定向，但本阶段用本地假用户进入应用。

3. **状态管理。** 使用 Riverpod 管理当前用户、权限快照、导图卡片、日志草稿、日期范围、任务表单和 UI 状态。权限状态由 provider 统一提供，页面同时依据状态隐藏入口并在调用 repository 时保留拒绝分支。

4. **视觉系统。** 使用 Material 3 ThemeExtension 定义奶油白背景、薄荷绿、珊瑚橙、深色正文、圆角、描边和阴影。建立 `CuteCard`、`CuteIconButton`、`SectionHeader`、`StatusPill`、`EmptyIllustration`、`LoadingSkeleton` 和 `ErrorPanel` 等组件。卡通图标从本地 OpenMoji 资源读取，保留作者、来源和 CC BY-SA 4.0 说明。

5. **接口边界。** 为每个域定义 request/response DTO、分页结果、统一 `ApiFailure` 和 repository。Dio client 只处理 base URL、追踪 ID、超时和错误映射，不在客户端保存 DeepSeek 密钥。mock repository 返回带来源标记的演示数据，AI 页面明确显示“演示数据/建议草稿”。

6. **页面范围。** 五个主页面之外，补齐登录占位、任务详情与派发、日志编辑与历史、下属日志、审批列表与详情、消息中心、个人资料、组织穿透、设置和 AI 节点详情，保证导航点击后不存在空白页。

## Risks / Trade-offs

### 安卓端页面清单与接口接入

本次覆盖方案第一阶段全部安卓界面。第二阶段跨公司匹配不纳入首期框架。下面的页面可以通过独立路由、详情页或弹层实现，但每个入口必须有可操作的内容和返回路径。

| 业务域 | 页面与交互范围 | 预留接口域 |
| --- | --- | --- |
| 身份 | 登录、注册、部门选择、待确认、首次改密、会话失效、账号停用 | /auth |
| 导图 | 四象限、各象限全部列表、展示详情、私人备注、个人重点新增编辑排序归档、独立公司发布入口 | /dashboard |
| 任务 | 授权列表、派发表单、分组选择、人员搜索、附件选择、详情时间线、接收、成果反馈、验收、转派、撤回、改期 | /tasks、/organization |
| 日志 | 我的日志、下属日志、人员选择、编辑草稿、关联任务、提交、已提交详情、修订历史、已读、评语、周报月报、AI 总结预览 | /logs |
| 视图 | 日周月切换、日期选择、任务和日志混合时间线、详情跳转 | /logs、/tasks |
| AI 地图 | 今天三件事、关系图、过滤、节点详情、来源跳转、风险解释、步骤拆分、任务草稿、建议确认、生成中、取消、失败重试、预算限制 | /ai、/ai-maps |

| 审批 | 待办、已处理、我的申请、前后版本对比、审核链、通过、填写驳回原因、修订重提、版本冲突 | /reviews |
| 管理 | 部门团队维护、员工归属确认、角色与派发资格配置、直属关系编辑、账号停用、审核策略、审计详情 | /organization、/reviews |
| 分析 | 六项指标、区间与人员范围筛选、统计口径和分母、更新时间、导出请求与下载失败 | /analytics |
| 消息与设置 | 类型筛选、未读数、全部已读、通知跳转、字体设置、隐私说明、退出登录、素材许可 | /notifications、/auth |

API 契约需记录请求方法、路径草案、查询参数、分页、DTO、错误码、版本号和幂等键。草案不是已上线服务。日期使用业务时区计算后转 UTC，周一为周首；未来 Web 共用同一契约和日期口径。审批显示候选版本与生效版本，无独立复核人时保持待审，自审禁止；客户端无法代替真实服务端鉴权，mock guard 只用于演示与客户端测试。

卡通 UI 包以本地 Flutter package `mobile/packages/cute_ui/` 引入主工程，封装上述主题与组件；通过 `flutter_svg` 渲染本地 OpenMoji 素材。OpenMoji 是素材库，不应被描述成现成的 Flutter 组件库。实施时核对依赖兼容性和许可证、固定版本并提交锁文件；当前未下载资源、未完成依赖集成。全局以明亮中性色为底，薄荷绿与珊瑚橙作为强调色，卡通形象用于空状态和 AI 区域，长表单与审批正文保持清晰易读。

mock 模式通过独立构建配置启用，支持五角色与成功、无权限、空数据、断网等样例；真实模式不自动回落到虚假成功。公开注册没有管理角色选择项；短信未接入须明确不可用。上传、导出、登录和 AI 的演示结果不得冒充真实服务结果。

### 风险控制

- [风险] 页面较多，首期容易只做静态截图。→ 每页至少实现导航、返回、展开、筛选、日期切换、表单校验和状态切换等可验证交互。
- [风险] 卡通素材与正文混用导致可读性下降。→ 插图只用于空状态、引导和 AI 助手，正文使用高对比文字，点击目标不小于 48dp。
- [风险] mock 模型与后端最终字段不一致。→ 先固定 DTO 和错误码草案，并在 repository 层隔离，真实接口接入前不在 widget 中硬编码 JSON。
- [风险] 权限只做视觉隐藏。→ 所有写操作先经过 permission provider 和 repository guard；无权限分支显示明确提示并保留 403 映射。
