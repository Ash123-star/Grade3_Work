# Design

## Context

既有阳光纸张页面已重建，但草稿仍为明文偏好、会话仅内存；动机见 proposal。当前HCJ混合修改保留，新增模块依赖方向为UI→存储服务→Drift/安全插件。

## Goals / Non-Goals

为原生客户端补齐加密保存和重启验证，不增加服务端契约、离线业务缓存或权限授予。DeepSeek密钥继续只留服务端，与本地密钥完全无关。

## Scope and invariants

本变更只处理客户端本地状态。服务端仍是认证、组织范围和会话撤销的权威来源；客户端不得把本地恢复材料当作已授权身份。密码、DeepSeek 密钥、私人备注和日志正文不得写入普通偏好设置或日志。

## Decisions

| 路线 | 优点 | 风险 | 结论 |
|---|---|---|---|
| 继续使用 SharedPreferences + 自定义混淆 | 改动小 | 明文可读、无密钥生命周期、无法满足隐私要求 | 拒绝 |
| 仅使用 `flutter_secure_storage` 保存整份草稿 | 平台密钥保护简单 | 大文本/多日期查询差，无法可靠处理草稿版本和迁移 | 拒绝 |
| Drift 数据库保存 AES-GCM 密文，密钥由 `flutter_secure_storage` 保护 | 可查询账号/日期，字段密文，密钥不进数据库；可注入测试存储 | 增加 SQLite 与平台插件，真实设备需联调 | **采用** |

## Local data model

`drafts` 表仅含 `lookup_id`、`ciphertext`、`nonce`、`mac`。查找键是服务端地址、账号、业务日期或日志ID/修订基线版本的 HMAC，不明文暴露账号、业务日期、时间或字段名。加密 JSON 包含完整定位信息、字段、实际保存时间及已确认的服务端草稿ID/version。AES-256-GCM 使用随机 nonce，以查找键作为认证附加数据；读取验证标签与定位信息，防止交换密文。密钥由安全存储管理，HMAC 查找使用独立派生子密钥；丢失或损坏不静默重置数据库。

`session` 安全存储键只包含服务端返回的 token、expiresAt、accountId 和服务端地址，不缓存权限或业务数据。密码永不保存。启动恢复先读取材料，再调用现有 `auth/me`；401、身份不一致、过期或未知状态立即清除恢复材料并进入登录，待确认和强制改密仍进入相应安全页。网络失败显示验证恢复页并阻断业务，保留材料供明确重试。所有凭证操作串行，避免迟到写入重新保存已撤销令牌。

## Migration and compatibility

首次读取新库没有记录时，客户端只读取当前账号/当前业务日或当前日志/基线版本的精确旧键，先加密写入并回读校验，再删除对应旧键；迁移失败不删除旧值，并在编辑器明确提示。已存在新记录时只清理同一定位的残留旧键，不覆盖新密文。生产实现不再写入旧明文键；其他账号和修订版本只在本人读取时迁移，不批量删除。正式服务与演示的库定位隔离。提交成功才删除对应定位，失败后保留正文及已确认的服务端草稿 ID/version。测试提供内存 Drift executor 和可注入的安全存储，仍验证真正加密与 SQL，而非替代业务实现。

依赖实际解析成功：drift2.35.2、sqlite3固定3.5.1、cryptography2.9.0、flutter_secure_storage固定10.0.0、path_provider2.1.6。最新版sqlite3依赖meta与Flutter3.38.7固定meta冲突，secure_storage11的win32与既有file_picker10冲突，故使用兼容锁定版本；不升级Flutter或其他UI依赖。SQLite3原生hooks无需废弃sqlite3_flutter_libs；使用 Drift custom SQL 的小型 schema，免生成文件但保留 GeneratedDatabase migration/version 管理。SQLite 源由依赖官方分发，不引入 SQLCipher 编译链。AES-GCM 保护负载，数据库文件结构不是全文件 SQLCipher 加密，此边界必须在报告中说明。Android 禁用自动备份及设备迁移，避免只恢复密文或恢复旧会话；真实设备 Keystore 仍未验证。浏览器原型不使用不安全令牌持久化，本能力面向原生 Android。

假设：离线保存限本人已进入的编辑器；不新增离线业务浏览或自动提交队列。新旧字段与现有表单相同，变更不改公共 DTO、审核规则和服务器数据。对这些既有前端目标的实现属于用户已授权范围。

## Error and account boundaries

- 所有异步读写携带 accountId 快照；切换账号、退出或页面销毁后丢弃迟到结果。
- 读写失败显示邻近编辑器的恢复提示，不清空输入，也不伪造“已保存”。
- 清理会话只清除当前账号的安全凭证；草稿按账号保留，其他账号不可查询。
- 受保护恢复完成前路由只允许认证状态页；`auth/me` 成功且身份/状态有效后才进入导图。

## Verification

最终批次统一执行 `openspec.cmd validate --all --strict`、Flutter analyze、Mock/HTTP 测试和定向渲染；不构建 APK。验收覆盖密文不含正文/身份/日期、随机 nonce、交换/损坏密文拒绝、账号/日期/服务/版本隔离、迁移失败不删除、提交失败服务器版本重启恢复、启动网络失败/身份变化/待确认/改密/迟到响应、退出及旧会话失效不撤销新账号。非功能：隐私与可靠性；渲染小屏/字号 1.5。

## Risks / Trade-offs

- [平台密钥不可用] → 不降级为明文，保留内存输入并提示重试；真机验收保留为未完成。
- [历史明文文件/备份] → 精确成功迁移后删除旧键，禁用新自动备份；无法证明历史设备备份安全删除，报告残留风险。
- [SQLite hooks/原生插件] → SDK兼容依赖解析已通过，集中测试可验证SQL/加密；不将其当作Android打包验证。

## Migration Plan

新增客户端schema1，首次进入对应草稿再事务迁移，旧数据库不存在无需服务器迁移。回滚前需保留新密文和安全密钥；旧版本不会读取新加密稿，因此不能仅回滚页面而承诺草稿可恢复。不删除用户数据库或密钥来掩盖错误。
