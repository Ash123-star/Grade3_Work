# Proposal

## Why

日志草稿和会话状态目前依赖明文 `SharedPreferences` 或仅存在内存中。设备被读取、应用进程重启或账号切换时，既不能满足产品要求的私密草稿保护，也无法在安全边界内恢复会话。阶段 3 审查已将这两项列为未完成能力，现在需要在不暴露密码和 API 密钥的前提下补齐。

## What Changes

- 增加账号和业务日期隔离的 Drift 本地草稿库。
- 使用平台安全存储保存本地加密密钥和可恢复的会话凭证；草稿正文以 AES-GCM 加密后写入数据库。
- 保留旧版本草稿的一次性迁移和错误恢复边界；迁移失败时保留编辑器输入，不把明文继续作为正式存储。
- 启动时读取受保护会话并通过现有 `auth/me` 验证，验证前不打开业务页面；退出、失效和账号变化清除会话恢复材料而保留其他账号的加密草稿。
- 为加密读写、账号/日期隔离、会话恢复失败和旧数据迁移增加单元及 UI 契约验收。

## Capabilities

### New Capabilities

- `secure-local-state`: 受保护的本地凭证、加密草稿和恢复生命周期。

### Modified Capabilities

无；不改变后端能力、接口或权限模型。

## Impact

- Flutter 依赖增加 Drift/SQLite、平台安全存储和路径支持；Android 需要随应用打包 SQLite 实现。
- 修改 `mobile/lib/core/state`、表单草稿保存、应用启动恢复和登出清理；不修改服务端、数据库迁移或公开接口。
- 现有 Mock 测试提供内存/测试存储实现，生产路径使用平台安全存储和本地数据库。真实设备密钥备份策略、系统卸载后的恢复和后端会话撤销仍需设备/服务联调。
