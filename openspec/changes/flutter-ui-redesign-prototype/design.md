# Design

## Context

已确认主题是阳光纸张、动漫橙、Q 版人物、圆润温和。详细规范为 mobile/docs/stage-2-sunny-paper-design-system-plan.md，官方参考为同目录 stage-2-ui-theme-research.md。本轮替代旧棕橙/薄荷绿、小圆角和等待主题选择方案。

## Goals / Non-Goals

目标：以鲜橙、奶油纸张、彩色语义容器和原创工作伙伴建立一致卡通主题，仍可清楚阅读任务、日志、来源和审核信息。

用户于 2026-10-12 授权继续完成阶段 3 设计，并按设计修改 Flutter，最后统一验收。实施范围为 mobile 的主题、公共组件、五个主页、日历、业务阅读/表单和成员工作台；不修改后端、数据库或公共 API，不下载竞品资产。完整页面契约见 mobile/docs/stage-3-page-layout-and-interaction-design.md。

## Decisions

1. primary #FF8A24，onPrimary #44210D，对比度 6.07:1；白字/鲜橙 2.36:1 不采用。
2. 普通卡 20dp、人物卡 24dp、按钮 18dp、字段 16dp，交互至少 48dp；正文保持可读。
3. 原创约 2.5 头身工作伙伴，welcome/writing/explaining/success/empty/retry 六姿态。仅真实成功庆祝；无权限、待审、失败不庆祝。
4. 选择 App 拥有 Material 3 与 SunnyPaperTokens，渐进适配旧组件。仅替换 cute_ui 常量不能消除静态令牌和页内色值；新增框架增加主题冲突、包体和维护成本，均不选。
5. 色彩、间距、形状、动效集中在 theme；公共组件集中 shared。保留页面事件/输入和 Repository 边界，主题不新增 HTTP 字段或业务状态。
6. 单一主题已选，不再要求多配色切换。旧 HTML 只有导航和提示，本轮不标记为新版原型完成。
7. 保留默认导图、两行两列四象限、左到右五栏、派发无完成情况、日志内下属入口、AI 带来源人工确认；AI 首屏信息架构在阶段 3 比较。
8. 新素材自有或官网/GitHub 且许可明确，本地打包；OpenMoji 保留 CC BY-SA 4.0。

## Risks / Trade-offs

鲜橙白字对比度不足，固定深前景并验证状态配对；角色/圆角可能占空间，360/390dp 及放大字体检查后调整预览条数。角色最终稿未制作，不以静态示意当生产资源。

原工作区存在用户未跟踪改动；Issue 未关联。本次不提交推送混合内容。路由/认证、日期一致性、真实 AI/附件及接口验收是独立缺口，不能随视觉任务勾选完成。

## Migration Plan

规范与 Issue → Material 3/ThemeExtension 和组件状态页 → 新 HTML 完整四象限/表单/失败恢复 → 导图与日志代表页 → 角色最终素材与其他页面 → 旧引用盘点 → 统一验收。阶段主题选择已确认，具体角色和组件截图后续评审；迁移调用方前不删除旧包/素材。

## Acceptance

规范严格校验；纯色色彩配对通过普通文本 4.5:1、关键边界 3:1。后续实现验证 360×800/390×844、1.0/1.3/1.5 字体、键盘、TalkBack、减少动态效果；验证正向提交及失败/冲突保留内容、权限与隐私；最终获取 analyze、Mock 测试、APK 和手工流程退出结果/证据。静态文档通过不等于 Flutter 交付。

## Stage 3 implementation batch

采用现有 Flutter primitives 和 Material 3，在 App 层拥有 SunnyPaperTokens；cute_ui 通过 theme extension 读取视觉契约，保留旧资产许可和未迁移 API。对比仅改包内静态色值的路线，App 层主题可避免业务页与包主题分裂，不需新增框架。

日历月视图采用手机七列网格和选日议程，周视图横滚时间轴；日志采用连续文档/行式历史；任务详情保留事件流转，派发列表移除状态筛选/标签。AI 优先三件事为本轮推荐默认布局，明确样例、来源与人工确认，真实生成尚未接入。成员工作台增加分类但不增加数据范围。

当前代码的日志日期混用在同批次修复，以编辑业务日期为提交日期；修改 UI 不新增后端契约。测试覆盖日期独立、非法工时、失败输入保留、无权限、窄屏放大文字及导航。完成整个批次后集中 analyze/test/build，编译发现问题后定向修正，不在编码过程中反复全量检查。
