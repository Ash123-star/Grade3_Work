# Design

## Context

动机和交付范围见 proposal.md。用户明确“认证、组织、审核一起规划，再分批实现”，并确认 MVP 分工优先、PRD 仅参考。工作分支为 lyb。Java 21、PostgreSQL 16、Redis 7 已可运行；当前全套集成测试 10 项中 9 项通过，任务转交用例因目标成员不在团队返回 INVALID_OWNER，需 C/E 核对夹具，不能删除范围校验换取通过。

auth/organization Controller 直接访问数据库；已有应用 API 不能单凭声明视为接入。review 有应用服务，但混合控制器、组织/日志验证及跨模块 SQL。实际数据模型以 server Flyway 为准，不能照搬 PRD 旧表名。当前组织树人员读取存在默认页大小截断风险。

## Goals / Non-Goals

目标：不改变已批准权限语义的前提下，建立可测试的服务调用路径、持久登录防护、组织完整性和审核一致性。三批共同遵守接口兼容与真实数据库验证。

边界：B 实现本模块规则；公共过滤器、身份上下文、统一错误和 OpenAPI 汇总由 E 协调；任务/日报应用由 C 提供接口；通知和 outbox 由 D 协调。此变更不调用 DeepSeek、不引入任何客户端密钥或 AI 功能。

## Decisions

### 1. MVP 优先并保持已有主规格

MVP 要求五角色、组织范围、分层审核、版本校验、自审禁止与驳回原因。比较“按参考 PRD 重写权限”与“保留当前主规格，补齐实现和证据”：推荐后者，避免 B 单方面改变 C/D/E 共用授权和审核语义。团队→部门→公司复核保持现行策略；同对象多候选仍依赖最终版本冲突拒绝。PRD 同对象单条待审、团队长无审核资格及同级访问禁令不加入本批。归属确认与角色变更按当前独立申请流程分开，不为对齐参考故事合并成高权限直接写接口。预置三个部门不解释为永远禁止维护部门。

登录五次失败锁十分钟作为明确的安全补充，单列规格、任务和测试；找回密码及短信不包含在本阶段。

### 2. 逐模块接入分层而非全库重写

比较仅增加 Controller 校验与拆出应用服务/领域规则/基础设施访问：推荐后者，以满足仓库约束并可单测。Controller 只做 DTO 校验、协议映射、当前身份提取；应用服务编排事务；纯领域规则处理密码防护状态、组织合法性、审核决定；repository 封装 SQL。沿用现有 API、数据库和 Spring Boot，不引入微服务。

每批先固定现有请求、响应及错误，再替换实际调用路径。既有 ActorContext 不包含全部认证元数据；注销的凭证参数、改密身份校验在 auth 边界处理，不擅自扩大共享 Actor 类型。与 E 确认已有 AuthApi/OrganizationApi/ReviewApi 的适配；公共接口变更必须在实现前形成契约记录。

### 3. 登录防护采用 PostgreSQL 持久状态

比较 Redis 计数与 PostgreSQL 独立登录状态：Redis 已存在且轻量，但需原子脚本、TTL 与持久化语义；PostgreSQL 可复用事务、行锁与真实集成验证，重启后仍保留锁定。推荐新增登录状态表，以规范化账号的不可逆摘要为键，记录失败数、锁定截止、更新时间；已知/未知账号都走统一失败响应。账号规范化必须与现有登录查询一致，不能悄悄改变账号大小写含义。

失败处理事务返回明确结果，事务提交后再映射 401，禁止在同一事务内先递增再抛异常导致回滚。首次并发插入用唯一键解决竞争，后续行锁更新；第五次失败设置十分钟截止，锁定中不续期，过期重置，成功清零。用可注入时钟覆盖边界，不通过测试睡眠十分钟。已验证正确密码但状态停用时拒绝登录并说明状态。已有 IP 限流保持，由 E 负责公共 Limiter；为未知账号状态记录设置清理保留期和容量验证，避免无限增长。

沿用数据库会话摘要存储，不改为 JWT 或 Redis 会话。注销数据库撤销可幂等；重复 HTTP 调用若已被过滤器拒绝，仍遵守现有未认证响应，不虚构 200 契约。账号停用、调岗、待确认和初始改密必须在下一次请求使用当前数据库状态，由 B 测试并与 E 协调过滤器缺陷。

### 4. 组织写入在审核通过时重新验证

候选创建及最终应用都检查公司、部门/团队关系、角色、负责人、汇报环、有效管理员数量。仅提交时检查无法抵御等待审核期间的组织变化。最终更新以公司级事务锁序列化影响最后管理员的操作，并使用版本条件更新；统一锁顺序避免死锁。读取从数据库带范围条件，不能先加载全公司再客户端过滤。分页或树完整性修复须与 E 确定返回契约，覆盖超过 100 人边界。

### 5. 审核使用现有候选模型与跨模块应用接口

比较在 review 继续直接更新所有模块表与通过模块应用接口调用：推荐接口调用，同步本地事务覆盖候选终态、业务新版本、审计及 outbox 写入；不采用异步最终写业务值，避免审核已通过而业务未生效。B 实现审核路由、权限、决定、版本检查与组织变更应用；C 实现 task/log 的验证和应用，D/E 协调事务 outbox。模块应用失败则本次审核决定回滚，旧值继续生效。

对申请加行锁并检查当前层级/当前审核人/版本，终态不重复处理；自审任何层级都拒绝，驳回原因 trim 后不能为空。缺少独立人保持待审，不默认通过。审核记录和事件不可包含密码、token 或秘密配置。既有任务复核策略和员工复核职责保持主规格，不新增未经要求的角色。

### 6. 三批验收与跨组回归

第一批认证：注册、登录、失败锁定、改密、注销、待确认限制；第二批组织：树/人员读取、关系维护与范围隔离；第三批审核：路由、通过/驳回、自审和版本并发、跨模块接口替换。各批均先单元测试，再真实 PostgreSQL/Redis HTTP 集成，再接口文档与证据更新。

安全验收至少包含角色注入、跨公司、跨部门、跨团队、待确认访问、自审、停用旧会话、调岗旧会话、旧 token、初始改密绕过、错误密码锁定和敏感字段泄漏。性能参考 PRD：20 并发、10 万日志/1 万任务背景数据，记录硬件、数据、预热、样本与关键组织/审核请求 P95≤2 秒；首页≤3 秒及全链路由 E 协作。本机资源不足可先小样本诊断，但不能代替规定规模证据。

## Risks / Trade-offs

- [已有权限与参考 PRD 有差异] → 保留用户确认的 MVP 与主规格口径，联调时解释差异，不宣称满足参考 PRD 全部条款。
- [账号锁定可被恶意触发] → 保留 IP 限流、统一提示、十分钟固定到期，记录清理和容量测试；不暴露账号存在性。
- [跨模块接口与共享设施非 B 所有] → E/C/D 协作项先形成 Issue，B 不接管他人业务或绕过公共授权。
- [当前全套测试存在失败] → 保留原失败记录并推动 C/E 修复；仅 B 定向通过不代表全套通过。
- [并发迁移编号冲突] → 每批实施前检查最新 Flyway 编号和其他成员未合并迁移，新增下一可用版本。
- [Issue/Sprint 尚未关联] → 提供待录入清单，实施前补真实平台编号；不编造编号或声称已发布。

## Migration Plan

先保留现有接口基线、测试结果和环境，再新增兼容登录状态迁移；每批运行 Flyway、定向及全套测试。旧会话与旧业务数据保持可读，新状态表无密码明文；迁移验收包括已有数据库升级及全新数据库初始化。

失败回退应用版本时保留新增表，不自动 drop 或修改已发布迁移；登录锁定属于安全行为，旧版本不识别时会失去防护，回退须记录该风险并限制使用。组织及审核重构尽量不改变表结构；若约束调整需要修复历史数据，先检测并报告，不能自动删除。完成代码与验收后再按仓库流程提交、推送 PR，归档前同步主规格并严格校验。
