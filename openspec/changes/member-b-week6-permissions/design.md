## Context

以 main 4ded9fc 与 week6 分工为依据。log 已有 submitted_at、LOG 审核与权限范围，缺少窗口和部门搜索；独立 web 复用 AI 业务接口且未限制管理员。标签模型尚由 C 开发。此前上下文中的职责限制由用户明确的新分工覆盖。

## Goals / Non-Goals

实现 B 的时间、数据范围及访问控制，保持旧客户端兼容。非目标为 Flutter 视觉、多参与人任务模型和 AI。标签权限必须在 C 的真实调用路径接入后才能勾选完成。

## Decisions

- 时间：选择服务端 Instant + 数据库首次 submitted_at，拒绝客户端时间。修订申请持有日志行锁后校验；最终审批不重新检查窗口（用户确认允许跨窗审核），仍验证版本与权限。撤回保留 submitted_at，重提以 COALESCE 保留首次时间；撤回后的草稿也不能绕过已开启的窗口。无时间的历史已提交记录保守拒绝。
- 查询：选择新增 departmentId/search 与 groups，同时保留 items/total/nextCursor，避免替换响应破坏客户端。分页单位仍为日志，groups 只分组当前页，同部门可跨页；公司与组织范围进入 SQL。无权或未知部门均空结果，不先查部门是否存在。部门归属使用人员当前部门，与既有 scope 保持一致；关键字按正文/姓名/账号匹配，长度上限 100。
- 标签：优先复用 C 的表与端口，不创建 B 私有标签表。创始人操作不由 ADMIN 泛化；标签分类范围与绑定时校验共用规则。接入前记录依赖，不把孤立 Policy 宣称功能完成。
- Web：选择独立 /api/admin/workspace/** 管理命名空间并委托现有应用接口，服务端按每次数据库读取的当前 ADMIN 校验；独立 Web 只调用受保护命名空间。拒绝用客户端头、User-Agent 或全局锁死 /api 来识别管理员，保持 Android 和 Flutter Web 联调能力。
- 安全错误使用既有统一响应；窗口过期 409 LOG_EDIT_WINDOW_EXPIRED，权限 403，未登录/停用 401。不显示版本但仍用 version 乐观锁。

## Risks / Trade-offs

- 与 C 共享 log/review 和迁移 → 小提交、增量接口、并行改动合并时重新核对；不修改公共 BackendIntegrationTest。
- 标签尚无主线契约 → 等 C 接口后集成；不重建平行模型。
- 日志公开评论、Web 任务审计展示未认领 → 单独登记待协作，不静默丢弃。
- 新窗口会拒绝旧日志修改 → 文档明确，不补伪造提交时间、不删旧内容。

## Migration Plan

### 后续已确认范围（2026-10-19）

用户确认等待 C 的标签及新任务审核契约；授权 B 实现日志公开评论和 Web 任务审计展示。评论公开范围不扩大日志权限，24小时后仍可评论和回复，不支持改删。比较新建评论系统与扩展现表，选择后者：V15 增加 parent_id 与同日志复合外键，保留旧评论。追加接口 text 限2000字、可选parentId；无幂等键，重复POST会产生独立评论。事务内锁日志防止与撤回竞态，通知作者与仍有权读取日志的被回复人，同人去重；不复制正文到通知。

任务审计选择复用 audit_records/review_requests，新增只读 task-audit 分页查询；只ADMIN、同公司，在数据库过滤后分页。包含任务直接事件、任务审核申请/决定和最终生效，返回操作者、时间、理由及前后值，页面不提供修改删除。优于新建审计表，可保留旧事件；C未来事件契约改变时需补充适配。任务ID可选过滤，越权和未知ID都返回空，禁止跨公司关联。Web提供独立任务审计入口、加载/空/失败状态及翻页，不依赖AI生成成功。

时间和查询复用现有字段；新增 V14__log_first_submission_window.sql 调整提交一致性约束，允许撤回后保留首次时间，已提交仍必须有时间。V14 在本次已抓取主线及 C 分支尚未占用；C 合并前必须重新核对编号。已发布迁移保持原样。回滚应用不删除任何历史、审计、业务数据。最终统一执行后端真实 HTTP/PostgreSQL 测试、Web 构建、OpenSpec strict；安全与事务可靠性作为两项非功能验收。
