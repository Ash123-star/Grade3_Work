# Design
2026-11-05节日显示修复：公司月历只标节日当天名称，不把连休或调休工作日标成节日，不加星标。客户端复用MIT许可的6tail/lunar公农历转换与节气算法，固定公历日期计算元旦、劳动节、国庆节，农历计算春节、端午、中秋，春节前一天计算除夕，清明采用节气日期；同日重合合并名称。范围1900–2100，包含相邻年份，越界明确提示且不生成日期。节日本日使用纯本地计算，不依赖服务器缓存、登录或设备时区；行政放假安排联网更新，保留独立展示行，不影响任务读取、折叠、拖动、审核和权限。

用户进一步确认联网优先、离线兜底：进入月历先显示本地节日计算结果，再读取本地持久缓存并并发刷新相邻年度的既有服务端公告。联网成功时用公告的isOffDay增加独立休/班标记，公告name不用于重复标节日名称；失败保留最近成功的缓存并提示，首次离线无缓存只显示节日本日，不猜调休。StreamProvider分阶段发布，不等待网络才展示本地日期。缓存仅含公共公告、不含用户/令牌，存储失败不得丢弃已获取内容。固定1900–2100算法范围，公告沿用2007–2100；部分年度未公布只影响对应年度休/班，不阻塞当前已有安排。过期缓存/离线说明统一在月历上方展示，不在每格填充警告。

路线比较：只使用服务端公告不能支持首次离线，单用历法不能预测每年行政调休；采用本地历法+持久公告缓存+在线刷新。新增一个锁定版本的Flutter依赖，无接口或数据库变化。库的MIT声明随依赖进入Flutter许可证登记，并在现有素材许可目录保留副本。仅调整节日数据层及日期标注，不修改任务/审核/权限及已有用户改动。
2026-11-05用户确认恢复五行折叠：保留跨周任务身份，按每日期最多五个任务展示行计算预览；超过五项为前四项加剩余数，点击进入完整日清单，不能截断服务端读取。节假日独立行不占任务容量，候选不计正式总数。小屏采用月份单一纵向滚动，不嵌套日格纵滑；具体候选几何与移动change协调，保持抓取日命中不变。旧完整行发布证据不证明本次目标已实现。
# Scope
2026-11-06月格溢出修复：原实现对`+N`额外预留至少48dp，造成忙周增高。改为所有周统一预留五个展示槽，基础高度只由视口和文字缩放决定；前四条任务与右下角黄色剩余胶囊分别占用独立空间。胶囊按bottom/right定位，不参与周高计算；拖动候选仍可扩展预览空间，底部预留胶囊高度避免覆盖。今天右上角复用Sunshine小黄鸭，日期标题预留侧边空间，休/班在同一标题区域中固定定位。公司页移除72dp浮钮占位行，完整月历可延伸到底栏上方，不改变读取、权限、计数、日期点击或任务拖动写入协议。本次仅编译，密集任务、大字体、节假日重合与浮钮点击等界面验收由用户执行。

公司月历展示元旦、除夕、春节、清明节、劳动节、端午节、中秋节、国庆节当天；连休及补班只显示独立休/班标记，不重复节日名。不新增其他纪念日、其他节气、拖动或审核变更。

2026-10-31 联调发现 raw 域名连接重置，同仓库 GitHub contents API 返回200。改用固定 contents 地址及 raw Accept，不接受用户 URL；完整响应6秒超时，流式累计限制256 KiB。回归修复范围包括主线旧审核夹具、Flutter正式/Mock模式分组及真实失败处理；不回退权限或放宽断言。

2026-11-06 部署核对发现两个环境相反：本地 API 容器 Contents 返回403限流而 raw 返回200；云端 raw 连接重置/Java超时，但 Contents 返回200及2026年39条安排。因此改为同仓库 Contents 优先、raw 兜底，固定官方地址、不传令牌、不接受用户 URL、不新增供应商。每入口仅一次、各3秒/256KiB，双源合计请求预算6秒，适配移动端8秒接收超时；连接超时仍为2秒。中断立即向上传播，不继续请求。仍校验年份、日期、重复项及国务院公告域名，两源均失败保留缓存并如实返回 STALE/UNAVAILABLE，不伪造调休。不同年份采用独立锁；客户端警告限定于月格可见年份。编译与实际部署核对记录见既有部署/验证文档，不运行测试套件。
