# Design

## Context

2026-10-23 用户授权按页面规划并逐点实施。17项包括后续追加的单级审核；每批只对应一个原始修改点，不能以“共享组件”把后续 UI 需求提前混入。2026-10-29 用户确认本批同时兑现六组 P0 服务端链路和 #17 正式审核行为。Mock只验证客户端行为，不能代替正式服务端授权、持久化或事务证据。产品代码完成后按仓库约束统一验收；规划阶段只运行 OpenSpec strict 校验。

事实：当前分支HCJ，已有前次任务未提交的 `mobile/handoff.md`；不覆盖或混入本次交付。现有月历为 `_MonthGrid` + `_monthLanes` + `_monthWeekBars`，单元格容量0–5，超额被跳过、跨周续段只有颜色；当前月只读按全月网格查询。任务管理是卡片与多行工具条；个人主页仍含公开重点/时间线；日志通过通用大表单、候选审批和已读登记；服务端资料PUT只支持介绍/头像；统计只有有限汇总；审核为团队/部门/公司多级。这些是修改对象，不当成待实现的新发现任务。

## Goals / Non-Goals

**Goals:** 原编号#1–#17全部可追溯；奶油白主题和五栏结构不变；先修月历再迁表格入口、日志、我的、下属、导图、全局文案及审核。服务端对新增时间/字段/审核规则真正执行，不能仅改按钮。

**Non-Goals:** 不复制飞书或Apple资产，不升级Flutter全栈，不重做独立Web视觉，不扩大任务查看范围，不删除旧日志正文/评论/历史，不将Mock转成正式回执；创始人免审不授予原本没有的组织/业务写权限。

**需求解释边界（2026-10-23复核）：** 用户原文及随后明确回答为业务依据，逐条见 `requirements-audit.md`。横向滚动提示、保存/取消、弹层关闭和长文滚动等仅为实现既定操作所需的易用性细化，不作为另增业务范围的理由。列宽、弹卡宽度、防抖时间等为可调实现参数，不是用户指定值；不得据此新增字段、另设审批、猜测工作日/权限或减少原文要求。发现无法依据现有数据满足需求时记录具体缺口，不以自选的弱化方案通过验收。

## Decisions

### A. 批次与验收策略

一个change容纳跨页依赖，用 `tasks.md` 的页面组和17个编号批次控制；#4重构表格，#5单独迁移入口（同时完成#4要求的去除原入口）。#12复用#1–#3月历，#11只改审批视觉，#17才改变审核策略。代码阶段不勾功能验收，不自动提交推送；最终统一验收后按仓库规范交付。用户明确要求覆盖技能默认“分组即测试”的建议，采用其集中测试安排。

用户后续明确：只用已有主题配置中的颜色；新增/重构可视控件采用项目定制的Apple式细腻交互，不直接使用Flutter默认成品外观。实现允许基础布局/绘制/输入/滚动原语承担组件底层，不新增一套配色或全局视觉。每点接通路径、异常边界并核对局部差异即停止该批，不提前测试，也不因尚未最终验收而重做该点。同一阻塞至多两次有新证据的定向修正，仍未解决则记录准确阻塞和依赖，不原地循环。明确阶段截至条件见tasks的执行边界，全部17点和统一验收证据齐全前不报告整个目标完成。

### B. 月历三批

1. **#1 +N**：用实际轨道结果计算当天隐藏任务数，先按当前可用高度分配全月稳定轨道；若该周有溢出，则为该周底部预留计数行，保留原轨道编号，仅隐藏超出预留后容量的轨道（最多5条），避免重新分配导致跨周胶囊跳行。N按本周最终轨道计算，包含为提示腾出空间后隐藏的记录，只统计当天合法不同ID未呈现的任务，不用标题是否显示判断可见。右下角灰色 `+N`，使用正文缩放后的行高，不与最后轨道重叠；整个单元格可点击打开原有完整日列表。极矮高度使用明确最小日格高度并让网格内部可滚动，不能缩字体或完全裁掉提示。不在本批修改续段名或切月方式。
2. **#2 续段名**：每周裁剪段左端均显示现有六字预览，`starts/ends`仍只表达真实任务起终点，避免重新起圆角暗示新任务。同周内无须每日重复；下周一重复；被隐藏续段计入#1。非法反向日期不绘制。
3. **#3 连续月份**：比较①仅替换月份+AnimatedSwitcher，简单但不跟手、难覆盖长跨月；②原生纵向惰性滚动月份列表，保留相邻月份、稳定高度和状态。选② `CustomScrollView`/sliver月份分块，连续上下流动；初始创建前后100年窗口，接近任一边缘时按100年扩展并锚定当前月份/格内偏移，因此没有产品层面的年份终点。一个纵向滚动坐标承载所有月份，不在月份内再嵌滚动。屏幕主要可见月份更新标题，箭头/今天滚动到目标月份/日期。每个月使用稳定 `ValueKey(year,month,owner)`；按相同正文最小行高计算4/5/6周月高度，文本放大或视口较矮时扩展该月高度，避免裁行/压缩。sliver缓存区预取相邻月份，加载失败用同尺寸奶油表面+重试，不清空当前月。月份任务查询按月历可见周的区间交集返回，不以截止时间落月筛选；缓存依当前会话仓库和月份键隔离账号。完成滚动前不销毁可见块。自定义快速回弹物理与系统减少动画适配，减少动画时仍可直接抵达。

服务端日期区间查询需按 `start <= rangeEnd && deadline >= rangeStart` 交集返回跨月任务，不能只按截止日落入本月查询。客户端返回字段采用上海业务日期并验证范围。新月第一个可见续段（包括月初非周一）重复名称；灰色相邻月日期也能正确承接合法跨度，点击后切到目标日期而不丢名。

手势：月份采用一个连续纵向滚动坐标，五栏仍横向；不得将#1的极矮月格内部滚动直接嵌入连续月份列表，形成内外两层争抢纵滑。日期弹层滚动不透传；连续滚动的短拖保留自然偏移，取消后正常停稳，不额外强制整月跳转；滚动位置独立于本人/成员。丝滑目标是原生连续内容、无空帧/黑背景与突换，帧率必须在最终设备验收取证，规划不虚报达标。最终须覆盖首次/缓存命中、稀疏/密集、上下连续十个月、快速反向、前后台和网络慢/失败，记录设备刷新率、帧时长及慢帧证据；出现可复现黑屏、空白中间态或明显跳变即不通过，不能仅凭AnimatedSwitcher或编译成功认定符合Apple式顺滑体验。

### C. #4 任务表格与#5入口

结构：唯一AppBar标题与返回 → 搜索 → 表格（无第二标题、概览、接收/发布切换、密度切换、批量工具栏、筛选按钮条或新增悬浮按钮）。重用奶油白背景、细灰网格、灰字表头与橙色小型筛选标记，避免复制飞书Web的高密度小字号。

表格字段以任务列表接口实际返回为准：任务名称、标签、参与人、开始时间、截止时间、派发时间（任务创建时间）。当前安全投影不返回正文、派发人或完成情况，表格不新增这些列，也不增加替代状态列。不能将ID当姓名；名称两行后省略，点记录可打开受保护任务详情。列宽与行高按手机可读性调整，横向滚动查看超屏字段。

实现采用SDK内置 `CustomScrollView` 懒加载记录与独立固定字段行，外层横向滚动保持列头和记录列同步；不为此新增依赖或升级SDK。

字段行固定；提供横向滚动条，窄屏可查看完整字段且不缩小字体。点任意列头打开主题化筛选弹层，支持该列条件与清除；多个列条件与全局搜索共同生效。基于完整授权分页，不从半页推算；身份变化即清理输入与结果。

#5将“任务管理”移到日周月切换下面一行左侧，“今天”右侧，两者48dp点击区；月份日期箭头另维持既有位置。日周月均显示，移除“我的”的链接与文案，`/me/tasks`旧深链可重定向到语义新路由，不重复入口。返回保留日期/周期/滚动和筛选。

调研来源：Flutter官方包 https://pub.dev/packages/two_dimensional_scrollables 、发布元数据 https://pub.dev/api/packages/two_dimensional_scrollables 、官方API https://api.flutter.dev/flutter/widgets/TwoDimensionalScrollView-class.html 。飞书帮助首页可访问但本次未得到冻结字段正文，故只按用户明确的飞书式表头/记录结构借鉴，不将未读取内容写成官方结论。

### D. 日志#6–#8

#6抽出专用 `DiaryComposerSheet`（建议名）复用现有安全草稿，不扩充通用表单。唯一标签/正文“今日工作”，右下提交；日期显示为紧凑只读上下文，历史记录字段不作为输入。灰黑遮罩复用弹层，关闭/返回/后台对最后文本排队加密保存；输入防抖300–500ms，关闭前flush，存储失败保留内存并显示重试。窗口高度用**未减键盘的完整屏幕高度**H，外层总预算2H/3，键盘K后输入高度 `max(0,2H/3-K)`；安全区纳入预算。K过高时提供收起键盘后继续编辑/提交，不超预算也不把正文强行缩小。滚动确保光标和提交可达，TalkBack可关闭键盘。提交成功仅清相同revision的本机稿，超时/409保留正文与版本；旧多字段草稿加密结构保留兼容，不展示其余输入。

创建加号、首页继续写、详情合法编辑、同步入口和旧 `/form/log`/修订路由按对象/日期导向日志页弹层，去掉旧完整写日志界面。不得误删其他任务、认证表单。

#7日志页保留清晰的日期选择入口，选任意有权查看的历史日期即可查看当日已提交日志；当天、昨天、前天无已提交日志时，加号在该日期上下文打开#6输入层补交。其他历史日期及未来日期只能查看实际数据/空态，不提供可提交入口；已提交日志按首次时间决定编辑能力，不能只按日期粗暴禁用。取消选日不改变原筛选，不因日期选择改变本人/下属数据权限。

两种更新路线：①客户端撤回→存草稿→重提，暴露中间状态且可丢可见正文；②服务端专用本人正文直接更新应用方法。选②，拟定 `PUT /logs/{id}/content`，请求 `{work,version}`，事务内校验本人、ACTIVE、业务日期/首次时间、乐观锁，更新正文/历史/审计/outbox，不能先撤回。首次提交仅今天、昨天、前天（上海）；提交后 `now < submittedAt+24h`可改，满24h拒绝；跨出三天仍有效，首次submittedAt永不重置。过期日志可读/评论，不可改。旧LOG修订新建入口停用/转明确错误；历史待审LOG候选不得在新规则下延迟覆盖直接编辑正文，需要标记失效或显式终止，不自动批准。旧日志的blockers/tomorrow/hours/taskIds保留历史，不破坏关系；新编辑只改work。只有该日志批次例外无需审核，其他业务仍按当时审核策略。

移动端适配器以 `Command('update-content', {id, work}, version, idempotencyKey)`调用上述HTTP契约；编辑器首次提交保留现有draft→submit链路，既有日志直接调用content endpoint。Mock校验本人、ACTIVE会话、版本、非空正文和首次提交24小时边界，成功只更新work/正文版本并保留`submittedAt`；同日志旧待审候选失效。正式服务端在本批实现对应三日/24小时/组织权限/历史候选失效能力，使用PostgreSQL事务和日志版本记录提供可审计证据。

#8详情移除旧额外字段与 `DiaryReadReceipt`/reading-history，不调用POST read；只保留“今日工作”单正文框、必要作者/日期/编辑能力和下方评论。合法本人点编辑时复用#6输入层，不保留另一套完整编辑页；过期或上级查看时正文框只读。历史数据与已读表不删；停用阅读登记后同步移除依赖该登记的日志待阅展示，不偷偷新增自动登记、已打开事件或以通知未读冒充日志未读。通知本身的未读机制不因本次变化被删。

### E. 个人资料#9

姓名/部门/职位/角色/组织归属仅展示并在编辑态变灰；介绍、电话、邮箱、性别、年龄、头像本人可写。电话是用户确认的可编辑字段，必须原子更新 `users.phone`（非仅profile展示值），复用唯一约束；手机号/邮箱格式和长度沿用现有契约，年龄拒绝负值与非整数，选填个人信息可清空，性别可不填写/不透露，不自行新增年龄上限或必填限制。修改电话不声称短信校验通过，若存在phoneVerified须失效并保留真实状态。邮箱无验证也不显示已验证。

比较①把所有字段塞profile JSON，电话身份不一致；②电话及组织字段归权威users，个人展示字段放profile并merge更新。选②，`PUT /profiles/me`扩展可写白名单、版本、字段级错误，保留现有介绍/头像及未编辑字段，注入name/department/position等返回400/403不静默接受。必要职位字段由受权组织维护来源提供，不从角色中文猜造；缺值显示未填写。

所有组织上级（直属及递归上级）可见联系方式：读取时求当前同公司reporting_relations祖先链，保留已有合法管理员组织管理权限；同部门平级不能借部门列表批量取得电话/邮箱。每次服务端查询/附件/缓存失效按当前关系；组织循环或缺失关系拒绝扩大范围。电话邮箱不因上级可见而自动开放给AI检索/普通日志。

本人主页删除公开重点/日志时间线读取，编辑在同一个Widget保持输入、保存/取消和409提示。头像点开受保护预览（右上更换），复用附件选择/格式上限/所有权检查；取消不改，更新头像时保留全部其他profile值。旧profile-edit深链归一到本人页编辑态。

移动端HTTP适配扩展现有 `PUT /profiles/me` 请求为 `{introduction, phone, email, gender, age, avatarAttachmentId, version}`，仅提交本人表单修改字段；Mock对本人写入、字段白名单、电话格式/唯一、邮箱格式和非负整数年龄执行校验。`GET /profiles/{id}`契约需在本人/实际组织上级范围内返回联系人字段，Mock以直属关系树验证可见成员；下属工作台头卡通过该profile读取接口补全电话/邮箱，不从组织列表推测或拼接。正式数据模型中 `users.phone` 是权威唯一手机号；新增 nullable `email`、`gender`、`age`、`employment_start_date` 列；简介和头像继续保存在 JSONB `profile`，更新时 merge 而不覆盖未提交字段。所有读取每次按同公司当前 `reporting_relations` 祖先链及既有合法管理员范围授权；平级、无关高职级及其他公司不得读取联系人。已有员工无可靠入职日时保持 NULL 并返回 `UNKNOWN`，不按迁移时间推算；新成员确认生效时将上海业务日期写入入职日期。

### F. #10统计与#11审批视觉

统计：去掉常驻统计说明/口径段，页头保留日期区间选择与范围选择；上方紧凑真实指标，下方三个主图。

- 综合分组条形图：按部门/团队/人员比较派发、验收、逾期数，用户可选系列，排序与长标签横滚/换行。
- 折线图：日粒度派发/验收/逾期事件量、日报提交人数/率趋势；日/周/月视图依明确粒度聚合，不把当前快照伪造历史逾期曲线。
- 扇形/环形图：选定范围任务阶段分布（接收前/进行中/待验收/已验收/归档/撤回等真实事件映射），扇区点选显示数量/占比，图例可开关；不是派发页面替代状态列。
- 必须覆盖的业务维度包括已确认的任务阶段分布、按期验收率、逾期趋势、日报提交趋势和部门分布；派发/接收/反馈/验收等真实指标可在这些图中选择。不能仅把同一个总数换三种图充数，也不能以新增多种图为由丢失原有按期验收率、日报提交率。无部门权限者保持既有访问边界，不为增加维度开放其他部门。
- 多维组合：上海日期范围 + 有权组织/团队/人员 + 指标系列，互相联动；条形/点/扇区点击展示数值、时间、分母/口径及同范围可分页明细；清除选择恢复全图。数据结构必须服务端汇总并返回维度、粒度、分子/分母、updatedAt，导出同范围。

### I. #17单级审核与移动端接口契约（用户追加）

替换现有团队→部门→公司route，不再通过多步链批准；审批页面、策略配置、通知、API与系统说明同步。用户已确认：**按配置的直属上级**，使用同公司 `reporting_relations.employee_id → manager_id`，审核人必须ACTIVE、不是申请人且关系仍有效；不按角色高低从同部门随机选人，不跳到祖先。缺失、停用、循环、自指、跨公司关系均保持待审并显示未配置，不自动批准；管理员也不默认免审。MEMBERSHIP成员确认保留有效管理员审批（ADMIN_MEMBERSHIP），不要求待确认员工先具备直属关系，也不适用创始人免审；无有效管理员时保持待审，不自动开通业务。

创始人只对自身已获授权的非MEMBERSHIP动作免上级审核：服务端重新读取有效FOUNDER身份，经过正常字段/版本/权限校验后，同事务apply、记录系统免审依据及APPROVED审计/outbox，0人工步骤，无“自己点击同意”或伪造上级。复用既有APPROVED状态，区分审计decisionSource=FOUNDER_EXEMPT，不用新状态值破坏旧约束。失败整体回滚、幂等不重复执行；普通用户自审仍禁止，管理员不自动等于创始人。

数据升级比较：①直接改所有历史审核steps，可能丢审计/重复apply；②历史完成链只读保留，新单级路由带策略版本，待审申请按确定规则转单级并保留旧步骤历史。推荐②：完成/驳回链不变；未决多级申请保留旧步骤审计、使未决旧步骤失效，重建唯一当前直属上级步骤；此前某一级同意不等于新规则已批准。用户未要求升级时批量执行创始人历史候选，因此迁移不得自动apply旧候选；有效创始人在新规则下明确继续/重新提交本人旧申请时，才按当前权限/版本校验并自动批准，已生效的幂等返回，冲突保留正文和错误，不迁移SQL直接改status。本人日报旧候选按#7失效策略，不参与自动通过。审核决定时重新验证直属关系和版本，变更后旧审核人不能继续审批；reroute保留历史不删已决定步骤。原本不需要审核的合法动作不因本次改造被新增审核步骤。

移动端先以以下统一契约接通Mock和HTTP适配器：`GET /reviews` 与 `GET /reviews/{id}` 返回 `applicant_id/name`、`status`、`reviewer_id/name`、`reviewer_configured`、`approval_mode=DIRECT_MANAGER/ADMIN_MEMBERSHIP`、`expected_version`、候选/当前值、理由及只读历史事件；可保留旧 `steps` 作为审计历史，但不得将其渲染为待办审核链。提交修改沿用各资源既有revision入口，由服务端根据登录身份和当前组织关系决定审核人；响应携带最终状态及 `decision_source`（普通单级为`DIRECT_MANAGER`，创始人免审为`FOUNDER_EXEMPT`）。审核决定沿用 `POST /reviews/{id}/decision`，请求 `{approve, reason, expectedVersion}`；不得由客户端传入或覆盖 reviewer。无直属上级返回待审及 `reviewer_configured=false`，不得自动批准；创始人走原有资源修改入口，由服务端身份校验后自动应用并返回已批准结果，不生成待审记录。Mock采用 `DemoAccount.managerId` 路由、同一版本/自审/驳回原因校验，并对创始人走直接应用分支。

### J. P0 服务端契约实现与数据库迁移（2026-10-29）

技术路线比较：①新建平行 v2 Controller/DTO 和一套新业务表，会增加客户端双栈、重复权限逻辑和回滚复杂度；②扩展现有 REST 资源与应用服务，仅新增兼容参数/响应字段和 Flyway 向前迁移。采用②：保留现有模块化单体、错误信封、认证 Actor、分页及事务边界；旧 `date/period` 调用继续有效，新 `from/to` 与组织筛选被正式绑定。数据库只追加 `server` Flyway 迁移，不改已发布版本或 `deploy/postgresql`。

- `GET /tasks/received-card` 返回当前 Actor 有权看到的全部已派发历史任务及稳定游标分页。字段至少含 `id/title/phase/dispatchAt/version`；`dispatchAt` 来源于该任务最早有效 `DISPATCHED` 事件时间，按时间倒序、ID 稳定排序，不把截止日当派发时间。搜索和 `limit` 沿用当前分页上限。任务普通列表支持 `from/to` 左闭右开网格与 `ownerId/participantId` 兼容筛选，任务区间按 `start_at < to AND deadline >= from` 相交；缺少 startAt 的旧数据以业务定义兼容，不因 NULL 丢失。
- `GET /logs/subordinates` 支持 `from/to`，与 `date/period` 二选一；成员、部门、关键词、日期必须组合过滤且仅返回已提交日志。`GET /logs/subordinates/calendar` 按 `ownerId/month=YYYY-MM` 返回整月每日状态、入职日和提交日志ID；成员范围须当前 Actor 可见。以上海业务日期判定：有已提交记录为 `SUBMITTED`，已到日期且入职日明确但未提交为 `MISSING`，未来为 `FUTURE`，未知入职起点覆盖的更早日期为 `UNKNOWN`。
- `PUT /logs/{id}/content` 仅本人更新已提交 `work`；事务中锁定日志、检查 ACTIVE 状态、版本及首次提交后未满24小时，并保持原 `submitted_at` 不变，写入 `log_versions`/审计。旧待审正文候选失效或冲突，绝不在新正文更新后覆盖；不再允许旧客户端利用其他修订入口绕过时间窗。首次提交仅限上海今天、昨天、前天；已提交正文可在独立24小时窗口内跨出三日修改。
- `GET /analytics`、`GET /analytics/details` 与 `/analytics/export` 共享日期周期和组织过滤解析及授权范围；任何跨公司/越权部门、团队、人员筛选拒绝，不静默放宽。汇总返回移动端的 `groupedComparison/trend/taskPhaseDistribution` 等完整字段；明细采用白名单指标和游标分页；CSV 逐页应用相同过滤并保留公式注入转义与导出上限。趋势数据只基于 `task_events`、日报提交时间等真实事件；统计废弃的阅读登记指标不再作为日报业务指标。
- `GET /profiles/{id}` 返回 `phone/email/gender/age/employmentStartDate` 等字段；`PUT /profiles/me` 接受确认的白名单、`version`，将 phone/email/gender/age 更新至权威 users 列，将 introduction/avatarAttachmentId merge 至 profile JSONB。电话唯一冲突、邮箱格式、性别32字符以内自由文本/空值、年龄非负整数和未知/只读字段均有字段级错误；更新原子且冲突为409。联系方式读取每次按当前祖先 reporting relation 授权。
- #17 审核默认 `DIRECT_MANAGER`：除注册 `MEMBERSHIP` 确认外，直属上级当前有效且非申请人时仅产生一个有效步骤；缺失/失效时申请待审、无有效步骤，不能按角色或祖先猜选。`MEMBERSHIP` 保留 `ADMIN_MEMBERSHIP` 管理员审批，不走直属上级或创始人免审。审核决定请求必须携带当前 `expectedVersion`，服务端重验当前直属关系、申请版本、当前审核身份、禁止自审和驳回原因。创始人对原本有权执行的其他审核型修改在同事务校验/应用，落 `APPROVED` 与 `FOUNDER_EXEMPT` 审计/outbox，不创建人工待办；管理员仍走正常审批。旧多级策略参数拒绝写入，旧已决定步骤保留审计，旧待审普通关键变更按直属关系重路由，待审成员确认按管理员规则重路由；历史创始人待审候选不自动应用。账号确认不能以免审扩大注册权限。

## Risks / Trade-offs

- #7直接日志编辑、第17单级审核与现行方案/主规格存在明确变化；只在对应实施批次同步产品基线、后端注释/OpenAPI、旧change冲突说明。历史已通过内容不追溯自动重放。
