# Proposal

## Why

移动端已有主要业务入口，但月历溢出和连续任务识别、日志输入成本、个人资料信息层级以及任务管理布局仍不符合本阶段产品要求。本变更完整承接用户2026-10-23提出的16项修改及追加的第17项单级审核，保留奶油白/团团主题，按页面分组、每次只实施一个原始修改点，全部修改完成后统一测试。2026-10-29 用户进一步授权本批兑现六组 P0 前后端链路和 #17 正式服务端行为，让已接入的 Flutter 请求、Spring API 和数据库具有一致且可验收的数据契约。

## What Changes

- 月视图（#1–#5）：右下角准确显示隐藏记录 `+N`；每周续段重复任务名；上下连续滚动切月并处理跨月续段与动画；任务管理改为固定字段表头、字段筛选和双向滚动的表格；入口从“我的”迁至日周月控件下方、与“今天”左右对称。
- **BREAKING** 日志（#6–#8）：只保留“今日工作”；创建改为底部输入层，键盘和输入层合计不超过屏幕2/3；自动保存加密本机草稿并恢复；移除旧独立编辑页和阅读登记，保留评论。最近三天允许首次补交；首次提交后24小时内本人直接编辑，无需审批，首次时间不重置，超过24小时只读，历史日期仍可查看。
- 我的（#9–#11）：个人主页仅显示个人资料；原地编辑可写字段、禁用组织字段，头像预览和上传；工作统计提供条形/折线/扇形图及交互联动；审批页统一奶油白布局，待审并入灰字元信息行。
- 下属工作台（#12）：姓名/职位/部门/电话/邮箱等资料卡；删除“正在查看”和“返回本人面板”；只保留日志/任务两类；日志提交日历绿/红点与日期详情；任务复用视图页月历尺寸及记录规则。
- 导图（#13–#15）：公司任务按派发时间降序，完成记录删除线/灰字；公司重点改居中只读详情卡；个人重点为独立自定义内容，居中可编辑卡，不与资料页绑定。
- 全局（#16）：移除面向用户的 Mock/演示字段与提示，保留真实加载、空数据、失败、权限和业务结果语义，不把离线数据冒充正式提交。
- **BREAKING** 审核（#17，用户追加并确认）：除 `MEMBERSHIP` 成员确认保留管理员审批外，关键变更改为组织中配置的直属上级单级审核；没有有效直属上级则待审，不自动通过。创始人在其已有权限范围内的非MEMBERSHIP操作自动批准且保留审计，其他发起权限、字段和版本校验不放宽。
- 用户已确认：首次提交后24小时编辑窗口不再受“三天内”限制；手机号可自改且所有组织上级可看相关资料；公司任务保留当前可见范围，无任何历史任务时显示真实空态；统计需多维条形/折线/扇形图。
- 本批后端实现范围：接收任务卡片与任务区间查询、下属日志范围/月份状态、已提交日志24小时正文更新、统计汇总/明细/同范围导出、资料读写与入职日、直属上级单级审核及创始人权限内免审。所有组织范围由服务端按当前 Actor 校验；未知历史入职日保留 NULL 并返回 `UNKNOWN`，新确认员工以生效日期记入职日。
- 资料字段决策：`users.phone` 继续作为唯一权威手机号；新增 `email`、`gender`、`age`、`employment_start_date` 列；简介和头像继续写入并 merge JSONB `profile`。不以迁移日期猜填既有员工入职日。
- 审核迁移决策：保留旧审核步骤作为审计；普通关键变更仅分配当前直属上级，MEMBERSHIP仅分配有效管理员；缺少有效审核人时保持待审且不产生可操作步骤。旧LOG申请失效。迁移不应用历史候选，包括创始人候选；有效创始人只有明确继续本人旧申请或重新发起操作，才按当前权限和目标版本校验免审生效。
- 规划只建立验收条件，不执行产品测试；先做OpenSpec规划校验，各批实现后统一验收才勾选功能完成。手工/自动化/构建均不提前运行。

## Capabilities

### New Capabilities

- `mobile-calendar-workspace`：月历溢出、跨周/跨月续段、纵向切月、任务表格及入口迁移。
- `mobile-diary-experience`：单字段底部编辑、草稿恢复、三日补交/24小时直接编辑和纯正文详情评论。
- `mobile-personal-workspace`：本人资料原地编辑、交互统计和统一审批布局。
- `subordinate-calendar-workspace`：员工资料、日志提交日历与复用任务月历。
- `mobile-product-presentation`：全局移除演示标识并维持真实业务状态语义。

### Modified Capabilities

- `dashboard-quadrant-layout`：增加公司任务排序/完成展示、公司重点弹卡和独立个人重点编辑要求。
- `collaboration-backend`：单级审核及创始人免审、日志限时直接编辑例外、单字段日志与阅读登记停用边界、资料字段写权限及上级可见范围。

## Impact

- Flutter：`features/calendar`、`features/dashboard`、通用表单/详情/目录、`routing`、`core/state`、模型/Repository、公共弹层及主题组件；不重做全局视觉、不改变底栏顺序。
- 本批同步修改 Spring Boot 服务端、`server` Flyway 迁移、Flutter HTTP/DTO 映射、SpringDoc 运行契约、`docs/openapi.json`、`docs/backend-interface.md`、移动端契约文档及验证记录；不修改独立 `deploy/postgresql` 数据模型，不扩大 Web 页面范围。
- 兼容性：旧日志多字段保留存量数据，不做破坏性删除；旧日志编辑路由转到新编辑入口；旧任务管理深链可保留但“我的”不再出现入口；旧客户端日志修订入口不得绕过24小时限制。
- 追踪：本地Issue `docs/issues/mobile-page-experience-refresh.md`；远程Issue编号、Sprint和负责人待关联，不编造。先复用当前工作分支HCJ；已有未提交的 `mobile/handoff.md` 属前次交接工作，不混入本批提交。
- 当前已获授权按序实施17个独立修改点，每次只实现一个；#1–#17已有移动端接入但尚未验收。当前批次仅实现被用户明确授权的服务端 P0 链路和 #17，不改变其余移动端 UI 批次范围。最终集中验收后按证据更新任务状态，不提前宣称功能合格。后续补充约束：只用既有主题色与定制可视组件，明确批次/阶段截至条件，并限制同一阻塞的无效重试，执行细则见tasks。
- 2026-10-23逐项复核见 `requirements-audit.md`：补齐日志选日入口与验收，消除阅读登记/待阅统计冲突，表格只使用真实字段；下属红点不擅设工作日豁免，连续月份只有一个纵滑坐标，审核升级不擅自批量执行历史候选。列宽等只作可调易用性参数，原文及用户确认优先。本次复核不改变产品代码、不提前执行产品验收。

2026-10-29剩余接口范围确认：用户取消意见反馈，删除移动端相关接口、表单和界面入口，旧support/feedback深链返回帮助页；保留任务成果反馈、评论及AI分析评价。任务RETURNED、成果反馈附件及团队目录沿用现有状态/权限接通；AI新增SELF/AUTHORIZED范围并在后台、重试与来源分析保持，confirm-task必须携带作业version，行锁/来源重验/TASK_CREATE审核/幂等回执同事务，V23新增确认回执表。任务评论与日志回复复用已有实现，不新增已停用阅读登记的人员清单。详细源码接入及最终验收边界见 `docs/mobile-remaining-api-implementation-status.md`。本轮无测试、分析、编译、构建、迁移执行、服务启动或OpenSpec校验；历史结果不能外推，所有新功能任务保持未验证，未提交推送。
2026-10-29追加授权：删除停用日志HTTP接口及客户端残留，统一新契约；逐项区分过时测试与真实缺陷并修复，最终集中验收。
