## ADDED Requirements

### Requirement: 公司任务派发排序与完成记录
P0／#13：公司任务卡 SHALL 保持当前授权及本人接收筛选范围，按真实派发时间从近到远排序。已验收/已归档记录 SHALL 保留并以删除线和灰字展示，不能因为没有进行中任务便显示任务为空；确实无任何历史任务时显示“暂无任务记录”，不伪造完成记录。排序 SHALL 不使用截止时间或客户端读取时间替代派发时间。

#### Scenario: 完成任务与同时间排序
- **WHEN** 当前任务都已验收或归档，或多条派发时间相同
- **THEN** 继续展示授权历史记录和完成样式，同时间以稳定ID排序，查看全部可访问未预览记录

#### Scenario: 缺少派发时间或无法读取
- **WHEN** 旧响应缺少派发时间、没有历史记录或加载失败
- **THEN** 缺时间记录稳定置后且不编造时间，无历史显示真实空态，失败保留重试语义而不是假装全部完成

#### 移动端接收任务卡接口契约
移动端 SHALL 通过统一列表仓库读取接收任务卡数据，Mock 与 HTTP 仓库使用同一记录字段和分页语义。正式后端待实现 `GET /tasks/received-card?cursor={cursor}&limit=30`，从当前会话身份推导“本人接收”范围并执行与现有任务列表一致的组织权限过滤；不得由客户端传入任意用户 ID 扩大范围。响应沿用列表 envelope `{ "items": [...], "total": 0, "nextCursor": null }`。每项至少返回 `id`、`title`、`ownerId`、`participantIds`、`dispatcherId`、`dispatchAt`、`phase`。`dispatchAt` 必须来自该任务有效派发的 `DISPATCHED` 流转事件 `created_at`；`phase` 使用任务真实当前阶段，包括 `ACCEPTED`、`ARCHIVED` 和独立的 `WITHDRAWN`。服务端分页须涵盖可见历史记录，不能只返回进行中任务；客户端完整读取分页后排序并限制卡片预览数量。缺少 `dispatchAt` 的项目稳定置后，同时间按 ID 排序；不使用任务创建、截止、接收或客户端读取时间替代派发时间。

#### Scenario: 接口缺失或旧响应字段不全
- **WHEN** 正式服务尚未实现该路由，或任务记录缺少阶段/派发时间字段
- **THEN** Mock 模式继续呈现同契约交互；正式模式显示可重试错误或将缺时间记录稳定置后，不从截止时间/创建时间猜测派发时间，不把状态未知记录伪装为已完成

### Requirement: 公司重点居中只读详情
P0／#14：点击公司重点记录 SHALL 保持当前路由与背景位置，在屏幕中央展示奶油白圆角矩形卡片及变暗遮罩，卡片显示该条实际标题和完整内容；内容过长可在卡内滚动，关闭后回到原卡片位置。公司正文仍只读，私人备注与正式正文权限分离。

#### Scenario: 点击、关闭与长正文
- **WHEN** 用户点击某条公司重点，滚动长正文并关闭
- **THEN** 弹卡显示正确对象，关闭后导图滚动不变，无新详情页入栈，系统返回先关闭弹卡

#### Scenario: 失权或内容已不可用
- **WHEN** 弹卡期间账号变化、目标被归档或读取失败
- **THEN** 清理旧受保护内容并给出中性错误/重试，不显示其他记录代替，也不开放公司正文编辑

### Requirement: 独立自定义个人重点弹卡
P0／#15：个人重点 SHALL 作为本人独立创建的备忘录、工作感悟等内容，不与个人资料字段或个人主页绑定。点击已有记录 SHALL 用居中奶油白圆角卡展示可编辑标题与正文，保留新增及已有排序/归档能力；保存按版本更新，取消不覆盖，背景变暗且不跳新页面。

#### Scenario: 新增备忘与编辑感悟
- **WHEN** 本人新增一条工作备忘，或编辑已有个人重点后保存
- **THEN** 内容保存在该用户个人重点资源并刷新卡片，个人简介等资料不被改动；最多十条置顶约束保持

#### Scenario: 空内容、冲突与越权
- **WHEN** 提交空必填内容、旧版本或尝试修改他人重点
- **THEN** 显示明确校验/冲突/权限错误并保留本人输入，不误写个人资料，不改变现有跨用户可见范围
