## Why

当前任务仍以单一 `owner_id` 与 `PRIMARY/COLLABORATOR` 角色组织人员，派发请求会立即生成生效任务，且没有任务标签、公开任务评论、任务删除审核或开始时间。这与“参与人集合”“创建/修改/删除须审核”“每项任务仅一个标签”和公开协作讨论的产品规则不一致，也会让旧接口把主负责人、协作人和独立进度备注暴露给客户端。

本变更由 C（马宛玉）负责，优先级为高。关联 Issue：**待创建**；Sprint：**待关联**。在 Issue 编号确定前，不能将该项报告为已交付或合并。

## What Changes

- 新增任务标签、任务标签关联、任务参与人、任务评论及评论去重结构；所有结构仅通过 `V16+` Flyway 迁移新增，不修改已发布迁移。
- 以无角色的参与人集合取代对外的主负责人/协作人模型。历史 `owner_id`、`task_assignees` 仅用于迁移回填和旧数据兼容；任务详情和列表只返回去重的 `participants`。
- 任务创建、通用修改和删除均进入现有审核链。创建在审核通过前不写入正式任务；删除在审核通过后归档而非物理删除，并保留申请、审核、理由、时间和原任务摘要的审计证据。
- 任务草稿/修订增加带时区的开始时间；截止时间继续以带时区的精确时间保存。完成情况不再有独立字段或进度备注，反馈内容追加到任务说明末尾。
- 标签由创始人维护，任务一次只能关联一个可见的活动标签；标签颜色由服务端随详情和列表返回。
- 新增公开任务评论与回复接口。评论不可编辑或删除；访问、写入、重复、空内容和父评论范围均由服务端校验；评论与 outbox 通知在同一事务写入。
- 同步 OpenAPI、后端接口说明、单元测试和 PostgreSQL/Redis 集成测试。

## Capabilities

### New Capabilities

- `task-participant-governance`: 审核后生效的任务创建、修改和删除，以及无主负责人语义的参与人集合、时区时间和审计。
- `task-labels`: 公司/部门范围内的单标签管理、可见性和稳定颜色返回。
- `task-comments`: 面向有任务读取权限成员的公开评论、回复、去重和事务通知。

### Modified Capabilities

- `task-dispatch-idempotency`: 创建请求的幂等结果改为同一审核申请；审核通过后才产生正式任务。
- `task-lifecycle`: 参与人可执行接收与反馈；任务验收、归档等既有生命周期不再依赖主负责人/协作人角色。
- `task-list-query`: 列表使用参与人范围和安全投影，继续不得返回完成情况、阶段或替代状态字段。

## Impact

- 代码：`module/task` 为主；新增 `module/comment`；通过 `module/review` 的已审批应用接口接入既有审核链；`OpenApi.java` 更新请求和响应契约。
- 数据库：新增 `V16__task_governance.sql`、`V17__task_labels_and_comments.sql`（最终编号在实现前以当前最大 Flyway 版本为准）。旧任务会回填参与人，已发布迁移不改写。
- 接口：`POST /api/tasks` 从“立即创建任务”变为“提交创建审核”；详情/列表移除 `owner_id`，新增 `participants` 与 `label`；新建标签和评论接口。属于客户端可见的破坏性变更，需由 Flutter/Web 负责人按 OpenAPI 更新调用。
- 协作边界：不实现审核链路本身、通知投递器、AI、Flutter 或 Web 页面。评论仅在同一事务写入现有 outbox；通知模块负责人负责投递与展示。
