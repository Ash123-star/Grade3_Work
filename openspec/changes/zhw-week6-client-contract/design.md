## Context

当前分支 zhw 基于 dc00e2b。HCJ 压缩包仅作契约参考，尚未合入主线。用户批准先核对再批次实现、统一验收。

## Goals / Non-Goals

实现当前后端提供的客户端能力；不修改数据库、审核权限或 HCJ 视觉，不伪造标签和多人任务服务。

## Decisions

比较直接移植 HCJ 请求与按现有后端分段适配：前者会发送 TaskDraftNormalizer 不接受的字段，且将日志审核误作直接编辑；采用后者。保留旧任务接口兼容调用，但新任务字段明确失败，待 C 接口落地再迁移。

Query 增加 departmentId，并在分页中透传。日志保留原始能力和组织信息；回复从 HCJ parentCommentId 映射为 parentId，读取同时保留原始字段及别名。POST 评论不自动重试。服务端负责所有权限和24小时时间边界，客户端只提供提前提示。

## Risks / Trade-offs

HCJ 尚未合并，页面筛选和回复交互仍需合并后验收；缺少运行环境时不能报告真实联调完成。旧任务字段因现有页面和服务端依赖保留，未完成新模型迁移。API 规格已包含日志增量，不新增不存在的 endpoint。远端 Issue/PR 不重复尝试被拒绝的操作。

## Validation

统一运行 Flutter 分析及数据契约、SSE、会话隔离测试；smoke 覆盖真实 HTTP 日报提交、部门筛选、评论回复和非法输入。安全关注越权与旧会话，可靠性关注分页筛选不丢失、评论不重试及 SSE 去重。记录明确退出码；环境阻塞保留未勾选任务。

## Toolchain follow-up

2026-10-23 验收发现本机 drift 缺失及旧锁文件与当前 Flutter SDK 约束冲突。按官方归档及锁文件 SHA256 恢复 drift，随后离线解析只同步7项SDK关联包。纳入 mobile/pubspec.lock，工具链和旧SDK兼容风险记录在验证报告。正式模式契约测试与依赖Mock初始数据的界面测试分别按对应开关验收。

## Main integration follow-up

Issue #32、草稿PR #33建立后，main已到808d9d6，HCJ及任务新后端已合入。比较整文件覆盖和逐段融合：采用后者，保留主线姓名/页面适配与本分支日志能力；只保留一个截止时间定时器，避免重复dispose和每秒刷新。
